# 별빛 상점 · 아레나 확장 · 크리스마스 배포 클릭 안내서

대상: [kwonyoung1/pocket-friends](https://github.com/kwonyoung1/pocket-friends)

운영 게임: https://kwonyoung1.github.io/pocket-friends/

작업 브랜치: `codex/arena-shop-christmas`

기존 main에는 이미 일반 스테이지 40개가 있습니다. 기존 ID·클리어 기록을 보존하고 10개를 추가해 **일반 50개 + 별도 크리스마스 1개**로 확장합니다. 기존 캐릭터·환수·성급·장비·사진·재화는 초기화하지 않습니다. DB 마이그레이션은 없습니다.

## 1. PR과 검사 확인

1. [이번 작업 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls?q=is%3Apr+head%3Acodex%2Farena-shop-christmas)을 엽니다. 로그인 화면이면 기존 `kwonyoung1` 계정으로 로그인합니다.
2. 목록의 `arena-shop-christmas` PR을 클릭합니다. 목록이 비어 있으면 [브랜치](https://github.com/kwonyoung1/pocket-friends/tree/codex/arena-shop-christmas)와 [자동 PR 실행](https://github.com/kwonyoung1/pocket-friends/actions/workflows/auto-pr.yml)을 확인합니다. PR이 이미 병합됐으면 목록 필터의 Open을 해제하거나 `is:closed`로 찾습니다.
3. PR의 **Checks**를 클릭합니다. `unit`, `browser`, `cloud`, `build`가 성공해야 합니다. PR에서 `approve`, `backend`, `deploy`가 `Skipped`인 것은 운영 배포가 main에서만 실행되기 때문입니다. PR 성공만으로 운영 완료가 되지는 않습니다.
4. **Approve workflows to run**이 실제로 보일 때만 클릭합니다. 이는 검사 실행 허용이며 코드 리뷰 승인과는 별개입니다.
5. 빨간 검사에 들어가 처음 실패한 단계와 오류를 확인합니다. `build`의 `test "$UNIT" ...` 실패는 앞선 검사 실패를 모은 결과이므로, 먼저 실패한 `unit/browser/cloud`를 확인합니다. 실패를 무시하고 병합하지 않습니다.

## 2. 자동 병합과 이번 변경의 보호 리뷰

이번 변경은 코인 사용·보상·서버 검증을 포함하므로 기존 저장소 정책상 보호 대상입니다. 기존 자동화나 보안 설정을 완화하지 않습니다.

1. PR **Files changed**에서 상점 가격·서버 검증·보상·이벤트 날짜를 확인합니다.
2. 리뷰 승인 필요 표시가 있을 때 **Submit review** → **Approve** → **Submit review**를 누릅니다. 본인이 PR 작성자인 경우 GitHub에서 자기 승인할 수 없으며, 권한 있는 다른 리뷰어가 필요합니다.
3. 이번 변경은 보호 대상이므로 기존 자동 병합 봇은 명시적 리뷰·병합을 기다리도록 설계되어 있습니다. 필수 검사와 리뷰가 모두 끝나 초록색 **Merge pull request**가 활성화되면 **Merge pull request** → **Confirm merge**로 병합합니다. 보라색 **Merged**가 정상입니다. 보호 규칙을 해제하거나 관리자 우회를 사용하지 않습니다.
4. [자동 병합 실행 화면](https://github.com/kwonyoung1/pocket-friends/actions/workflows/auto-merge.yml)을 확인할 수 있습니다. 설정을 확인해야 할 때는 [Actions 변수](https://github.com/kwonyoung1/pocket-friends/settings/variables/actions)에서 기존 `AUTO_PR_ENABLED`, `AUTO_MERGE_ENABLED`, `AUTO_SERVER_DEPLOY_ENABLED`를 확인합니다. 이미 정상인 값은 수정하지 않습니다.

## 3. main 배포 승인 및 완료 확인

1. [main 배포 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Amain)을 엽니다.
2. 이번 PR 번호가 제목에 있는 최신 **Merge pull request ... arena-shop-christmas** 실행을 클릭합니다. 예전 실패 실행을 재실행하면 예전 코드가 배포되므로 새 main 실행을 확인합니다.
3. `Waiting`과 `release-approval` 안내가 실제로 보일 때 **Review deployments**를 클릭합니다.
4. **release-approval**을 선택하고 **Approve and deploy**를 누릅니다. 이 단계는 기존 운영 보호 규칙이 요구하는 승인입니다. PR 리뷰와 별개이며 버튼이 없으면 이미 처리됐거나 아직 검사 중입니다.
5. `backend / functions` → `backend-gate` → `deploy`가 모두 성공할 때까지 기다립니다. 이번 작업은 **game Edge Function 배포가 필수**입니다. `treasure` 전용 로직은 변경하지 않아 배포 계획이 정한 필요한 함수만 배포합니다.
6. `deploy` 안의 **Verify live HTML, exact commit and executable assets**, **Read-only live mobile boot check**가 초록색인지 확인합니다. 실행 전체가 초록색이더라도 `deploy`가 회색 **This job was skipped**면 웹 배포가 수행된 것이 아닙니다.
7. 실행 Summary의 배포 SHA와 main 병합 SHA가 일치하는지 확인합니다. `Release proof`와 `release-proof-...` 아티팩트가 배포 증거입니다.
8. [Pages 설정](https://github.com/kwonyoung1/pocket-friends/settings/pages)에서 배포 주소가 위 운영 게임인지 확인합니다. 기존 GitHub Actions 설정은 그대로 사용합니다.

## 4. 실제 게임에서 새 기능 확인

1. [운영 게임](https://kwonyoung1.github.io/pocket-friends/)에 접속합니다. 새 버전이 안 보이면 탭을 닫고 다시 열거나 새로고침합니다. **브라우저 저장 데이터 삭제·월드 초기화는 하지 않습니다.**
2. 기존 게임 비밀번호로 접속하고 기존 공유 월드를 사용합니다. 신규 월드를 만들지 않습니다.
3. **별빛 아레나**를 누릅니다. **별빛 상점**, **그림자 성채**, **천상의 문**, **겨울밤의 선물**이 보이면 새 UI가 적용됐습니다.
4. **별빛 상점** → **캐릭터 훈련소**에서 대상과 능력치를 고릅니다. 구매 전후 수치와 코인을 확인하고 **훈련 강화** → **확인하고 진행**을 누릅니다. 실제 코인이 사용되므로 검토만 할 때는 **취소**를 누릅니다.
5. 다른 기기에서도 같은 비밀번호의 기존 공유 월드를 사용합니다. 상점 강화·주문서·에너지·진행은 기존 공유 아레나 계정에 저장됩니다. 별도 아레나 코드를 입력할 필요가 없습니다.
6. 진행 중인 전투는 입장 당시 레벨·장비·성급·훈련·스킬·COST로 계속됩니다. 새 구매는 다음 입장부터 반영됩니다.

## 5. 상점 규칙과 가격

공용 기존 코인을 사용합니다. 별도 유료 재화나 새 결제 시스템은 없습니다. 서버가 보유 여부·실제 성장·가격·단계·수량·잔액을 검증하며, 통신 재시도는 기존 영수증/CAS로 중복 차감을 막습니다.

| 항목 | 효과/조건 | 가격 |
| --- | --- | --- |
| ATK·DEF 훈련 | 각각 +30까지, 단계당 +0.7% | 현재 단계 n에서 `100 + 30n + 500×floor(n/10) + 5n²` |
| HP 훈련 | +30까지, 단계당 +1% | 위와 같음 |
| 스킬 강화 | 스킬별 +10, 피해·회복·보호막 단계당 +3%, 지원 수치 +2% | 현재 단계 n에서 `300 + 200n²` |
| 지휘력 +1 | COST 10→11, 선행 조건 없음 | 20,000 |
| 지휘력 +2 | COST 11→12, 2-1(6번째) 클리어 | 60,000 |
| 지휘력 +3 | COST 12→13, 3-1(11번째) 클리어 | 150,000 |
| 리더 교육 | 실제 출전 영이 또는 찬미 Lv.40 이상이면 +1 | 자동 적용 |
| 천상의 지휘 인장 | 10-5 최초 클리어로 +1 | 최초 보상 |

최종 COST 상한은 15이며 최대 5명, 영이 또는 찬미 필수, 중복 출전 금지를 유지합니다. 스킬 범위·타격 수·확률·상태 이상 지속 시간·마스터리·해금 레벨은 강화로 변경하지 않습니다. 훈련 수치는 반올림으로 일부 단계에서 표시 값이 같을 수 있습니다.

**경험치 주문서** 메뉴에서 종류·수량을 고르고 **주문서 구매**로 보관한 뒤, 대상과 사용 후 레벨을 확인하여 **주문서 사용**을 누릅니다. 구매와 사용은 각각 확인 창을 거칩니다.

| 주문서 | 경험치 | 개당 코인 |
| --- | ---: | ---: |
| 작은 | 100 | 800 |
| 중급 | 500 | 4,500 |
| 고급 | 2,000 | 20,000 |
| 전설 | 10,000 | 120,000 |

기존 일반 캐릭터 `20+10×현재 레벨`, 환수 `20+8×현재 레벨` 성장 공식을 사용하며 Lv.50을 넘지 않습니다. 최고 레벨에게는 사용할 수 없습니다. 마지막 한 장의 초과 XP는 소멸할 수 있으며, 최대 레벨까지 필요한 장수를 넘는 여러 장의 불필요한 사용은 거부합니다. 구매 수량은 회당 1~99개, 종류별 보관 9,999개입니다. 유료 주문서 XP는 무료 전투 XP 한도와 구분합니다.

## 6. 신규 일반 스테이지

기존 1-1~8-5와 진행 기록은 유지합니다. 이전 스테이지 클리어로 다음 스테이지를 해금합니다.

| 지역 | 단계 | 에너지 | 반복 코인 | 최초 코인 |
| --- | --- | ---: | ---: | ---: |
| 그림자 성채 | 9-1 / 9-2 / 9-3 / 9-4 / 9-5 | 각 22 | 180 / 200 / 220 / 240 / 270 | 540 / 600 / 660 / 720 / 810 |
| 천상의 문 | 10-1 / 10-2 / 10-3 / 10-4 / 10-5 | 각 25 | 330 / 360 / 390 / 430 / 500 | 990 / 1,080 / 1,170 / 1,290 / 1,500 |

성채의 달그림자 나방·저주 사제·공허 기사·식월왕, 천상의 광구·성문 찬가사·여명 기사·천상의 심판자가 등장합니다. 약점·보호막·치유/지원 적 조합·상태 이상·보스 패턴을 사용하고 마지막 10-5는 3웨이브입니다. 보상은 실제 서버 재생 승리만 인정합니다.

공유 월드 아레나 코인 한도는 기존 하루 5,000, 무료 전투 XP는 출전 대상별 하루 100을 유지합니다. 새 규칙에서는 최초 코인을 전액 지급할 한도가 없으면 최초 코인을 다음 날로 이월하고, 최초 비코인 보상은 한 번만 지급합니다. 클리어 기록은 즉시 저장됩니다. 상자와 XP는 코인 한도와 구분하며 각 보관/XP 상한을 적용합니다.

## 7. 크리스마스 운영 일정과 보상

- 공식 입장: **2026년 12월 1일 00:00 ~ 2027년 1월 1일 00:00 직전, 한국 시간**.
- 설정 파일: [season.ts](https://github.com/kwonyoung1/pocket-friends/blob/codex/arena-shop-christmas/src/arena/season.ts). 이번 릴리스 날짜 이전/이후에는 정식 입장 버튼이 잠기며 연습은 가능합니다.
- 서버 시간이 기준이며 단말기 시계로 정식 입장이나 보상을 우회할 수 없습니다.
- **크리스마스 스테이지 보기** → **정식 도전** → **겨울밤의 선물 도전**으로 입장합니다. 에너지는 정확히 10이며 반복 클릭/응답 손실로 중복 차감하지 않습니다.
- 눈 슬라임·선물 미믹·눈 장난꾼·얼음 순록·선물 도둑 크람푸스가 등장합니다. 보스는 최대 2회 소환과 저체력 광역 패턴을 사용합니다.
- 승리마다 크리스마스 특별 상자 1개, 최초/반복 코인 30/10, XP 12/5를 지급합니다. 기존 일반 스테이지 해금과 이벤트 진행은 분리됩니다.
- 기간 중 입장한 유효 전투는 종료 시각을 지나도 입장 후 6시간 유효기간 내에 완료할 수 있습니다. 기간 후 새 정식 입장은 불가능합니다.
- 획득한 상자는 기간 후에도 남습니다. **환수 도감 · 보물상자**에서 크리스마스 특별 상자를 선택해 개봉합니다.

| 결과 | 기본 확률 |
| --- | ---: |
| 일반 코인 160 | 60% |
| 희귀 환수 | 22% |
| 영웅 환수 | 11% |
| 전설 환수 | 6% |
| 신화 환수 | 1% |

환수 합계 40%로 일반 전설 상자의 35%보다 높습니다. 기존 전설·신화 천장을 공유하며, 천장 발동 시 표시 확률이 달라집니다. 중복 환수는 기존 전용 조각·합성 규칙을 사용합니다. 기존 일일 코인 한도로 일반 코인 보상이 전혀 지급되지 않으면 기존 안전 처리대로 강화석 1개로 대체하며, 남은 한도가 있으면 그 범위만 지급합니다. **크리스마스 종소리**를 체크하면 사용자 개봉 동작 때만 짧은 합성 종소리가 재생됩니다. 기본은 꺼짐이며 외부 음원 다운로드는 없습니다.

## 8. 실패 시 클릭 경로

| 화면/오류 | 조치 |
| --- | --- |
| PR Approvals 필요 | 위 2절의 보호 리뷰. 규칙 해제 금지 |
| Waiting / release-approval | 위 3절 **Review deployments** |
| backend 실패 | Actions에서 `backend / functions`의 첫 오류를 확인. 웹 배포 강행 금지 |
| `Invalid access token` | [Supabase 계정 토큰](https://supabase.com/dashboard/account/tokens)에서 해당 배포 토큰의 만료/폐기 여부를 확인. 정상 토큰을 무조건 새로 발급하지 않음 |
| 유효한 토큰을 새로 발급해야 하는 경우 | 위 토큰 페이지 **Generate new token**, 대상 pocket-friends 프로젝트와 Edge Functions 읽기/쓰기 권한. 생성 직후 표시되는 **전체 문자열**을 복사. 기존 마스킹된 토큰은 복원 불가. 이름·마스킹 문자열·Publishable/Secret API key를 복사하는 것이 아님 |
| GitHub에 토큰 갱신 | [Environments 목록](https://github.com/kwonyoung1/pocket-friends/settings/environments) → **cloud-backend** → **Environment secrets**의 `SUPABASE_ACCESS_TOKEN` 연필 → 전체 토큰 붙여넣기 → **Update secret**. 채팅·코드·스크린샷에 토큰을 보내지 않음 |
| Pages 아티팩트 오류 | 최신 main 실행의 **Re-run jobs** → **Re-run failed jobs**를 한 번 실행. 이번에도 기존 시도별 고유 아티팩트 이름을 유지. 같은 오류 반복 시 로그를 보관하고 중단 |
| 상점 통신 오류 | 게임의 **상점 작업 다시 확인**. 새 명령 반복 생성·월드 초기화 금지 |
| 다른 기기에 이전 화면 | 새로고침 후 같은 기존 공유 월드 선택. 진행 중 전투는 이전 규칙·입장 수치일 수 있음 |
| 배포 Success인데 화면 그대로 | 선택한 실행의 `deploy` 실제 성공, SHA/라이브 검사 확인. `Skipped`면 배포 완료가 아님 |

기존 Actions/Pages/Secrets가 정상인 경우 재설정하지 않습니다. [Actions 권한 설정](https://github.com/kwonyoung1/pocket-friends/settings/actions), [일반 설정](https://github.com/kwonyoung1/pocket-friends/settings), [브랜치 보호](https://github.com/kwonyoung1/pocket-friends/settings/branches)는 문제 확인 경로이며, 승인이나 필수 검사를 없애는 안내가 아닙니다.

## 9. 배포 완료의 판단 기준

코드 작성·로컬 테스트 통과·PR 생성·PR 병합·game 서버 배포·Pages 배포·실제 SHA 검증을 각각 구분합니다. 네트워크 403/권한 제한으로 실행 상태나 운영 접속을 확인할 수 없으면 미확인이라고 보고합니다. 보호 승인 대기는 실패를 의미하지 않지만 운영 완료도 아닙니다. 이 문서는 클릭 절차이며 배포 성공 증명 자체는 아닙니다.

## 10. 모바일·데이터 사용량

360×800, 375×812, 390×844, 412×915에서 터치 UI를 검증합니다. 실기기 Android/iPhone 검증과 브라우저 에뮬레이션은 구분합니다. 새 배경 WebP 3개와 몬스터 PNG 3개의 디스크 합계는 약 428KiB이며 GitHub Pages 정적 자산으로 제공합니다. 상점 미리보기·탭 변경은 클라이언트 계산을 사용하고 상점/시즌용 상시 폴링을 추가하지 않습니다. 실제 Supabase 월간 Egress 절감률을 이번 자산 크기에서 추정하지 않습니다.
