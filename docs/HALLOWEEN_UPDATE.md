# 할로윈 테마와 가구·보석 배치 영역

기존 방 크기와 친구·사진·육성·인벤토리·코인·탐험·장비·미니게임 기록을 유지하면서 배경 선택과 배치 검사를 개선했습니다. 테마 장식은 배경 SVG이며 아이템 수량이나 이동 장애물을 만들지 않습니다.

## 사용하는 방법

1. 게임의 **우리의 거실** 위쪽에서 **🎃 할로윈 테마로 변경**을 누릅니다. 모바일에서는 거실 제목 다음 줄에 있습니다.
2. **🌿 기본 테마로 변경**을 누르면 원래 방으로 돌아갑니다. 무료이며 쿨타임이 없습니다. 선택은 자동 저장하고 클라우드 월드의 다른 기기에도 반영합니다.
3. **인벤토리 → 배치할 가구 또는 보물 → 방에 배치하기**를 누릅니다. 방 바닥을 누르거나 끌어서 위치를 고른 뒤 **여기에 놓기**를 누릅니다.
4. 점선은 공통 바닥 경계입니다. 아이템은 본체 크기에 맞춰 경계 안쪽에 멈춥니다. 손가락에 가려진 모습은 조작 바의 작은 미리보기로 확인할 수 있습니다.
5. **가구 편집 → 배치 아이템 선택**에서 겹친 아이템도 골라 이동·레이어 변경·개별 회수할 수 있습니다.

새 배경은 크림·연보라 벽, 호박빛 바닥, 부드러운 남색 창밖과 초승달·별, 웃는 호박과 랜턴, 마녀 모자 가랜드, 보라색 전구, 박쥐, 창문의 거미줄, 웃는 유령, 모서리 호박 바구니와 사탕으로 구성했습니다. 유령·랜턴·별은 느리게 움직이고 박쥐는 간헐적으로 지나갑니다. 기기의 **움직임 줄이기**를 켜면 테마 애니메이션을 끕니다. 외부 이미지·유료 생성 API를 사용하지 않습니다. 기존 영이·찬미의 사진·말풍선 정책과 다른 친구들의 대사 제한은 유지하며, 선택사항인 계절 대사는 추가하지 않았습니다.

## 실제 배치 경계 비교

아래 수치는 방 일러스트의 **1000 × 640 기준 좌표**입니다. 실제 게임 저장 좌표는 양 축에 `√1.5`를 곱합니다. 방 크기는 계속 **1224.745 × 783.837**이며 카메라/확대 구조도 유지합니다.

이전 검사는 모든 아이템의 기준점을 가로 **165~910**, 세로 **275~530**에 제한했습니다. 새 검사는 바닥의 시각적 시작인 **y=199**와 방 끝을 기준으로 **8**씩 안전 여백을 둔 가로 **8~992**, 세로 **207~632**를 공통 외형 경계로 사용합니다.

| 기준점 범위 | 이전 가로 | 이전 세로 | 변경 후 가로 | 변경 후 세로 | 기준점 이동 가능 면적 증가 |
| --- | --- | --- | --- | --- | --- |
| 보석 본체 | 165~910 | 275~530 | 25.00~975.00 | 244.47~633.35 | 약 94.46% |
| 큰 침대 | 165~910 | 275~530 | 50.94~949.06 | 257.79~621.00 | 약 71.71% |
| 작은 돌 장식 | 165~910 | 275~530 | 38.60~962.25 | 251.34~630.44 | 약 84.32% |
| 키 큰 기본 화분 | 165~910 | 275~530 | 36.05~961.40 | 287.89~629.59 | 약 66.44% |

공통 경계는 실제 바닥 `(0~1000) × (199~640)` 면적의 **94.83%**입니다. 이는 본체가 들어갈 수 있는 바닥의 비율이며, 모든 크기의 가구 기준점이 그 전체를 움직인다는 뜻은 아닙니다. 기준점은 기존 그림 컨테이너의 아래쪽 85% 위치여서 보석 기준점 y=633.35에서도 본체의 끝은 y=632 안에 들어갑니다.

그림이 긴 화분은 상단의 과거 좌표에서 잎이 벽으로 나올 수 있어 새로 옮길 때에는 위쪽 여백이 조금 커집니다. **이미 저장된 화분·가구·보석은 새 경계에 맞추어 강제로 옮기거나 삭제하지 않습니다.** 기존의 y=275 화분도 원래 좌표·ID·레이어를 그대로 표시하며, 사용자가 이동할 때 새 검사만 적용합니다.

## 그림 크기와 이동 판정

- 가구 종류별 SVG 본체 경계와 실제 표시 너비·높이로 허용 기준점을 계산합니다. 기존 저장에 개별 너비·높이가 있으면 그대로 사용합니다.
- 보석은 일반 가구 컨테이너의 절반 크기를 유지합니다. 전설 아우라·빛·그림자는 본체 경계에서 제외하여 가장자리 배치를 불필요하게 막지 않습니다.
- `src/room/placement.ts`의 공통 계산을 화면 미리보기와 서버 검증이 함께 사용합니다. 가구의 본체 경계 정보는 `src/expansion/artConfig.ts`에 모았습니다.
- PC와 모바일의 방 렌더링 비율 차이에도 본체와 기준 좌표가 일치하도록 배치용 SVG를 월드 크기에 맞춥니다. 인벤토리 그림은 원래 비율을 사용합니다. 모바일 배치 시작 시 부드러운 자동 스크롤 대신 즉시 이동하여 손가락을 누른 뒤 화면이 계속 움직이는 문제도 방지합니다.
- 캐릭터 이동은 별도 기존 경계 **x=50~950, y=230~570**을 유지합니다. 보석·장식은 통과하며 장애물 가구의 충돌·연결 경로 검사는 계속 적용됩니다. 가구 겹침과 개별 레이어/회수 규칙도 유지합니다.

## 저장과 서버 호환성

기존 JSON 월드에 선택적 `roomTheme: {id, changedAt}`와 `placementBoundsVersion: 2`만 추가합니다. 테마 없는 기존 데이터는 기본 테마로 표시합니다. 클라우드의 변경 시각은 서버 시각이며 기존 CAS/작업 영수증으로 중복 명령을 방지합니다.

저장 버전·기존 키·원본 사진·장비·기록·배치 좌표와 레이어를 유지합니다. 새 월드 생성이나 전체 데이터 재입력은 필요 없습니다. **추가 SQL 실행과 테이블 마이그레이션은 없습니다.** 기존 Supabase의 `game` 함수 배포와 웹사이트 배포는 둘 다 필요합니다.

클라이언트 프로토콜은 12입니다. 새 서버를 먼저 배포해도 이전 화면(11)은 기존 월드에서 계속 동작합니다. 새 화면이 처음 쓰기 명령을 처리하면 영역 버전 2를 기록하고 이후 이전 화면의 쓰기는 새로고침 안내와 함께 차단합니다. 구형 화면의 오래된 데이터가 새 테마를 지우는 것을 막기 위한 처리이며 기존 저장을 초기화하지 않습니다.
