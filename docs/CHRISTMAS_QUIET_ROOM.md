# 크리스마스 겨울 테마와 조용한 모바일 거실

기준: `main`의 `09d72c2`에서 만든 `feat/christmas-quiet-room`.

## 확인한 원인과 한계

- 최신 main에는 이미 `winter` ID, 테마 선택 UI, 겨울 WebP, RoomArt 전달, 저장 마이그레이션, 서버 명령 허용 처리가 있었다. 로컬 및 두 모바일 클라우드 세션에서 겨울 선택이 기본으로 돌아가는 오류는 재현되지 않았다. 기존 선택이 `default`인 저장은 의도적으로 그대로 유지한다. 업데이트만으로 사용자의 테마 선택을 덮어쓰지 않는다.
- 기존 겨울 이미지는 실제로 눈 덮인 나무·지붕·푸른 하늘·니트 담요·러그를 포함하지만 트리·리스·양말·선물은 없었다. 모바일 방은 가로 카메라가 있어 오른쪽 장식이 첫 화면에서 잘릴 수도 있었다. 겨울 선택/재접속 때만 모바일 카메라를 가운데로 맞추고, 트리를 중앙 창가에 배치했다. 기존 가구/캐릭터 좌표를 바꾸지 않았다.
- 겨울 이미지 로딩 실패를 처리하는 경로가 없었다. 이제 실패 시 기존 실내 위에 **불투명한 눈 덮인 창밖 SVG**와 크리스마스 장식을 표시한다. 정상 로딩에서는 기존 수채화 WebP를 그대로 쓴다. 네트워크 실패를 주입한 테스트로 대체 경로를 검증했다.
- 운영 사이트 조회는 네트워크 권한 요청이 취소되어 수행하지 못했다. 운영 화면의 이전 배포·브라우저 캐시·실제 선택 상태 중 어느 것이 원인이었는지는 확정할 수 없다. 수정 후 빌드와 배포 확인 절차를 아래에 제공한다. 이번 메시지에는 새 모바일 참고 이미지 파일이 없어 저장소 원화와 직접 실행한 화면을 기준으로 작업했다.
- `…`는 빈 대사 fallback이 아니라 `src/cozy/presence.ts`의 **행복도 30 이하 lonely 감정 아이콘**이었다. `InteractiveFriend`가 모든 캐릭터에 이를 상시 표시했다. 기분 계산은 보존하면서 해당 기호와 상시 감정 배지를 제거했다.

## 실제 변경

| 항목 | 이전 | 변경 |
|---|---|---|
| 이동 완료 후 휴식 | 보통 2–6초, 성격·상태 배수 | 보통 15–30초, 18% 확률로 30–60초 |
| 최초 대기 | 0.5–2.5초 | 15–30초 또는 긴 휴식 |
| 동시에 자동 이동 | 별도 상한 없음 | 최대 2명, 새 출발 최소 1.8초 간격 |
| 출발 순서 | 친구 배열 순서 | 가장 오래 기다린 친구 우선 |
| 목적지 | 방 전체 무작위/가구/친구 | 주로 55–160 월드 단위, 가끔 최대 300; 직전 위치로 왕복 회피 |
| 기본 보행 속도 | 곰 29, 여우 42, 나머지 35 | 곰 23.2, 여우 33.6, 나머지 28 (20% 감소) |
| 출발·정지 | 일정 속도 | 지수 가속, 마지막 30단위 감속 |
| 생활 포즈 | 약 3–10초 간격, 점프 포함 | 15–30초 간격, 일반 대기 점프 제거, 작은 호흡 |
| 자연 대사 | 주로 20–50초, 6.5초 표시 | 주로 30–60초, 캐릭터별 최소 30초, 일반 대사 최대 2.7초 표시 |
| 일반 말풍선 | 내부 freeSpeech 검사 | 추가로 렌더 단계에서도 최대 1개, 사용자 행동 대사 우선 |
| 대기 방 React 갱신 상한 | 약 12.5회/초 | 약 3.3회/초; 걷기 12.5회/초, 직접 교감은 RAF 유지 |

이동 상한은 드래그·탐험·목욕·돌보기 명령의 실행을 기다리게 하지 않는다. 새 이동 속도/출발 이력은 WeakMap의 표시용 상태이며 저장 형식을 추가하지 않는다. 이동 도중 다른 친구의 38단위 이내로 더 접근하게 되면 제자리에서 다음 산책을 기다린다. 기존에 겹쳐 있던 저장 좌표를 강제로 재배치하지 않는다. 가구 충돌·드래그 유효 위치 규칙은 유지한다.

자연 대사의 같은 문장은 2분 동안 재출력하지 않는다. 공백·줄임표·점 기호만 있는 문구는 생성 및 렌더 양쪽에서 제외한다. 실제 배고픔/청결 알림은 유지하고, 일반 말풍선은 사용자 행동 결과와 겹쳐 표시하지 않는다. 돌보기·상태 알림·감정 아이콘은 얼굴 위에 여러 겹 표시하지 않는다. 배고픔·청결·졸림 배지는 선택한 캐릭터에만 표시하며, 기존 짧은 상태 이모션은 유지한다. 쓰다듬기 단계/하트와 수면·목욕 동작은 보존한다.

## 아트·효과

- **추가 원화 코드:** `src/room/ChristmasDecor.tsx`. 직접 작성한 SVG 트리, 금빛 별, 빨강/금색 오너먼트, 2개의 양말, 리스, 선물 2상자, 겨울 쿠션, 창틀 눈. 별도 외부 에셋이나 신규 래스터 이미지는 사용하지 않았다.
- **재사용:** `src/assets/room/winter-watercolor.webp`. 기존 생성 이미지의 출처/제약은 [이전 겨울 문서](MOBILE_WINTER.md)와 동일하다. 영이·찬미·동물·사용자 사진 원화는 수정하지 않았다.
- 장식은 RoomArt SVG 배경 레이어에만 있고 사용자 인벤토리·가구·장애물이 아니다. 새 구매 재화나 아이템을 만들지 않았다.
- 눈은 4개 창유리 clipPath 내부에만 표시한다. 눈 4–8개, 트리 전구 4–8개. 메모리 4GB 이하/논리 코어 4개 이하/8명 이상 방은 작은 예산을 사용한다.
- 전구는 5초 주기로 밝기만 부드럽게 바뀐다. 전체 화면 점멸, PixiJS 앱, blur 필터, 새로운 파티클 엔진을 추가하지 않았다. 겨울에는 기존 햇살 먼지 레이어를 함께 돌리지 않는다.
- 화면 밖·백그라운드·suspended·reduced-motion에서는 눈/전구 애니메이션이 멈춘다. 실제 기기의 FPS·온도·배터리 수치는 측정하지 않았다. 위 갱신 횟수는 코드의 상한 계산이며 실측 FPS가 아니다.

## 데이터·서버

DB 스키마·SQL 마이그레이션·Supabase 프로젝트 변경은 없다. 코인·음식·씻기·탐험·장비·미니게임 규칙을 바꾸지 않았다. 로컬 원본은 클라우드 사용 중에도 덮어쓰지 않는 것을 테스트했다. `winter` 저장 ID는 그대로라 기존 겨울 선택을 보존한다.

`game.ts`/`interaction.ts`는 서버도 가져오는 공용 모듈이므로 이번에는 기존 Supabase Edge Function을 다시 배포한다. DB 초기화, 프로젝트 재생성, 사이트 데이터 삭제는 하지 않는다.

## 병합 및 배포: 클릭 순서

1. [PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/christmas-quiet-room?expand=1)를 연다. 로그인 상태에서 **base: main**, **compare: feat/christmas-quiet-room** 확인 후 **Create pull request**. 자동 생성된 PR이 있으면 그 PR을 연다.
2. PR의 **Checks**에서 테스트가 초록색인지 확인한다. 노란색이면 기다리고, 빨간색이면 실패한 로그를 확인한다. 같은 이전 실행의 Re-run은 새 코드를 배포하지 않는다.
3. [Deploy cloud backend (manual)](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml) → **Run workflow** → **Branch: feat/christmas-quiet-room** → **Run workflow**. 가장 위에 새로 생긴 실행을 열어 **deploy-backend / Success**를 확인한다. 기존 Supabase 프로젝트에 함수만 업데이트한다. SQL Editor 작업은 없다.
4. PR로 돌아와 **Merge pull request → Confirm merge**. 충돌/실패 Checks가 있으면 먼저 해결한다.
5. [Test and deploy Pocket Friends](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)에서 이번 병합 제목과 **main**이 표시된 새 실행을 연다. **build** 다음 **deploy** 모두 초록색이 될 때까지 기다린다. 자동 실행이 시작됐다면 수동 Run workflow를 또 누를 필요 없다. 서버 배포 성공만으로 웹사이트가 바뀌지는 않는다.
6. [게임 열기](https://kwonyoung1.github.io/pocket-friends/) → 모바일 페이지 새로고침 → **방 테마 선택: 겨울(크리스마스) 테마**. 기본 또는 할로윈이 선택된 저장을 자동으로 겨울로 바꾸지 않는다. 트리/리스/양말/선물/눈 덮인 창밖이 보이는지 확인한다. 다른 테마로 바꿨다가 겨울로 돌아오고, 새로고침 후에도 유지되는지 확인한다.
7. 바뀌지 않으면 같은 **main 병합 실행의 deploy 성공 여부**와 선택 값을 먼저 확인한다. 브라우저 탭을 닫고 같은 링크로 다시 연다. 사이트 데이터·클라우드 월드·저장 데이터는 삭제하지 않는다.

## 검증 결과

- `npm test`: **535/535 통과**, 41개 파일. 공통 game/interaction 수정으로 단위 테스트 전체를 검증했다. 앞선 병렬 빌드/브라우저 실행 중 기존 보상 테스트 한 건이 pending으로 끝났으나, 해당 파일 단독 8개 및 최종 단위 전체 재실행은 통과했다. 보상 코드는 수정하지 않았다.
- 모바일 관련 E2E: **25/25 통과**. 캐릭터/원화/개인 사진 보존, 보행·대기, 직접 교감, 실제 터치 드래그·취소·동시 잡기, 저장·재접속, 테마·화면 크기·저사양·백그라운드 포함.
- 모바일 클라우드 E2E: **3/3 통과**. 겨울/할로윈 전환과 두 모바일 세션·재접속·원본 저장 보존, 미니게임 중 방 DOM 변경 0 및 동기화 계속 수행.
- TypeScript/Vite build 및 단어 데이터·이펙트 번들 분리 검사 통과. 기존 큰 청크 경고는 남아 있다. 신규 외부 라이브러리는 없다.
- Deno CLI가 환경에 없어 로컬 Edge Function `deno check`는 수행하지 못했다. PR의 기존 CI 단계가 확인한다.
- 사천성/보물 3매치 전체 E2E는 반복 실행하지 않았다. 미니게임 공용 배경 정지 검증 2개만 수행했다.
