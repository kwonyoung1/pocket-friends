원래 Canvas에도 별·광선·충격파가 있습니다. 새 효과의 차이는 입자 수만 늘리는 것이 아니라 발광 텍스처·혼합·탄성과 미술 자산입니다. 미술 품질은 주관적이므로 실제 페이지에서 반복/드래그해 판단할 수 있게 했습니다. 테스트용 점수/HUD 배치는 실제 게임의 완전한 복제는 아닙니다.

## 프레임 성능

프로덕션 Vite 빌드를 preview로 제공했습니다. Chromium의 **SwiftShader 소프트웨어 WebGL**, PC1440×1200 및 iPhone13 화면/터치 에뮬레이션을 사용했습니다. 모바일도 실제 Safari/휴대폰 하드웨어가 아닌 Chromium입니다.

같은16개 제거 이벤트를 한 엔진만 보이게 재생합니다. 각 측정 전에 해당 장면을2초 예열하고6초간 측정, 총3쌍을 A→B/B→A/A→B 순서로 실행했습니다. 다른 브라우저 부하와 빌드를 겹치지 않았습니다. 동일 CSS 크기/프레임 데이터/초기 입자 상한/DPR 제한을 사용하되 실제 입자 수·미술·혼합·자동 감축 규칙은 다릅니다. 따라서 순수 GPU 엔진 속도 벤치마크로 해석하지 않습니다.

|환경|기존 Canvas RAF FPS 중앙값|신규 Pixi+GSAP RAF FPS 중앙값|기존/신규 프레임 p95 중앙값|
|---|---:|---:|---:|
|PC 에뮬레이션|49.5|38.1|50.0 / 50.0ms|
|모바일 화면 에뮬레이션|54.4|38.2|33.3 / 50.0ms|

각 엔진/환경3회 표본이며 >50ms Long Task는 모두0입니다. Long Task0은 GPU/프레임 지연이 없다는 뜻이 아닙니다. FPS는 RAF 콜백 간격으로, GPU 실행시간이나 입력 지연 측정이 아닙니다. 자동 감축 후 상한은 이 표본에서 Canvas32/Pixi64였고 실제 최대 입자 수도 원시 파일에 남겼습니다.

**이 환경에서는 기존 Canvas가 더 빠릅니다.** 시각 효과 후보는Pixi+GSAP로 선정했지만 운영 기본 엔진 교체를 권하지 않습니다. 실제 GPU PC/안드로이드/iOS에서 페이지의 순차 비교를 반복해 확인한 뒤 Canvas 기본+선택적 고품질을 검토하는 것이 적절합니다. 실제 GPU에서 반드시 더 빨라진다고 주장하지 않습니다.

## 검증 결과

- `npm test`: **34개 파일,511개 통과**. 기존509개 + lab 프레임/집계2개.
- 최종 `npm run build`: TypeScript/Vite 다중 페이지/영단어 정답 묶음 제외/새 엔진 격리 검사 통과.
- `npm run check:effects-isolation`: 기존 게임의 정적/동적 도달 그래프에 lab 모듈이나 Pixi/GSAP가 없는지 확인. 현재 game4개/lab14개 도달 청크.
- 프로덕션 `EFFECTS_TEST_URL=http://127.0.0.1:4178 npm run test:effects`: **PC3개/모바일3개,6개 모두 통과**. 이미지·다중 파괴·색상 전체 제거·콤보·포인터/실제 터치·취소·감소 모션·측정/JSON/취소/게임 데이터 불변 포함.
- 테스트 페이지에서 게임/App/Supabase 요청이 없는지 감시하고 기존 저장키의 값이 그대로인지 확인했습니다. 새 점수는 실험 표시이며 코인 API가 없습니다.
- 소스 diff 기준 기존 `src/match3`, `src/sichuan`, `src/cloud`, `supabase`, `src/App.tsx`, `src/main.tsx`, 육성/저장 코드 변경 없음. 실제 운영 서버/DB 조작 없음.
- `git diff --check`: 통과.
