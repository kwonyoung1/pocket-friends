# 동기화 중 화면 흐려짐 개선

PC·모바일 데이터 일치와 보상 중복 방지를 위해 서버 동기화는 유지합니다.

## 변경한 동작

- 5초 연결 확인, 30초 상태 정산, 화면 복귀 시 정산 주기를 그대로 유지합니다.
- 상태 정산만 진행 중이면 게임 조작을 잠그지 않습니다. 상단에 `백그라운드 동기화 중…`을 표시합니다.
- 그동안 입력한 구매·힌트·돌보기 명령은 정산 뒤에 순서대로 전송합니다. 각 호출은 서버 확인까지 기다립니다.
- 실제 사용자 명령의 중복 입력 잠금은 유지합니다. 사천성은 잠겨도 패 전체를 반투명하게 만들지 않습니다.
- 처리 결과 안내 줄의 높이를 유지해 메시지가 바뀔 때 방이 위아래로 튀는 현상도 줄였습니다.
- 연결 실패 시 기존 작업 번호를 재사용합니다. 정산만 실패했다면 다음 조작으로 정산을 재시도한 뒤 조작을 처리합니다. 사용자 작업이 실패했다면 기존의 `같은 작업 다시 시도` 안내를 유지합니다.
- 로그아웃·수동 동기화 버튼은 통신 중 중복 실행 방지를 유지합니다.

서버 응답 속도 자체를 바꾸는 업데이트는 아닙니다. 구매나 패 맞추기의 서버 확인 시간은 남아 있으며, 요청 중복 방지를 없애거나 보상을 미리 지급하지 않습니다.

## 데이터 보존

클라우드 DB, 서버 코드, 저장 형식, 작업 번호, 보상 규칙을 변경하지 않았습니다. 기존 사진·캐릭터·육성·코인·탐험 데이터는 그대로 사용합니다. 새 월드 생성이나 SQL 실행은 필요 없습니다.

## 배포 순서 — 웹사이트만 배포

이번 변경은 브라우저 코드와 CSS에만 있으므로 **Deploy cloud backend (manual)은 실행하지 않아도 됩니다.**

1. [변경사항으로 Pull Request 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...fix/smooth-background-sync?expand=1)를 엽니다.
2. 위쪽 선택값이 `base: main`, `compare: fix/smooth-background-sync`인지 확인합니다.
3. `Create pull request`를 누릅니다. 이미 PR이 있다면 표시된 `View pull request`로 들어갑니다.
4. PR 아래쪽 검사 결과를 기다립니다. `Test and deploy Pocket Friends / build`가 초록색이 된 뒤 `Merge pull request` → `Confirm merge`를 누릅니다.
5. [웹사이트 배포 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)을 엽니다. 가장 위의 이번 병합 실행이며 `main` 표시가 있는 항목을 누릅니다.
6. `build`와 `deploy`가 모두 초록색이 될 때까지 기다립니다. 병합하면 자동 실행되므로 `Run workflow`를 다시 누를 필요는 없습니다.
7. [게임 열기](https://kwonyoung1.github.io/pocket-friends/)를 누릅니다. PC는 `Ctrl + Shift + R`로 새로고침하고 모바일도 새로고침합니다.
8. 월드 선택 화면이 나오면 **이 클라우드 월드 사용하기**를 누릅니다. 기존 데이터를 지우거나 새 월드로 만들지 않습니다.
9. 사천성에서 약 30초 기다려도 패가 한꺼번에 흐릿해지지 않는지 확인합니다. 패를 맞출 때 잠깐 중복 입력을 막는 동작은 정상입니다.

## 검증 결과

- `npm test`: 21개 파일, 198개 테스트 통과. 새 클라이언트 단위 검사 4개는 정산 중 잠금 해제, 순차 전송 및 완료 대기, 실패 정산 재시도, 실패 사용자 작업의 잠금·동일 번호 재시도를 검증합니다.
- `npm run build`: TypeScript, Vite 빌드, 영단어 정답 데이터의 클라이언트 번들 제외 검증 통과. 기존 큰 청크 크기 경고는 남습니다.
- `CI=1 npm run test:cloud -- --workers=2`: PC·모바일 총 40개 통과. 기존 재접속·구매 재시도·기기 간 동기화와 새 지연 응답 시나리오를 포함합니다.
- 관련 브라우저 검사 6개를 별도로 실행해 모두 통과했습니다.
- 첫 전체 실행에서는 두 손가락 교감 검사와 시간 경과 검사가 각 1건 실패했습니다. 결과 문구 영역의 높이를 고정했고, 시간 검사는 실제 서버 저장 시각 차이로 정확한 기대 회복량을 계산하도록 고쳤습니다. 실제 시간도 흐르는 브라우저 검사에서 고정값 42만 기대하지 않도록 한 것으로, 시간당 +8 검증의 허용 오차를 늘리지 않았습니다. 이후 최종 전체 40개가 통과했습니다.
- 로컬 모드 전용 `test:e2e` 전체는 이번에 실행하지 않았습니다. GitHub의 기존 통합 워크플로에서 실행됩니다.
- 사용자 운영 서버의 지연 시간이나 프레임 속도를 직접 측정한 것은 아닙니다. 검증은 테스트 서버의 실제 명령 처리 코드와 의도적으로 지연시킨 응답을 사용했습니다.
