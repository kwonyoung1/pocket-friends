# 씻기 4회·사천성 이펙트·상태 이모션 업데이트

기준 코드: main `461c8f4`(사천성 PR #11 병합본). 작업 브랜치: `feat/care-tile-emotions`.

## 1. 무엇이 바뀌었나요?

| 기능 | 이전 | 이번 변경 |
|---|---|---|
| 씻기 | 친구마다 하루 2회 | 친구마다 하루 4회. 사용한 횟수는 유지 |
| 씻기 시간 | 시작 후 30분 목욕 | 그대로 유지. 남은 분·초를 1초마다 표시 |
| 사천성 제거 | 연결 즉시 사라짐 | 실제 경로 연결선 → 두 패 확대·빛 알갱이 → 축소·제거 |
| 연속 성공 | 없음 | 3연속 Nice! / 5연속 Great! / 10연속 Perfect! |
| 경쟁 수동 섞기 | 한 판 3회 | 한 판 1회. 재시작 시 1회 |
| 탐험 수동 섞기 | 단계마다 3회 | 그대로 유지 |
| 자동 섞기 | 막힌 보드에서 자동 실행 | 그대로 무제한. 수동 횟수 차감 없음 |
| 상태 표현 | 여러 아이콘·지속 모션 | 우선순위에 따라 파스텔 SVG 한 종류를 1.8초 표시 |

기존 캐릭터, 이름·사진·육성 상태, 코인, 인벤토리·가구, 탐험·영단어 진행 기록, 햄스터, 사천성 보드·시간·쿨타임·랭킹을 초기화하지 않습니다. 기존 Supabase 프로젝트와 저장 키·버전을 계속 사용합니다.

## 2. 씻기는 어떻게 사용하나요?

1. 게임에서 원하는 친구의 **상태 확인** 버튼을 누릅니다. 모바일에서 돌보기 영역이 접혀 있다면 이 버튼으로 먼저 펼칩니다.
2. **씻기 (현재 사용 횟수/4)** 버튼을 누르면 생활 화면이 열립니다. 상단 **생활·입양 → 친구 생활**로 들어가도 됩니다.
3. 생활 화면에서 **씻기 (예: 2/4)**를 누르면 해당 친구가 30분간 목욕합니다.
4. 시작 즉시 횟수가 1 올라가며, 남은 시간은 `29분 59초`처럼 표시됩니다.
5. 목욕 중이거나 하루 4회를 사용한 경우 버튼이 비활성화됩니다. 수면·탐험·교감 중에도 기존 제한을 유지합니다.
6. 4회를 사용하면 **“오늘은 충분히 씻었어요! 내일 다시 씻겨 주세요 🛁”**를 표시합니다.

30분 제한은 기존과 같이 **목욕 시작부터 완료까지**입니다. 완료 후 추가로 30분을 더 기다리는 규칙은 넣지 않았습니다. 횟수는 친구마다 따로 관리하고 한국 시간 자정에 초기화합니다. 자정을 넘기는 목욕은 원래 완료 시각까지 계속합니다.

PC·모바일이 동시에 요청해도 서버가 현재 횟수·진행 상태를 확인하고 한 요청만 시작합니다. 새로고침·기기 시간 변경으로 제한을 우회할 수 없습니다. 서버의 시간을 이용한 남은 시간 표시이며 오프라인에서 서버 응답 없이 새 목욕을 확정하지 않습니다.

## 3. 사천성은 어떻게 달라졌나요?

**연결선과 제거 효과**

같은 패 두 개를 누르면 기존 연결 판정 함수가 계산한 실제 좌표를 SVG 선으로 그립니다. 직선·ㄱ자·ㄷ자와 보드 밖 경로를 지원합니다. 패 중심과 그리드 간격을 실제 화면에서 측정하고, 화면 크기가 바뀌면 다시 계산합니다. 외곽 경로용 여백도 확보했습니다.

연결선은 약 0.24초에 그려지고, 두 패가 커졌다가 별 알갱이와 함께 작아져 사라집니다. 전체 효과는 0.45초입니다. 효과 중 입력·힌트·섞기·모드 전환을 잠깐 잠가 중복 제거를 막고, 이후 최신 보드를 표시합니다. 교착 자동 섞기는 제거 표시가 끝난 뒤 이어서 보여 줍니다. 타이머는 계속 흐릅니다.

서버에는 **두 번째 패를 누른 시점에 바로 연결 요청**을 보냅니다. 화면 효과가 끝날 때까지 서버 요청을 미루지 않으므로 마지막 패 이후 애니메이션 시간은 경쟁 기록에 더하지 않습니다. 서버가 거부한 연결은 보드에 반영하지 않으며 연속 성공으로 세지 않습니다. 시스템의 ‘동작 줄이기’ 설정에서는 이동·입자 효과를 없애고 선과 단순 강조만 표시합니다.

**연속 성공**

서버가 확인한 마지막 성공 시각에서 3초 이내에 다음 쌍을 성공시키면 연속 횟수가 이어집니다. 3/5/10회에서만 Nice!/Great!/Perfect! 문구가 잠깐 나타납니다. 잘못된 다른 패를 선택하거나 3초가 넘으면 다시 1회부터 시작합니다. 콤보는 화면 효과이며 추가 코인·점수를 지급하지 않습니다.

**섞기 횟수**

- 경쟁: `섞기 (1/1)` → 사용 후 `섞기 (0/1)` 및 비활성화. 새 판은 다시 1회입니다.
- 탐험: 기존대로 단계마다 3회입니다. 단계·보상·1시간 쿨타임은 유지합니다.
- 자동 섞기: 두 모드 모두 무제한이며 기존의 개수 보존·최소 한 쌍 보장 알고리즘을 유지합니다.

업데이트 전에 시작한 경쟁 판도 보드와 시간을 유지합니다. 기존 3회 중 사용한 횟수를 새 한도 1회에서 차감합니다. 예를 들어 이전 남은 횟수가 3이면 새로 1회, 이전에 한 번이라도 썼다면 0회입니다. 새로고침으로 섞기를 추가 지급하지 않습니다. 기존 최고 기록과 TOP 5는 그대로 보관합니다.

## 4. 캐릭터 이모션은 언제 보이나요?

파스텔 SVG로 밥그릇·빵, 비누·거품, 달·Zzz, 하트·별, 체온계를 제작했습니다. 새로운 얼굴 이미지를 덮어쓰거나 사진의 얼굴을 변형하지 않습니다. 몸의 작은 기울임·살짝 숙이기·가벼운 들썩임으로 감정을 표현합니다. 기본 SVG 동물은 작은 눈 감기 표현도 사용합니다.

- 상태 우선순위: 질병 → 포만감 30 이하 → 청결도 30 이하 → 체력 30 이하 → 행복·일반 감정
- 여러 상태가 낮으면 한 번에 하나만 표시하고 다음 주기에 순서대로 표현합니다. 질병이 있으면 먼저 질병을 알립니다.
- 포만감 10 이하: 살짝 배를 감싸는 듯 숙이고 음식 생각 아이콘을 표시합니다.
- 청결도 10 이하: 작은 먼지를 더 많이, 더 짧은 간격으로 표시합니다. 먼지는 이모션 표시 중에만 보입니다.
- 각 친구는 약 2~4분 간격, 한 번에 1.8초 표시합니다. 근접한 동시 표시를 줄이도록 시간 간격을 둡니다. 서버 갱신·대기 상황에 따라 실제 표시 시점에 약간의 차이가 있습니다.
- 같은 상태만 계속 필요한 경우 두 종류의 그림을 번갈아 표시합니다. 새로고침해도 다음 표시 시각을 유지합니다.
- 말풍선이 있으면 아이콘을 캐릭터 옆으로 옮깁니다. 쓰다듬기·드래그·수면·목욕·탐험 중에는 상태 모션을 억제합니다.
- 먹이·목욕·치료로 상태가 회복되면 해당 이모션을 즉시 숨깁니다. 다른 낮은 상태는 별도로 표현될 수 있습니다.

아이콘이 항상 떠 있지 않은 것이 정상입니다. 이모션을 확인하려면 낮은 상태의 친구를 잠깐 지켜보세요. 일반 동물의 평소 자동 대사는 계속 비활성화하고 필요한 상태 알림만 기존 빈도로 출력합니다. 영이·찬미의 평소 대사와 기존 교감·이동·음식 취향은 유지합니다.

## 5. Supabase에서 SQL을 실행해야 하나요?

**이번에는 새 SQL을 실행하지 않습니다.** 기존 프로젝트·비밀번호·변수·Secrets도 그대로 사용합니다. JSON 저장 데이터에 선택 항목만 추가하고 기존 RLS·CAS 트랜잭션·작업 영수증을 재사용합니다. 서버 코드는 업데이트해야 합니다.

열어 둔 이전 화면이 새 규칙과 기록을 덮어쓰지 않도록 새로고침을 요청하는 보호 장치를 적용했습니다. 서버 배포 직후부터 웹 배포 완료 전까지 이전 화면에 업데이트 안내가 보일 수 있습니다. 웹 배포가 완료되면 PC와 모바일 모두 새로고침하세요. 기존 데이터를 다시 가져오거나 새로운 공유 월드를 만들 필요가 없습니다.

## 6. 배포 방법: 이 순서대로 눌러 주세요

### A. PR을 만들고 검사 결과를 기다립니다

1. [이번 업데이트 PR 생성 화면 열기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/care-tile-emotions?expand=1)
2. 위쪽에 **base: main**, **compare: feat/care-tile-emotions**가 선택됐는지 확인합니다.
3. 제목은 `씻기 4회·사천성 이펙트·상태 이모션 개선`으로 입력해도 됩니다. 설명은 [준비된 PR 본문](https://github.com/kwonyoung1/pocket-friends/blob/feat/care-tile-emotions/docs/CARE_EFFECTS_PR.md)을 참고하세요.
4. 초록색 **Create pull request**를 누릅니다. 이미 PR을 만들었다면 [열린 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls)에서 이번 PR을 열면 됩니다.
5. PR 화면 아래 검사에서 **Test and deploy Pocket Friends / build (pull_request)**가 초록색이 될 때까지 기다립니다. 이 단계는 코드를 검사합니다. 아직 게임 화면 배포 단계는 아닙니다. 빨간색이면 병합하지 말고 해당 검사의 실패 단계 로그를 확인합니다.

### B. 서버를 새 브랜치 코드로 먼저 업데이트합니다

1. [서버 배포 화면 열기 — Deploy cloud backend (manual)](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml)
2. 오른쪽 위 초록색 **Run workflow**를 누릅니다.
3. 펼쳐진 창의 **Branch**를 눌러 **feat/care-tile-emotions**를 선택합니다. 아직 PR을 병합하기 전이므로 여기서는 main을 선택하지 않습니다.
4. 펼쳐진 창 안의 초록색 **Run workflow**를 누릅니다.
5. 목록 맨 위에 생긴 새 실행을 엽니다. 이전 날짜의 초록색 실행과 혼동하지 마세요. 이번 실행의 브랜치가 `feat/care-tile-emotions`인지 확인합니다.
6. 왼쪽 **deploy-backend**와 상단 **Status: Success**가 초록색이면 서버 배포 완료입니다. 이 작업은 씻기 제한·저장·경쟁 규칙을 처리하는 서버를 바꿉니다. 게임 화면은 아직 이전 상태일 수 있습니다.

### C. PR을 병합해 화면 배포를 시작합니다

1. [열린 PR 목록 열기](https://github.com/kwonyoung1/pocket-friends/pulls) → 이번 업데이트 PR 제목 클릭
2. PR의 **Conversation** 탭 아래쪽으로 내려갑니다. 목록 화면에는 병합 버튼이 없습니다.
3. 검사 통과와 서버 배포 성공을 확인한 뒤 **Merge pull request**를 누릅니다.
4. 이어서 나타나는 **Confirm merge**를 누릅니다.
5. PR에 **Merged** 표시가 나타나면 main 반영이 완료된 것입니다.

### D. 게임 화면 자동 배포를 확인합니다

1. [화면 검사·배포 화면 열기 — Test and deploy Pocket Friends](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)
2. 맨 위의 **Merge pull request …** 실행을 엽니다. 브랜치 표시가 **main**인지 확인하세요.
3. **build**는 테스트와 화면 빌드입니다. **deploy**는 GitHub Pages에 새 게임 화면을 올리는 작업입니다. 둘 다 초록색이 되어야 화면 배포가 완료됩니다.
4. 병합으로 자동 실행이 시작됐다면 **Run workflow를 다시 누르지 않아도 됩니다.** 실행 중에는 기다립니다.
5. 자동 실행이 정말 없을 때만 이 화면에서 **Run workflow → Branch: main → Run workflow**를 실행합니다.

| 워크플로 | 대상 | 이번 실행 방법 |
|---|---|---|
| Deploy cloud backend (manual) | Supabase 서버: 규칙·검증·공유 저장 | 병합 전 기능 브랜치를 골라 직접 실행 |
| Test and deploy Pocket Friends | 코드 검사·게임 화면·버튼·효과 | PR에서 검사, main 병합 후 자동 배포 |

### E. PC와 모바일에서 새 화면을 확인합니다

1. [포켓프렌즈 게임 열기](https://kwonyoung1.github.io/pocket-friends/)
2. PC는 새로고침합니다. 이전 화면이 남으면 **Ctrl+Shift+R**(Mac: **Command+Shift+R**)로 다시 불러옵니다.
3. 모바일도 같은 주소에서 브라우저 새로고침을 누릅니다. 데이터 삭제나 앱 저장 공간 초기화는 하지 않아도 됩니다.
4. 공유 월드 선택 화면이 나오면 **이 클라우드 월드 사용하기**를 누릅니다.
5. 친구 생활의 씻기 횟수 `/4`, 새 경쟁 판의 `섞기 (1/1)`, 패를 연결할 때 짧은 선과 반짝임을 확인합니다. 진행 중인 판에서 이미 섞기를 사용했다면 `0/1`이 정상입니다. 상태 아이콘은 낮은 상태인 친구에게 2~4분 간격으로 나타납니다.

## 7. 빨간색으로 실패한다면

실패한 **실행 제목 → 왼쪽 build 또는 deploy-backend → 빨간 × 단계**를 누릅니다. 마지막 오류 20~40줄을 확인하면 됩니다. 실패 원인을 확인하기 전에 월드·저장 데이터·Supabase 프로젝트를 지우거나 다시 만들지 마세요. 배포 토큰·키·비밀번호 값은 대화창에 복사하지 않습니다.

이 문서는 소스와 배포 절차를 준비한 결과입니다. 실제 운영 반영은 위 GitHub 서버 배포와 PR 병합·웹 배포가 끝나야 완료됩니다. 테스트 실행 결과와 실기기 검증 범위는 [검증 보고서](CARE_EFFECTS_VERIFICATION.md)를 참고하세요.
