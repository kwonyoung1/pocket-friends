# 장비 강화 클라우드 검사 새로고침 경쟁 조건

## 보고된 실패

`cloud-tests/enhancement.spec.ts`가 서버의 강화석이 0이 된 직후 두 번째 기기를
새로고침하고, 비활성 상태의 `이 클라우드 월드 사용하기` 버튼을 기다리다
45초 제한에 걸렸다. 첨부 실행은 56개 통과, 1개 건너뜀, 1개 실패였다.

서버의 `commit` 완료는 클라이언트가 응답을 받아 미확인 작업을 지웠다는 뜻이 아니다.
기존 검사는 서버 상태만 기다렸으므로 느린 응답에서 미확인 `enhance` 작업이
sessionStorage에 남은 채 새로고침할 수 있었다. 입장 화면이 미확인 작업을 먼저
복구하도록 잠그는 것은 기존 데이터 보호 동작이다.

브라우저 로그의 D-Bus/GPU 메시지만으로 원화나 그래픽 드라이버 오류라고 판정하지
않았다. 로컬에서 기존 검사는 두 화면 모두 통과하여 간헐성을 확인했고, 추가 fixture가
서버 반영 후 응답을 명시적으로 보류하여 미확인 큐가 남는 구간을 검증한다.

## 수정

- `cloud-tests/fixture.ts`: 다음 강화 응답을 테스트가 해제할 때까지 보류하는 기능.
  기본 상태에서는 기존 요청 처리와 같고 임의 시간 지연이나 무한 재시도를 추가하지 않는다.
- `cloud-tests/enhancement.spec.ts`: 정상 응답을 받은 경우에는 클라이언트 미확인 큐가
  비워진 후 새로고침한다. 서버 반영만 보고 새로고침하지 않는다.
- 별도 응답 유실 시나리오에서는 미확인 작업을 남긴 채 새로고침하고 입장 잠금을
  확인한다. 같은 작업 번호가 유지되는지 검사한 뒤 `앞선 작업 결과 다시 확인`으로
  복구한다. 코인·강화석·아이템·강화 이력이 중복 변경되거나 재추첨되지 않아야 한다.
- +21 강화는 확률 12%이며 성공/실패 모두 유효하다. 서버가 확정한 결과 전체가
  복구 후에도 정확히 유지되는지 검사한다. 성공을 강제하거나 경제 규칙을 바꾸지 않는다.

게임 런타임, 인증, 보상, 사용자 데이터, DB, 원화, 타임아웃 및 배포 정책은 변경하지 않는다.

## 검증 명령

```sh
npx playwright test --config playwright.cloud.config.ts cloud-tests/enhancement.spec.ts cloud-tests/cloud.spec.ts --grep 'cloud enhancement|reload recovers an unacknowledged'
npm run build
```

로컬 결과: 위 관련 검사 **6개 통과**, TypeScript/production build 통과.
전체 클라우드 검사는 기존 CI에서 그대로 실행하며, 로컬에서 전체 60개 통과를 주장하지 않는다.

기존 데스크톱 호환 검사와 모바일 터치 에뮬레이션을 유지한다. PC 디자인 변경은 없으며,
클라우드 검사는 로컬 fixture를 사용하고 운영 DB를 읽거나 수정하지 않는다.

검증 후 기존 자동 PR/CI 경로를 사용한다. 운영 반영 여부는 main 병합과 배포 성공을
별도로 확인해야 하며, 로컬 통과만으로 배포 완료라고 보고하지 않는다.
