# 보물 3매치 검증 보고서

기준일: 2026-10-30 한국 시간. 최신 `origin/main`의 `95bfc2e`에서 만든 `feat/pocket-treasure-match` 브랜치입니다. Node.js 24, 시스템 Chromium, PC Chrome 및 iPhone 13 크기·터치 에뮬레이션을 사용합니다.

순수 엔진과 컨트롤러 테스트는 다음을 검증합니다.

- 30개 스테이지 각각 여러 시드의 초기 64칸·색상 범위·매치 없음·유효 이동·고유 ID.
- 3개/4개/5개 직선, ㄱ/T 교차, 2×2, 무지개 우선순위와 독립 그룹.
- 특수 보석 생성 위치·ID 보존, 10개 조합 유형, 정확한 십자 15칸·3행/3열 39칸·5×5 25칸.
- 무지개 지정 색 제거, 무지개 두 개의 최초 64칸 제거와 3,200점, 낙하 보충·재매치.
- 제거 개체 ID 중복 점수 방지, 연쇄 배율과 정수 점수, 같은 이동의 특수 연쇄, 다음 이동의 콤보 초기화.
- 얼음 교환 제한·중복 손상 방지, 자동 셔플의 점수/이동/얼음 보존과 특수 보석 보존 fallback.
- 잘못된 이동 복구, 빠른 중복 입력 차단, 성공/실패, 해금·최고 기록·여러 탭의 기록 최대값 병합, 저장 차단/손상 대응.
- 진행 중 일시정지의 상태·애니메이션 시간 보존, 다시 시작/종료의 RAF 정리, 메인 저장 키 비변경.

실제 브라우저에서는 클릭·네이티브 터치 스와이프·마우스 드래그·취소·키보드, 일시정지/재개·재시작, 파편·점수·전체 제거, 재접속 기록, 작은 화면의 전체 보드를 검사합니다. 클라우드는 두 브라우저 기기의 실제 서버 핸들러 경로를 사용해 테스트하고, 다른 기기의 구매가 퍼즐 종료 후 반영되는지 확인합니다. 햄스터와 방을 MutationObserver로 감시해 퍼즐 중 그리기가 멈추는 것도 확인합니다.

마지막 점수 팝업·글자 크기·폭발 시차 보정 후 관련 기능 18개와 클라우드 2개를 다시 통과했습니다. 이후 글꼴 로딩을 기다리고 한 작업자만 사용한 연쇄 재측정 6개도 통과했습니다.

## 30개 스테이지 반복 시뮬레이션

```bash
MATCH3_SAMPLES=20 node scripts/match3-balance.mjs
```

스테이지마다 20개 고정 시드, 총 600회입니다. 봇은 가능한 이동의 한 수 결과를 계산하고 즉시 점수와 남는 특수 보석 가치를 보고 선택합니다. 결정적인 다음 낙하를 미리 계산하는 봇이므로 **실제 사용자 승률을 예측하는 수치가 아닙니다.** 점수 폭주·무효 보드·지나치게 어려운 목표를 찾는 반복 검증입니다.

## 실제 프레임·10분 연속 플레이 측정

```bash
MATCH3_SOAK=1 npm run test:e2e -- tests/match3-performance.spec.ts --workers=2
```

이 명령은 시간을 빨리 감지 않고 **각 화면에서 실제 600초 이상** 플레이합니다. 처음에 10연쇄 보드를 실행한 후 교환·폭발·낙하·실패/재시작을 반복합니다. requestAnimationFrame 간격, PerformanceObserver의 50ms 이상 작업, Chrome DevTools Protocol의 GC 후 JS 힙, DOM 노드 수와 브라우저 오류를 수집합니다. CI의 일반 검사에서는 이 긴 실측 두 개를 opt-in으로 생략합니다.

3·5·10연쇄 기능 검사도 실제 프레임 간격과 긴 작업을 별도 기록합니다. 실제 측정 수치는 다음과 같습니다. rAF 콜백 빈도를 측정하며 물리 디스플레이에 출력된 픽셀의 FPS를 보증하는 수치는 아닙니다. 독립 퍼즐 컴포넌트 하네스에서 측정하고, 클라우드 격리/복원은 별도 두 기기 통합 검사로 확인했습니다. 운영 Supabase 네트워크의 실측 FPS는 아닙니다. 서버의 headless Chromium 개발 빌드 결과이며 실제 PC 하드웨어나 iPhone Safari의 FPS로 해석하지 않습니다.

| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| desktop | 523 | 59.40 | 16.8ms | 0 | 0ms | 478 → 467 | 2.55MiB |

## 기존 기능과 데이터 보호

사천성 및 영단어 폴더, CloudClient, 클라우드 프로토콜/서버 엔진, Supabase 함수·SQL, GitHub Actions는 원본 main 그대로 유지합니다. 기존 App/CloudGate/RoomExtras에는 진입 메뉴와 퍼즐 동안의 화면 격리 연결만 추가합니다. 서버 기준 육성·탐험 시간과 진행 중 요청은 멈추거나 취소하지 않습니다.

운영 Supabase 프로젝트나 실제 사용자의 월드에 테스트 데이터를 쓰지 않았습니다. 클라우드 검사는 격리된 인증·네트워크 장치와 기존 서버 핸들러 및 기존 DB 단위 검증을 이용합니다. 실기기 Safari 검증을 했다고 표시하지 않습니다.

신규 DB 테이블·SQL·서버 배포·외부 보상·유료 API·추가 npm 의존성은 없습니다. 새 퍼즐은 별도 JS 청크 29.81KB(gzip 11.88KB), CSS 7.91KB(gzip 2.65KB)로 분리되었습니다. 개발 전용 측정 하네스는 운영 번들에서 제외됩니다. 기존 메인 번들의 Vite 크기 경고는 남지만 빌드는 통과합니다. 운영 반영은 [클릭별 웹사이트 배포 안내](TREASURE_MATCH_DEPLOY.md)를 따릅니다.
