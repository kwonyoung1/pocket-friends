# 별빛 아레나 모바일 화면 개선 결과

2026-11-27. 최신 main `1bb0aa3` 기반. 요청 STANDARD / 실제 판정 FULL. 배치 모듈·회귀 테스트를 기존 공통 정책이 보수적으로 상향했습니다. 기존 검사/병합/배포 보호는 그대로입니다.

## 1. 전투 필드

전장 최소 높이를 210→300 CSS px로 늘렸습니다(최소값 기준 약43%, 모든 화면의 실제 증가율이라는 뜻은 아님). 상단 시즌44px/전투 헤더48px/행동순서28px, 44~45px 스킬/확인 버튼과 높이100px 이내의 적 카드를 사용합니다. 보조 적 정보는 필드의 펼침 패널에서 확인해 주요 정보와 전장 공간을 함께 확보합니다. 360×800·375×812·390×844·412×915를 검증합니다.

## 2. 진형과 접지

- 390px 가상 전장 안에 safe margin, ally zone, enemy zone, 전·후열 지면을 정의합니다. 적 1~6명의 개별 진형과 보스 중심/호위 진형, 아군 최대5명 전후 배치를 사용합니다.
- 단순한 tile 크기 대신 PNG 아틀라스의 알파 경계를 최초 디코딩 때 측정해 불투명 몸체 폭/높이와 발 기준점을 구합니다. 실제 발은 local floor 0에 맞추며, 투명 아래 여백이 지면을 띄우지 않도록 보정합니다. 대기 모션 2종의 최대 경계도 고려합니다.
- 진형에 맞는 셀 폭·인접 열 간격·머리 위 표시 영역으로 크기를 제한합니다. 보스는 중심축에 크게, 호위는 별도 열에 배치합니다. 기존 `enemyLayout` 함수는 과거 호출 호환용으로 보존하며 실제 렌더러는 새 `sceneLayout`을 사용합니다.
- 이름/HP 머리판은 간격을 정리하고 배경이 밝아도 읽히도록 어두운 바탕을 둡니다. 번호로 필드와 적 카드를 연결하며 전체 정보는 접기/펼치기 패널에 표시합니다.

## 3. 배경 프리셋/카메라

불꽃 협곡·설원·숲·성채를 포함한 14개 지역과 크리스마스, 총15개 프리셋을 명시했습니다. 각각 원화 crop, 전후 지면, 안전 여백, 크기 배율, 최대 권장 적6명을 정의합니다. 배경은 가로/세로를 따로 늘리지 않고 원래 비율을 유지한 cover 방식으로 전경을 보여줍니다. 따라서 이전의 배경 상단(하늘) 좌표에 적을 배치하지 않습니다. 전투 카메라는 진형에 맞는 확대 상한을 사용하고, 이동 목적지도 화면 여백 안으로 제한합니다.

## 4. 그림자/깊이

필터 없는 타원2개로 바닥 그림자를 그리고, 전열은 조금 더 진하고 후열은 약하게 처리합니다. 전후열 크기 차이는 약6% 범위로 절제했습니다. foot y로 정렬하며 점프 중에도 그림자/선택 원은 투영된 지면에 남습니다. 기존 스프라이트/원화/배경 이미지는 수정하지 않았습니다.

## 5. 전체 UI

남청색/밤하늘 패널, 금빛 주 대상·선택, 연청색 범위, 은빛 보조 텍스트를 공통 토큰으로 사용했습니다. 과한 실시간 blur 대신 정적 gradient/얇은 테두리/낮은 강도 그림자를 사용합니다. 편성 카드·스테이지 선택·도감/합성·상점/강화·결과/확인 팝업에도 같은 디자인 언어를 적용했습니다.

상단 계층을 줄이고 하단은 HP/현재 행동/스킬/확인 순으로 정리합니다. 버튼의 활성·잠금·선택·포커스·눌림을 구분하고 핵심 터치 높이44px을 유지합니다. 선택한 적의 전체 이름/HP/약점/상태/예고는 **대상 정보**에서 확인합니다. 피해 숫자는 화면 경계를 보정하고 HP 채움은 왼쪽 기준입니다. 보상·스킬 해금·공격/회복/타격·강화·레벨·성급·파티·에너지·계정 저장을 바꾸지 않습니다.

## 6. 성능/데이터

알파 스캔은 아틀라스 로드 때 한 번입니다. 진형/배경 배치는 전투 구성이나 실제 화면 크기가 바뀔 때만 다시 계산하며 프레임마다 배치 최적화를 돌리지 않습니다. ResizeObserver는 종료 시 해제하고 텍스처 메타데이터를 정리합니다. 화면이 공격 중 바뀌면 연출이 끝난 후 재배치합니다. 기존 저품질/동작 줄이기/백그라운드 정지·파티클 제한은 유지합니다. 새로운 이미지·폰트 다운로드나 Supabase 요청을 추가하지 않습니다.

## 7. 검증

- 배치/지면/이름표/알파/비율 단위146개 통과: 4종 배경×3높이×적1~6×보스 여부 등.
- 전체 단위838개 통과(61개 파일). 자동화71개·검증 정책37개, 고정 Deno lock, TypeScript/프로덕션 빌드 통과.
- 신규 모바일9개 통과: 적1/2/3/4/5/6, 보스+호위2/4, 숲/협곡/설원/성채 및 다른 지역, 4개 CSS 화면 크기, 열린 전투의 리사이즈, 44px 터치, 대상 정보, 실제 저장/재화 보존. 별도 기존 360px 6마리 검사도 통과했습니다.
- 전체 브라우저 최초 실행: 200개 통과·19개 기존 조건 생략, 예전 상단55px 고정 기대값 5개 실패. 의도한44px 종료 바에 맞게 겹침/터치 영역 assertion을 수정한 뒤 해당5개 모두 재검증 통과(33.5초). 기존 데이터 보존 검사는 유지했으며 미해결 실패는 없습니다.
- 전체 클라우드: 96개 통과·38개 기존 조건 생략(17.8분). 새 모바일9개도 최신 코드로 통과했습니다. 기기 간 저장·합성·장비·오프라인 재시도·보상 중복 방지·속성 추가 피해/광역 미리보기 검사가 포함됩니다.
- 소프트웨어 GPU의 Chromium 모바일 에뮬레이션이며 실제 Android/iPhone 실기기나 물리 GPU의 FPS 보장으로 보고하지 않습니다.

## 9. 한계

배경은 2D 일러스트이므로 새 배경을 추가하면 crop/지면 프리셋을 실제 그림에 맞춰 조정해야 합니다. 알파 경계는 해부학적 발 인식이 아니며 긴 무기/특수 포즈는 추가 미세 보정이 필요할 수 있습니다. 작은 화면에서 보조 정보는 펼쳐 확인하며, 지원 크기보다 짧거나 시스템 글자가 크게 설정된 화면은 세로 스크롤을 허용합니다. 별도 PC 전용 레이아웃은 추가하지 않았습니다.
