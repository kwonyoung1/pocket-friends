# 조용한 친구들과 6시간 교감 보상

이번 변경은 기존 main을 수정합니다. 저장 키, 사진, 친구 ID, 이름, 레벨, 코인, 아이템, 탐험 결과, 배치 가구, 햄스터, 목욕·감기 및 개명 제한을 초기화하지 않습니다. 기존 특별 친구 이름을 자동으로 바꾸지 않습니다.

## 달라진 동작

- `special-boy`, `special-girl`이 각각 영이·찬미 역할의 특별 친구입니다. 개명해도 이 ID는 유지됩니다. 기존 이름이 남자아이·여자아이라면 현재 개명 기능으로 원하는 이름을 지정할 수 있습니다. 기존 개명 제한은 그대로 적용합니다.
- 특별 친구만 20~50초 간격의 혼잣말을 합니다. 한국 시간대, 상대의 실제 이름을 사용합니다. 말풍선이 있으면 자동 대사를 잠시 미루며, 특별 친구끼리는 인사와 답을 순서대로 출력합니다.
- 일반 친구는 평상시 조용하게 이동하고 만났을 때 고개를 끄덕입니다. 터치·교감·돌봄 및 이벤트 완료 때는 반응합니다. 햄스터는 계속 말하지 않습니다.
- 포만감·청결도·체력이 30 이하이면 작은 돌봄 아이콘, 먼지·졸림·배고픔 표현이 나옵니다. 포만감/체력이 낮으면 속도가 느려지고, 체력 10 이하이면 휴식이 길어집니다. 포만감/청결도 10 이하에서는 행복 감소가 조금 빨라집니다. 이동을 영구적으로 멈추지 않습니다.
- 가장 낮은 상태를 우선 알리고, 같은 상태는 15분에 한 번만 자동 알립니다. 클라우드는 서버가 알림 시각을 보관하며 여러 친구의 알림을 최소 8초 간격으로 분산합니다. 직접 터치 반응이 최우선입니다.
- 일반·장시간 교감은 친구별로 정확히 360분의 보상 제한을 공유합니다. 일반 +행복2/친밀1, 특별 +행복5/친밀3입니다. 제한 중에는 하트와 대사만 나오며, 교감 XP·미션 횟수·성향 보상도 추가되지 않습니다.
- 상세 패널에 보상 가능 여부와 남은 시간, 현재 필요한 돌봄, 특별 친구 표시를 추가했습니다. 사진/사람 캐릭터 얼굴을 변형하지 않습니다.

## 저장 및 동기화

`Save.version=2`와 기존 저장 키를 유지합니다. 선택 필드 `lastPetRewardAt`, `careAlertAfter`, `lastCareLine`, `careNotice`를 추가하고, 기존 `petRewardAfter` 및 성장 보상 제한을 보존합니다. 새 필드가 없는 친구는 기존 제한이 끝난 뒤 처음 보상받을 수 있습니다. 별도 코인 지급이나 월드 재생성은 없습니다.

보상 판정은 Edge Function의 서버 시각을 사용합니다. 기존 PostgreSQL의 버전 비교/행 잠금/작업 번호 중복 제거로 동시 입력을 처리합니다. 클라우드 패널의 남은 시간도 서버 응답 시각과 단조 시계를 사용하므로 기기 날짜 변경으로 초기화되지 않습니다. 로컬 개발 모드는 기기 시간 기반이며 서버와 같은 시간 조작 방지를 보장하지 않습니다.

새 규칙이 저장된 월드는 구형 클라이언트의 변경 요청을 거절하고 새로고침을 안내합니다. 이 변경의 클라이언트 프로토콜은 4입니다. **서버 먼저, 화면 나중에 배포**해야 합니다.

## 비밀번호와 실제 배포 상태

비밀번호는 코드에 포함하지 않습니다. 기존 서버의 `GAME_ACCESS_PASSWORD`를 서버에서 해시 비교하고, Supabase 익명 인증에 더해 입장 회원 여부를 검사합니다. 익명 인증만으로 공유 월드를 읽거나 바꿀 수 없습니다. 기존 RLS, 서버 전용 쓰기, 전역 15분당 10회 로그인 시도 제한, 7일 입장 권한 만료, 로그아웃 시 회원 권한 회수를 유지합니다. 4자리 공유 비밀번호는 가족용 접근 제한이며 개인 계정의 강한 인증을 대신하지 않습니다.

배포용 빌드에서는 클라우드 플래그가 빠지거나 false여도 로컬 게임으로 우회하지 않습니다. URL·공개 키가 없으면 설정 안내만 표시하고 기존 게임 데이터를 렌더링하지 않습니다. 로컬 게임은 개발 서버에서만 허용합니다.

자동 테스트는 운영 데이터와 다른 모의 API 및 PostgreSQL에서 실행합니다. 운영 비밀번호, 운영 RLS 적용 상태, 실제 iPhone/Android 기기는 이 작업에서 직접 변경하거나 검증하지 않았습니다. 브랜치 푸시는 운영 배포 완료를 의미하지 않습니다.

## 직접 눌러야 하는 순서

1. GitHub 저장소 **Settings → Secrets and variables → Actions → Secrets**를 엽니다.
2. **New repository secret**을 눌러 Name에 `GAME_ACCESS_PASSWORD`, Secret에 대화에서 지정한 접속 비밀번호를 입력하고 **Add secret**을 누릅니다. 이미 있으면 연필 버튼으로 수정합니다. 비밀번호를 Variables, 코드, PR 본문에 넣지 마세요.
3. 이번 PR의 검사가 통과했는지 확인한 뒤, **Actions → Deploy cloud backend (manual) → Run workflow → Branch: feat/care-dialogue-cooldowns → Run workflow**를 누릅니다. 이 워크플로는 새 secret이 있으면 Supabase 서버 비밀번호를 적용한 뒤 함수를 배포합니다. 없으면 기존 서버 비밀번호를 유지합니다. 기존 `SUPABASE_ACCESS_TOKEN`과 `SUPABASE_PROJECT_REF` 설정을 재사용합니다. 비밀번호 적용에는 해당 토큰의 Application services → Edge Function Secrets → Read-write 권한이 필요합니다. 권한 오류가 나오면 이 권한을 포함한 토큰으로 GitHub의 `SUPABASE_ACCESS_TOKEN` secret을 교체한 뒤 같은 작업을 다시 실행하세요.
4. 서버 배포가 초록색이면 이번 PR로 돌아가 **Merge pull request → Confirm merge**를 누릅니다.
5. **Actions → Test and deploy Pocket Friends**에서 병합으로 시작된 실행을 엽니다. 실행이 없으면 **Run workflow → main → Run workflow**를 누릅니다. 서버와 화면 배포 사이에는 구형 화면에서 새로고침 안내가 나올 수 있으며, 기존 데이터는 유지됩니다.
6. build와 deploy 모두 초록색인지 확인하고 기존 Pages 주소를 새로고침합니다. 새 시크릿/비공개 창에서 게임을 열면 비밀번호 화면이 먼저 보여야 합니다. 틀린 비밀번호는 입장하지 못해야 합니다.
7. PC·모바일에서 같은 친구를 확인합니다. 한쪽에서 쓰다듬은 뒤 다른 쪽의 **새로 동기화**를 누르면 같은 보상 대기 시간이 표시되어야 합니다. 기존 세션이 유효한 브라우저는 비밀번호를 다시 요구하지 않는 것이 정상입니다. **로그아웃**하면 다시 요구합니다.

**새 Supabase 프로젝트 생성, SQL 재실행, 월드 초기화, 기존 데이터 재가져오기는 필요하지 않습니다.** 비밀번호 secret 적용은 기존 세션을 모두 강제로 로그아웃시키지 않습니다. 권한이 만료되지 않은 기존 회원은 유지됩니다.
