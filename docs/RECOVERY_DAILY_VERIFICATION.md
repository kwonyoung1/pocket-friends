# 회복 음식·한국 시계·일일 랭킹·단어 데이터 검증

검증일: 2026-10-17. 운영 Supabase 데이터와 실제 플레이어 저장소에는 테스트 명령을 보내지 않았습니다. 기존 설치 의존성을 사용했으며 새 패키지는 필요하지 않았습니다.

## 자동 검사

- `npm test`: **175개 통과**, 19개 파일. 실제 PostgreSQL 엔진 PGlite를 사용하는 서버 검사 30개 포함.
- 전체 화면 검사 `CI=1 npm run test:e2e -- --workers=2`: 최초 실행 **107개 통과, 3개 실패**(110개). 개발 중 소스 갱신으로 드래그가 취소된 1개, 새 음식 사용 버튼 오류로 실패한 2개였습니다.
- 새 음식 아트 적용 범위를 카드 아이콘으로 한정하여 버튼 이름과 사용 명령을 복구했습니다. 음식 테스트의 시각도 잠들지 않은 낮으로 수정했습니다.
- 관련 재검사에서 별도 시계 성능 검사용 React import 방식도 수정했습니다(Vite 최적화 모듈은 default export 사용).
- 최종 재검사 `CI=1 npm run test:e2e -- tests/recovery-daily.spec.ts tests/interactions.spec.ts --grep 'clock|ranking|recovery foods|drag from a pending' --workers=2`: **10개 통과**. 실패했던 3개와 새 시계 독립 갱신 2개를 포함하여 PC·모바일에서 검증했습니다.
- 기존 전체 실행과 수정 후 재검사를 합쳐 **서로 다른 화면 시나리오 112개**가 통과했습니다. 단일 실행에서 112개 전부가 초록색이었다고 보고하는 것은 아닙니다.
- `npm run test:cloud -- --workers=2`: **34개 통과, 새 검사 2개 실패**. 실패는 읽기만 한 저장소에도 새 필드가 이미 저장됐을 것이라는 테스트의 가정 때문이었습니다. 기존 저장을 읽는 동작은 원본을 덮어쓰지 않습니다.
- 테스트에서 실제 경쟁 시작 명령을 보낸 뒤 추가 필드 저장을 확인하도록 고쳤습니다. `npm run test:cloud -- --grep 'server-synced clock' --workers=2`: **2개 통과**. 총 36개의 서로 다른 클라우드 시나리오를 검증했으며, 단일 36개 전체 통과 실행은 아닙니다.
- 휴대폰 `Date.now`를 2038년으로 바꿔도 서버 보정 시계·한국 날짜·경쟁 시작 기록은 2026년 서버 시간을 사용합니다. 다른 기기에서 전날 기록을 읽어도 보존되고 오늘 목록에는 나타나지 않습니다.
- `npm run build`: **통과**. TypeScript·Vite·공개 번들 정답 데이터 제외 검사 포함.
- Deno `check --frozen`: **통과**. 기존 Supabase 함수 lockfile 그대로 사용.
- `node scripts/build-word-expansion.mjs --check`: **통과**. 원본 300개와 생성 파일 일치.
- `git diff --check`: **통과**.

## 단어 수량과 검증의 범위

기존 390개 + 직접 작성한 300개 = **690개**. 단계별 **230 / 230 / 230**입니다. 목표 **1,800 / 1,800 / 1,400**에는 각각 **1,570 / 1,570 / 1,170**, 총 **4,310개** 부족합니다. 5,000개 목표는 미완료입니다.

새 데이터 원본은 `data/words/recovery-expansion.tsv`이며, 번들용 생성본은 `src/words/recoveryRows.ts`입니다. 원본-생성본 일치 검사와 전체 데이터 구조·대표 뜻 검사를 실행했습니다. 뜻·예문은 직접 작성했으며 자동 검사는 외부 전문가의 전체 언어 감수나 공식 학년 인증을 뜻하지 않습니다. 신뢰할 수 없는 자료로 숫자만 맞추지는 않았습니다.

## 한계

- 자연 회복은 기존 비수면 회복 기준이 없어 사용자 선택을 기다립니다. “2배 회복 완료”로 처리하지 않았습니다.
- Chromium 데스크톱과 iPhone 크기·터치 에뮬레이션을 사용했습니다. 실제 iOS Safari 실기기 검사는 수행하지 않았습니다.
- 배포 전 코드와 격리된 서버·DB를 검증했습니다. 사용자가 Actions를 실행하기 전에는 운영 게임에 적용됐다고 주장하지 않습니다.
- 기존 빌드의 큰 JS 청크 경고는 남아 있습니다. 빌드 실패는 아닙니다.
