1. PR의 **Checks**를 누릅니다. [이번 브랜치 실행 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Acodex%2Fstarlight-beast-update)에서도 확인할 수 있습니다.

3. `unit`, `browser`, `cloud`, 필수 검사 `build`가 성공해야 합니다. **Expected/Pending**는 통과가 아닙니다.
4. 빨간 검사는 눌러 실패한 단계의 로그를 확인합니다. 검사·보호 규칙을 끄지 않습니다.
5. 자동 병합되면 보라색 **Merged**가 표시됩니다.

**Approvals — 1 still required / Review required**가 실제로 보이는 경우:

1. **Files changed**를 누릅니다.
2. 변경을 검토하고 **Submit review** 또는 **Review changes**를 누릅니다.
3. **Approve → Submit review**를 누릅니다. 작성자 본인 승인 제한이 있다면 저장소가 허용하는 다른 리뷰어가 필요합니다.
4. 조건을 모두 충족했는데 자동 병합되지 않을 때만 실제 화면의 **Enable auto-merge**, 또는 **Merge pull request → Confirm merge**를 사용합니다.

이번 변경은 서버 명령·에너지·재화 지급을 포함합니다. `AGENTS.md`와 기존 `scripts/automation/policy.mjs`가 요구하는 명시적 리뷰·운영 승인을 유지합니다. 이미 설정된 자동 PR/자동 병합을 다시 설정하거나 보호 규칙을 낮추지 않습니다.

## 4. 운영 게임에서 5인 편성하기

1. [포켓프렌즈 운영 게임](https://kwonyoung1.github.io/pocket-friends/)을 엽니다.
2. 평소처럼 로그인하고 **이 클라우드 월드 사용하기**를 누릅니다. 새 월드 생성·초기화·백업 덮어쓰기를 누르지 않습니다.
3. 성장·모험 메뉴에서 **별빛 아레나**를 누릅니다. 가로 메뉴를 옆으로 밀면 찾을 수 있습니다.
4. **정식 도전 / 친구 실제 레벨**을 확인합니다.
5. 친구 또는 보유 환수 카드를 눌러 선택합니다. **최대 5명·총 COST 10·영이 또는 찬미 포함·중복 불가**입니다.
6. 5명을 골랐는데 COST가 넘으면 고COST 친구를 해제하고 COST 2 친구로 바꿉니다. 처음부터 저COST 친구 5명을 보유하지 않았다면 기존 입양 또는 환수 획득 후 5인 편성이 가능합니다. 미보유 캐릭터를 자동 지급하지 않습니다.
7. 지역과 스테이지를 고르고 아래 **달빛 숲으로 출발** 등의 버튼을 누릅니다.

지휘력 강화 시스템은 현재 main에 없으므로 존재하지 않는 지휘력 구매 메뉴를 안내하지 않습니다. 기존 COST는 그대로 유지합니다. 출전 시 착용 장비의 강화 단계는 최대 12% 범위의 아레나 능력치 보조로 서버에 고정되며, 장비 자체와 기존 탐험 보너스는 변경하지 않습니다.

## 5. 별빛 에너지 확인

아레나 상단의 **별빛 에너지 현재값 / 100**을 확인합니다.

| 스테이지 순번 | 입장 에너지 |
|---|---:|
| 1~10 | 10 |
| 11~20 | 12 |
| 21~30 | 15 |
| 31~35 | 18 |
| 36~40 | 20 |

- 12분당 1, 최대 100까지 서버 시간으로 회복됩니다. 자연 회복 속도는 하루 120입니다. 가득 찬 동안 초과 회복은 비축되지 않습니다.
- **다음 +1**, **완충**까지 남은 시간이 표시됩니다. 부족하면 출발 버튼이 비활성화됩니다.
- 서버가 티켓 생성과 차감을 함께 확정합니다. 시작 요청이 서버에서 실패하면 차감도 저장되지 않습니다.
- 서버는 시작했지만 응답이 끊겼다면 같은 티켓을 **전투 이어하기**로 열면 됩니다. 재접속·새로고침으로 다시 차감하지 않습니다.
- 이미 시작한 전투의 패배·포기·유효 시간 만료에는 에너지를 돌려주지 않습니다. 같은 진행 중 티켓의 재입장은 무료입니다.
- 코인 충전 버튼은 없습니다. 에너지 부족 때도 **연습**은 무료·무보상이며 기존 육성·탐험·사천성·보물 3매치는 계속 이용할 수 있습니다.
- 계정은 서버가 검증한 아레나 계정 기준입니다. 같은 기기의 재로그인은 별도 연결 코드로 기존 계정을 자동 복구합니다. 다른 기기는 아래 연결 절차를 따라야 같은 환수·에너지를 사용합니다. 저장소/로그인 데이터 삭제를 해결책으로 사용하지 않습니다.

## 6. 상자에서 환수 획득하기

1. 정식 전투에서 승리하고 결과 화면의 서버 보상 확정을 기다립니다. 코인·경험치·상자 수량을 확인합니다.
2. **파티 다시 편성하기**를 누릅니다.
3. 위쪽 **환수 도감 · 보물상자**를 누릅니다.
4. 보유 상자 옆 **개봉**을 누릅니다. 서버 확인이 끝나기 전에 여러 번 누르지 않습니다.
5. 푸른빛/보랏빛/황금빛/천상 별자리 연출 뒤 환수 이름과 획득 결과가 표시됩니다. **연출 건너뛰기** 또는 **확인**으로 빨리 마칠 수 있습니다. 모션 감소 설정도 지원합니다.
6. 중복 환수는 같은 환수의 전용 조각으로 바뀝니다. 희귀 8개·영웅 16개·전설 32개·신화 64개입니다. 동일 환수를 여러 칸에 편성할 수 없습니다.
7. **최근 개봉 결과 다시 보기**는 결과를 다시 보여줄 뿐 추가 지급·재추첨을 하지 않습니다.
8. **파티 편성으로 돌아가기**를 누르면 획득한 환수를 실제 목록에서 선택할 수 있습니다. 환수는 기존 방·탐험·다른 미니게임에는 나타나지 않습니다.

## 7. 확률과 천장 보기

1. 상자 목록에서 **상자 이름 / 확률 보기** 부분을 누릅니다.
2. 아래에 그 상자의 실제 등급 확률과 보장 횟수가 표시됩니다. 천장 회차에는 기본 확률과 달라진 실제 확률을 구분해 표시합니다.
3. 전설의 보물상자 기본 확률은 일반 보상 65%, 희귀 24%, 영웅 8%, 전설 2.7%, 신화 0.3%입니다.
4. 신화는 전설 상자에서만 나옵니다. 별빛·전설 상자 합산 40회에는 전설 이상, 전설 상자 300회에는 신화를 보장합니다. 해당 등급 이상 획득 시 관련 카운트가 초기화됩니다. 신화 보장을 우선 적용합니다.
5. 같은 등급 환수는 등급 안에서 같은 확률입니다. 일반 보상은 해당 상자의 코인(82%) 또는 강화석 1개(18%)입니다. 이는 등급 추첨 후의 조건부 확률입니다.

숲·호수·수정·고대·별빛·전설 상자는 서로 다른 표를 사용합니다. 후반일수록 상자가 좋아집니다. 상자 유료 구매는 없습니다.

## 8. 도감과 환수 육성

1. 도감에서 이름·등급·COST·역할·획득일·중복·조각을 확인합니다. 미획득 환수는 실루엣입니다.
2. **스킬·획득 상자**를 누르면 스킬 해금 레벨과 획득 가능한 상자가 펼쳐집니다.
3. 보유 환수의 **조각 5 → XP 100**으로 전용 조각을 사용해 성장시킵니다. 최고 레벨은 50입니다.
4. **별자리 강화**는 단계에 따라 전용 조각 10·20·30·40·50개를 사용합니다. 최대 5단계이며 단계마다 HP·공격·방어가 3% 증가합니다.
5. 정식 전투 출전 경험치로도 환수가 성장합니다. 일반 친구의 기존 성장·마스터리는 그대로 유지됩니다. 액티브 Lv.30·35, 필살기 Lv.50 해금도 유지합니다.

환수: 루미·네뷸라(희귀), 셀레나·폴라·피닉(영웅), 아스트라·이클립스(전설), 세라피아(신화).

### 다른 기기에서 자동 공유하기

최신 자동 공유 버전에서는 연결 코드가 필요 없습니다. 같은 게임 접속 비밀번호로 로그인한 모든 기기가 같은 아레나를 사용합니다. 다른 기기의 개별 진행이 이미 있다면 기록을 삭제하지 않고 도감에서 선택할 수 있습니다. 서버와 웹이 모두 배포됐는지 [자동 공유 클릭 안내서](ARENA_AUTO_SHARE_DEPLOY_GUIDE.md)로 확인합니다. 이전 버전의 코드·브라우저 저장 데이터를 지우지 않습니다.

## 9. 난이도와 보상 확인

40개 기존 스테이지 ID와 해금 순서는 유지합니다. 후반은 공격·방어·속도·약점 게이지·결계와 격노 패턴이 강화됩니다. 성장을 마친 일반 친구로도 공략 가능하도록 검증합니다. 환수 등급만으로 승리가 결정되지 않습니다.

반복 코인은 5스테이지 구간별 **6·9·15·24·36·54·78·120**입니다. 첫 클리어 코인은 반복의 3배, 정식 승리는 상자 1개, 첫 보스는 상자 2개를 지급합니다. 첫 보스의 기존 강화석·희귀 보물도 연결됩니다. 고난도에서 에너지당 코인도 증가합니다.

기존 탐험 보상을 변경하지 않습니다. 공유 월드 전체 아레나 코인은 한국 시간 하루 5,000 안전 한도를 적용합니다. 계정별 출전 캐릭터 XP는 하루 100 한도를 유지하며 최고 레벨은 XP 지급 제외입니다. 코인 한도 이후에도 에너지는 소비되고 클리어 진행·상자는 저장됩니다. 미수령 첫 보상은 다음 보상 가능일 재도전으로 받습니다. 상자의 일반 코인이 한도 때문에 전혀 지급되지 못하면 강화석 1개로 바꿉니다.

## 운영 완료 조건

이번 PR Merged, 최신 main 필수 검사 성공, 필요한 서버 배포·SHA 검증 성공, Pages 배포·공개 SHA·읽기 전용 모바일 부팅 성공, 운영 새 콘텐츠 확인까지 완료돼야 합니다. 로컬 테스트 통과만으로 운영 배포 성공이라고 보고하지 않습니다.

## 클라우드 재접속 검사 오류 수정 확인 (PR #41)

구매·장비 강화의 응답이 끊긴 뒤 재접속하면, **앞선 작업 결과 다시 확인**으로 원래 작업 번호를 재조회합니다. 아레나 복구가 일반 거래까지 자동 처리하던 오류를 수정했습니다. 아레나 작업만 남아 있는 경우에는 자동 복구를 유지합니다. 보물 3매치 검사는 이동 애니메이션을 실제로 진행한 뒤, 멈춘 가상 시계의 유휴 시간만 건너뜁니다. 서버 보상 검증·두 기기 동기화·중복 코인 방지 검사는 유지합니다.

1. [PR #41 검사](https://github.com/kwonyoung1/pocket-friends/pull/41/checks)를 엽니다. **Commits**에서 최신 수정 커밋이 있는지 확인하고 **Checks**로 돌아옵니다. 이전 실패 커밋을 재실행해도 새 수정은 적용되지 않습니다.
2. **Test and deploy Pocket Friends**를 펼칩니다. `unit`, `browser`, `cloud`, 최종 필수 `build`가 성공해야 합니다. **Approve workflows to run**이 실제 표시되면 누릅니다. 검사 실패 시 해당 검사 로그를 확인하고 병합을 진행하지 않습니다.
3. [PR 본문](https://github.com/kwonyoung1/pocket-friends/pull/41)에서 **Merged**인지 확인합니다. 기존 보호 정책이 리뷰를 요구하는 경우에만 **Files changed → Submit review → Approve → Submit review**를 사용합니다. 보호 규칙을 해제하지 않습니다.
4. [main 배포 실행 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Amain)에서 해당 병합 커밋의 실행을 엽니다. **Waiting / release-approval**이면 **Review deployments → release-approval 선택 → Approve and deploy**를 누릅니다. 해당 버튼이 없으면 추가 조작하지 않습니다.
5. 전체 환수 업데이트에는 기존 계획에 따른 `game` 서버 배포가 필요합니다. 이번 재접속 수정만으로는 서버·DB 구조·토큰 변경이 추가로 필요하지 않습니다. `backend-gate`와 `deploy`의 성공 및 공개 버전 SHA를 확인합니다.
6. [운영 게임](https://kwonyoung1.github.io/pocket-friends/)에서 새로고침합니다. 저장 데이터나 쿠키를 지우지 않습니다. 구매·강화 재시도 안내는 미확인 작업이 있을 때만 표시됩니다. 운영 데이터로 오류 상황을 일부러 만들거나 보상을 반복 청구하지 않습니다.

이 안내는 확인 절차입니다. PR 검사 성공, 병합, 운영 배포 성공은 각각 별도로 확인해야 합니다. 기존 정상 Secrets·토큰·브랜치 보호 설정을 다시 만들 필요는 없습니다.

로컬 수정 검증 결과 (2026-11-23): 단위 테스트 606개 통과, 전체 클라우드 검사 70개 통과·기존 조건에 따른 12개 생략·실패 0개(15.3분), TypeScript 포함 프로덕션 빌드 통과. 보물 3매치 재접속 보상 검사는 데스크톱 25.3초·모바일 에뮬레이션 25.9초이며 기존 제한 45초를 유지했습니다. 운영 서버가 아닌 분리된 테스트 서버 결과입니다. 원격 CI·병합·운영 배포 결과와 혼동하지 않습니다.
