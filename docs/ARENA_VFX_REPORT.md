# 별빛 아레나 스킬 연출 개선 결과

2026-11-27. 기준 main `d7c9c45`, 작업 브랜치 `codex/arena-skill-vfx`. 요청STANDARD / 기존 공통 정책 실제FULL. 서버·저장·경제·스킬 수치·원화는 변경하지 않는다.

## 1. 외부 자료·기술

[실제 조사 기록](ARENA_VFX_RESEARCH.md)에 접속 결과·메타데이터·라이선스·채택 이유를 기록했다. 요청된6개 게임의 공식 사이트/영상과 기술 문서 사이트는 프록시403으로 확인하지 못했다. 직접 영상을 분석한 것처럼 보고하지 않는다. 설계는 요청서의 연출 원칙과 직접 확인한 설치 소스/API를 바탕으로 했다.

설치된 **PixiJS8.22.0(MIT)**와 **GSAP3.15.1(Standard no-charge license, 설치 README에서 무료 상업 사용 명시)**를 재사용해 새 전투 파티클/타임라인에 통합했다. `@pixi/particle-emitter5.0.10`은 peerDependency가8미만이어서 설치하지 않았다. Phaser/Rive는 중복 런타임·제작 자산/에디터 조건 미확인으로 도입하지 않았다. 새 유료 에셋/구독/의존성 추가는 없다.

## 3. 기존 대비

- 준비: 캐릭터의 짧은 후행 회전, 발밑 투영 문양과 에너지 응축.
- 발동: 실제 몸체에서 출발하는 궤적/투사체, 직접 타격 접근·잔상. 당근/화살/물약/얼음은 다른 형태와 포물선을 사용한다.
- 명중: 곡선 검기·균열·불꽃 날개·결정·성운·연금 반응 등 서로 다른 실루엣, 밝은 중심/잔광 분리, 지면 반응과 피격.
- 타격 강조: 강한 타격에 짧은 홀드와 작은 카메라 흔들림. 모든 일반 공격에 강한 흔들림을 강요하지 않는다.
- 종료: 잎/파편/잔불, 자연스러운 원위치와 카메라 복귀. 배속은 동일 게임 시퀀스를 압축한다.

|네뷸라|회전 별/타원 성운, 각 실제 타격의 성운 명중, 격파 강조|

기존 친구10명(영이·찬미 포함)·요정8명·모험가8명, 총26개의 기존 정의에 공통 프리셋을 적용했다. 몬스터는 실제 스킬 style·속성·boss 여부와 발/몸체/크기를 사용한다. 일반/정예/보스가 기존 전투 엔진에서 결정한 공격을 재생하며 캐릭터를 새로 지급하거나 이름/ID를 바꾸지 않는다.

## 5. 속성·상태·등급

- 화염: 굽은 불꽃/날개/지면 잔불. 물·얼음: 결정 투사체/서리/얼음 파편.
- 빛: 별자리·프리즘 별·황금 문양. 어둠: 검기 균열/성운/보랏빛 연무.
- 자연: 덩굴 곡선/잎/꽃. 대지: 갈라지는 지면/돌기둥·중력 파편.
- 화상/독/출혈/재생은 작은 입자, 빙결은 몸체 주위 결정, 기절은 별, 방어 감소는 깨진 방패, 공격 강화는 상승 표식, 실제 보호막/가호는 장벽으로 표현한다. 상태가 끝나거나 대상이 사라지면 제거한다.
- 희귀/영웅/전설/신화는 입자 밀도·문양 층·컷인 길이와 신화 강조를 달리한다. 성급은 제한된 장식 강도에만 반영한다. 피해·타격 수·확률은 바꾸지 않는다.

## 6. 필살기·카메라

기존 카드 원화에 별자리/사선 배경/계층화된 명암과 스킬명을 결합한다. 전설·신화는 더 긴 전용 컷인 시간을 사용하며5성 별 표기도 유지한다. 실제 캐릭터와 다른 이미지를 생성하거나 손발을 바꾸지 않는다. 배경/지면 프리셋을 유지하고 확대 상한과 작은 추적 범위로6명 전투에서도 카메라가 과하게 벗어나지 않게 제한한다. 효과는 canvas 안에 그려 DOM HUD 위로 나가지 않는다.

## 7. 전투 결과 안전성

`Action.hits[].strikes`와 차단/치명타 배열이 표시 타격의 기준이다. UI가 타격 수나 피해를 추정하지 않는다. 첫 접촉에서 기존 결과를 한 번 넘기고 이후 타격은 같은 확정 결과를 표시한다. 추가 회복/보호도 실제 Hit로만 표시한다. 연출 오류 때 이미 기록한 행동의 결과를 유지하고 낮음 품질로 전환한다. 닫기는 전투 소유 GSAP timeline을 취소하고 자료를 정리한다. 게임 시드·능력치·성장·스킬 수치·보상·서버/RLS/DB는 변경하지 않는다.

## 8. 성능·측정

- 기본 보통, 낮음32/보통80/높음144개의 활성 파티클 상한. 동작 줄이기에서는 최대12개. vector 효과8/16/24개, 떠오르는 숫자16개 상한. 기존 기기 판정/연속 프레임 지연 시 자동 축소를 유지한다.
- Particle/Graphics/Text 풀링,12모티프 공통 texture source, 프레임별 외부 요청 없음. 실시간 blur/postprocess 필터 없이 blend와 벡터 레이어를 사용한다.
- 직전 main과 같은 내용의 UI 빌드 대비 아레나 JS460,388→471,688bytes, CSS55,836→58,026bytes. gzip 합계163,132→167,423bytes, **4,291bytes(약2.63%) 증가**. 기존 GSAP 청크70,647bytes(gzip27,626)는 동일하다. 이 비교는 전체 앱/전송량/매출/실기기 메모리 측정이 아니다.
- 초기 방 화면의 PixiJS/GSAP 제외·연출 실험실 코드 분리 검사 통과. 새 이미지 다운로드나 Supabase API 요청을 추가하지 않았다.
- 최종 Chromium WebGL 소프트웨어 GPU·DPR1·순차1worker의8대표 렌더러 검사에서 활성 입자 peak44~144, vector peak5~24, 숫자 peak1~16이었다. Pixi deltaMS(100ms 상한)의 평균21.5~28.8ms, peak100ms가 관측됐다. 이전2worker 실행의39.0~48.2ms와는 동시성 조건이 달라 코드 성능 개선률로 비교하지 않는다. 이 수치는 캡처 일시정지/렌더러 전용 harness/공유 CPU·소프트웨어 GPU가 포함된 ticker 진단값이며 실제 표시 FPS나 물리 기기 성능으로 환산하지 않는다. 실제 Android/iPhone의60/30FPS 달성은 미검증이다.
- 품질 반복 검사에서는 낮음(동작 줄이기) peak12/보통80/높음144개의 파티클 풀을 재사용했다.6번 재생 뒤 중단/종료 후 활성 입자·할당 풀·vector·떠오르는 숫자·timeline이 모두0이었다. 실제 장시간 JS heap/모바일 발열 측정은 하지 않았다.

## 9. 검증

전체 단위868개(새30개 포함), 자동화71개, 검증 정책37개, frozen Deno 및 TypeScript/프로덕션 빌드 통과. 전체 브라우저214개 통과·28개 기존 조건 생략(13.0분). 전체 클라우드는 최초94개 통과·38개 기존 조건 생략·2개 실패(16.8분). 실패는 적의 사라짐 tween의 정상 취소 오류와 너무 짧은 미리보기 노출이었다. 취소를 처리하고 사용자가 누르는 미리보기 유지 시간을 분리한 뒤 해당2개 모두 재검증 통과(1.2분). 최종 소스 연출10개 모두 통과(46.3초). 미해결 실패는 없다. 소스에 영향을 준 수정 후 관련 검사는 다시 확인한다.

클라우드 검사는 격리된 fixture에서 수행하며 운영 Supabase를 수정하거나 운영 함수의 현재 배포 SHA를 확인한 검사가 아니다.

모바일 새 검사는8대표 스킬·4화면 크기·실제 엔진 결과 불변·결과 전달1회·1배속에서2배속 전환·품질3단계 반복·상태 해제·중단·모든 활성 자원 정리를 확인한다. 연출 검사 전용 DOM harness와 실제 게임 UI 회귀 검사를 구분하며 기존 저장/보상/동기화 검사는 그대로 유지한다.

## 10. 한계

- 기존 도트 atlas의 포즈를 재사용한다. 새 원화/새 관절 애니메이션/상업 게임 영상 수준의 손그림 셀 애니메이션을 제작한 것은 아니다.
- 새 효과음은 추가하지 않았다. 이번 변경은 전투 시각 효과와 애니메이션이다.
- 외부6게임 영상·Rive 편집기 무료 조건은 확인하지 못했다. 선택한 실제 기술/라이선스는 위 조사 기록에서 구분한다.
- 모바일 실기기·장시간 발열·Safari 메모리·물리 GPU FPS는 미측정이다. 소프트웨어 GPU 수치로 실기기 목표 충족을 보장하지 않는다.
- 많은 적/다단일 때 풀 예산이 차면 부가 장식을 생략한다. 피해/상태/보상은 생략하지 않으며 핵심 숫자와 대상 선택은 유지한다.
