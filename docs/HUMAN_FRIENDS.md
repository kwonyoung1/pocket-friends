# 남자아이·여자아이 특별 친구

기준 main: `2334f8f` (생활·탐험 확장 PR #5 병합). 기존 게임에 두 친구를 **추가**하며, 기존 동물을 교체하지 않습니다.

## 이미지 처리 결과와 한계

첨부 자료는 여러 방향의 동작 시트가 아니라 **두 사람이 함께 앉아 웃는 한 장의 그림**입니다. 팔·다리·옷 일부가 겹치므로 두 사람을 픽셀 그대로 완벽하게 잘라내는 것은 불가능합니다.

이미지 편집 도구로 축제 배경과 주변 물체를 제거하고, 겹쳐 가려졌던 작은 옷·다리 윤곽을 보완하여 두 개의 독립 투명 PNG로 재구성했습니다. 짧은 갈색 머리/회색 니트와 긴 갈색 머리·앞머리/검은 재킷, 청바지·흰 운동화를 유지했습니다. **원본에서 추출한 11개 동작 이미지가 있다고 주장하지 않습니다.** 얼굴 세부 선과 가려졌던 윤곽은 이미지 편집 결과이므로 원본 픽셀과 완전히 같지는 않습니다.

| 요청 모습 | 실제 제공 |
| --- | --- |
| 기본·앉기·웃기 | 각 캐릭터의 독립 앉은/웃는 PNG 한 장 |
| 정확한 정면·측면·후면 | 원본에 없어 추출하지 못함. 측면/후면으로 위장한 이미지를 만들지 않음 |
| 걷기 | 앉은 원화에 작은 상하 이동·기울임을 적용하는 CSS 대체 동작. 실제 다리 보행 프레임은 없음 |
| 쓰다듬기·행복·레벨업 | 원화 유지 + 작은 들썩임·하트·반짝임 |
| 놀람 | 원화 유지 + 짧은 기울임·느낌표. 별도 놀란 얼굴 이미지 없음 |
| 졸림·수면 | 원화 유지 + 느린 호흡·담요·달/zzz. 누운 수면 이미지 없음 |
| 놀이 | 원화 유지 + 좌우 움직임·작은 별 효과. 별도 놀이 포즈 없음 |

파일은 `src/assets/humans/boy.png`, `girl.png`이며 각각 1254×1254 RGBA PNG입니다. 게임은 같은 크기의 컨테이너, `object-fit: contain`, 공통 바닥 기준점을 사용합니다. 상태 전환 중 얼굴을 늘이거나 다른 얼굴로 바꾸지 않습니다. 정확한 방향별 걷기/후면/수면 원화가 나중에 제공되면 `HumanSprite`와 포즈 선택 함수를 통해 추가할 수 있습니다.

## 지급과 저장

- 고정 ID: `special-boy`, `special-girl`.
- 이름: 남자아이, 여자아이. 기존 **생활·입양 → 친구 생활 → 새 이름 → 이름 저장**을 사용합니다.
- 처음 게임에 들어오면 두 친구를 무료로 지급합니다. 같은 ID가 이미 있으면 기존 객체·이름·레벨·상태를 유지하며 새로 생성하지 않습니다.
- 일반 친구 한도는 기존대로 **8명**, 유료 입양 4종/10,000코인 규칙도 그대로입니다. 특별 친구는 별도여서 전체 최대 **10명**입니다. 햄스터는 기존 별도 한도를 유지합니다.
- 기존 지갑·재고·구매 이력·사진·추억·도감·진행 중 탐험 결과에 비용이나 초기화를 적용하지 않습니다.
- 각자 먹이·교감·성장·개명·탐험·목욕·감기·수면·가구 방문을 사용할 수 있습니다. 좋아하는 음식은 남자아이=빵, 여자아이=케이크입니다.
- 각각 28개의 고유 한국어 대사가 있습니다. 일상·일반/특별 쓰다듬기·배고픔·수면·탐험 출발/귀환·교류를 구분합니다. 둘이 마주쳐도 서로 이름을 부르며 대화를 주고받습니다.
- 로컬 기존 원본은 추가 전 `pocket-friends-v1-before-humans` / IndexedDB `before-humans`에 보관합니다. 두 저장소 모두 백업할 수 없으면 자동 덮어쓰기를 멈춥니다.
- 클라우드는 기존 서버의 행 잠금·revision·UUID 영수증으로 지급합니다. PC/모바일이 동시에 요청하거나 같은 작업을 재시도해도 각각 한 명만 남습니다. 기존 로컬 원본은 클라우드 데이터로 덮어쓰지 않습니다.
- 새 저장 형식은 기존 `Save.version=2`에 선택 필드 `world.specialFriendsVersion=1`을 추가합니다. 구형/신형 저장 파일을 읽으며 친구 수 검증은 최대 10명으로 확장했습니다. 특별 친구가 등록된 뒤 옛 클라이언트가 쓰려고 하면 새로고침을 안내합니다.

## 이미 클라우드가 연결된 게임 업데이트

**프로젝트·비밀번호·API 키를 다시 만들지 않습니다. 이 기능을 위한 새 SQL은 없습니다.** 직전 생활 업데이트의 백업 SQL과 서버가 설치된 프로젝트를 그대로 사용합니다.

1. 현재 [게임](https://kwonyoung1.github.io/pocket-friends/) 맨 아래 **추억 보관**으로 JSON 파일을 내려받습니다.
2. [PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/special-human-friends?expand=1) → **Create pull request**. 검사 성공 후 **Merge pull request → Confirm merge**.
3. GitHub 상단 **Actions → Deploy cloud backend (manual) → Run workflow → Branch: main → Run workflow**. 서버 성공을 확인합니다. 새 친구 ID와 지급 명령을 인식하려면 서버도 꼭 갱신해야 합니다.
4. **Actions → Test and deploy Pocket Friends**에서 최신 main의 `build`, `deploy`가 초록색인지 확인합니다.
5. PC는 **Ctrl+Shift+R**, 모바일은 주소창 **새로고침**. 공유 월드에 들어오면 두 친구가 무료로 등록됩니다. 다른 기기에서 늦게 보이면 **새로 동기화**를 누릅니다.

서버가 옛 버전인 상태에서 새 화면만 배포하면 명령 오류나 새로고침 안내가 나올 수 있습니다. 데이터를 지우지 말고 3번 서버 배포를 완료하세요. 기존 기능의 클라우드 설정이 아직 끝나지 않은 경우 로컬 저장은 그대로 유지하며, 운영 동기화가 완료됐다고 표시하지 않습니다.

## 검증 범위

자동 검사는 지급 멱등성, 일반 8명+특별 2명, 예전 데이터/사진/지갑/진행 중 탐험 보존, 이름 변경, 각자 자율 이동·대사, 실제 PNG 투명 픽셀·가장자리 잘림 여부, 상태 선택, 터치/드래그, 새로고침 복원, 두 기기 동시 지급과 서버 권한을 검사합니다. 모바일 검사는 Chromium 터치 에뮬레이션이며 실제 iOS Safari/Android 기기 최종 확인은 배포 후 별도입니다. 실제 운영 월드의 데이터는 이번 작업에서 직접 수정하지 않았습니다.
