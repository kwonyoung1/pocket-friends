# 생활·탐험·새 식구 업데이트

기존 main `fd9def9`와 대규모 요청서를 대조했습니다. A단계 클라우드 연동과 기본 성장·경제·탐험은 있었지만 B~D단계의 장시간 목욕, 야간 수면, 개명, 가구 배치, 지역별 확률, 감기, 입양, 햄스터는 없었습니다. 이 브랜치에서 기존 코드에 추가했습니다. 기존 저장소와 Pages 주소를 유지합니다.

## 지금 사용 중인 게임을 업데이트하는 순서

이미 PC·모바일 연동을 완료했다면 **프로젝트 생성·API 키 등록·기존 데이터 가져오기를 다시 하지 않습니다.** 게임 데이터를 지우거나 새로운 월드를 만들지 마세요.

1. 현재 게임 [포켓프렌즈](https://kwonyoung1.github.io/pocket-friends/)에서 맨 아래 **추억 보관**을 눌러 JSON 파일을 내려받으세요. 게임 중간에 변경이 생기지 않도록 배포가 끝날 때까지 창을 잠시 닫아 주세요.
2. GitHub에서 [백업 설치 SQL](../supabase/migrations/202610150002_life_backup.sql)을 엽니다. 파일 오른쪽 위 **Copy raw file** 아이콘으로 전체 내용을 복사합니다.
3. [Supabase Dashboard](https://supabase.com/dashboard) → 기존 **pocket-friends** 프로젝트 → 왼쪽 **SQL Editor** → **New query** → 붙여넣기 → **Run**을 누릅니다. `Success. No rows returned`면 정상입니다. 이 SQL은 새 백업 테이블과 전용 저장 함수만 추가합니다. `game_worlds`를 비우지 않습니다. 이 새 SQL은 재실행해도 안전합니다. 최초 설치용 `202610150001_cloud_world.sql`은 다시 실행하지 않습니다.
4. [변경사항 비교/PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/life-exploration-expansion?expand=1) → **Create pull request**를 누릅니다. 제목은 `생활·탐험·가구·새 식구 확장 및 기존 데이터 보존`으로 입력하면 됩니다. 자동 검사들이 초록색인지 확인합니다.
5. PR에서 **Merge pull request** → **Confirm merge**를 누릅니다. 초안이면 먼저 **Ready for review**를 누릅니다.
6. 저장소 상단 **Actions** → 왼쪽 **Deploy cloud backend (manual)** → **Run workflow** → Branch **main** → 초록색 **Run workflow**를 누릅니다. 완료 화면의 `deploy-backend`가 초록색인지 확인합니다. 이전에 등록한 토큰이 만료됐다면 `SUPABASE_ACCESS_TOKEN`만 갱신합니다. URL/공개 키/게임 비밀번호는 그대로 둡니다.
7. **Actions** → **Test and deploy Pocket Friends**에서 최신 main 실행의 `build`, `deploy`가 모두 초록색인지 확인합니다. 필요하면 **Run workflow** → **main**으로 다시 실행합니다.
8. PC와 모바일에서 [게임 열기](https://kwonyoung1.github.io/pocket-friends/) → 새로고침합니다. PC는 **Ctrl+Shift+R**, 모바일은 주소창 옆 **새로고침**을 누릅니다. 기존 사진·코인·아이템을 확인한 뒤 **생활·입양** 메뉴가 보이는지 확인하세요.
9. PC에서 친구 이름을 바꿔 모바일에서도 반영되는지 확인하세요. 연동은 기존 Realtime/조회 주기를 사용합니다. 늦으면 게임 상단 **새로 동기화**를 누릅니다.

새 서버가 먼저 적용됐는데 옛 게임 탭이 열려 있으면 “게임이 업데이트되었어요. 새로고침…” 안내가 나올 수 있습니다. 데이터를 지우지 말고 새로고침하세요. “생활 업데이트용 SQL…” 오류라면 2~3번의 **새 SQL**을 실행한 뒤 **같은 작업 다시 시도**를 누르면 됩니다. 아직 최신 SQL이나 서버를 배포하지 않았다면 새 기능이 운영 게임에 반영된 상태는 아닙니다.

## 플레이 방법

### 음식·생활

- **상점 → 음식 → 구매하기**로 음식을 마련합니다. 친구 선택 → **먹이 주기** → **인벤토리**에서 줄 음식을 고릅니다. 무료 먹이는 없습니다. 기존 간식 `snack`, 도시락 `lunch`, 케이크 `cake` ID와 보유 수량은 유지됩니다. 효과와 판매 가격은 새 밸런스를 적용합니다.
- 사료 15코인/+10, 빵 30/+20, 과일 도시락 50/+35, 스테이크 100/+60, 특별 케이크 200/+80입니다. 좋아하는 음식을 먹으면 행복 +5와 전용 대사가 추가됩니다. 기존 먹이 보상 쿨타임도 유지합니다.
- 친구 선택 → **생활·입양 → 친구 생활 → 목욕 시작**. 현실 30분 동안 다른 행동을 쉬고 끝나면 청결 100, 행복 +4입니다. 친구별 하루 두 번이며 시작한 한국 날짜에 횟수를 소비합니다. 자정에 새 횟수가 생겨도 진행 중인 목욕을 중복 시작할 수 없습니다. 창을 닫아도 다음 접속에 한 번만 완료합니다.
- 친구마다 한국 시간 자정~오전 6시 부근의 고정 수면표를 사용합니다. 구체적인 시간은 생활 메뉴에 표시됩니다. 수면 중 자동 이동·자동 대사가 멈추며 가벼운 터치에는 졸린 반응을 보입니다. 사진 얼굴은 변형하지 않습니다. 오프라인 계산은 기존 상태 감소 상한과 같은 최대 8시간입니다.
- **새 이름**에 1~12글자를 입력하고 **이름 저장**. 첫 변경은 바로, 이후 실제 168시간 뒤 변경할 수 있습니다. 이전 이름도 기록합니다. 클라우드에서는 서버 시각을 사용합니다.

### 탐험·도감·가구

| 지역 | 레벨 | 기본 시간 | 일반 / 고급 / 희귀 / 전설 |
| --- | --- | --- | --- |
| 신비의 숲 | 1 | 30분 | 70 / 24 / 5.5 / 0.5% |
| 반짝이는 해변 | 5 | 60분 | 55 / 32 / 12 / 1% |
| 고대 동굴 | 10 | 120분 | 40 / 37 / 20 / 3% |
| 비밀의 정원 | 15 | 240분 | 25 / 40 / 29 / 6% |

활발형의 시간 감소·차분형의 체력 절약·모험가형의 XP 증가를 유지합니다. 호기심형의 8% 추가 아이템은 같은 지역 확률을 사용합니다. **감기 10%, 햄스터 0.5%, 특별 사건 추첨은 탐험 한 번마다 별도이며 추가 아이템 수와 무관합니다.** 출발 때 서버에서 결과를 고정하고 귀환 시 한 번 지급하므로 새로고침으로 바꿀 수 없습니다. 기존에 출발한 탐험은 원래 아이템·보상·귀환 시각 그대로입니다.

- 새 수집 가구 32종, 등급별 8종을 추가했습니다. 기존 보물 12종과 기존 장식품도 계속 보관·열람할 수 있습니다.
- **인벤토리 → 방에 배치하기 → 방 바닥을 톡 누르거나 끌기 → 여기에 놓기**. 확정 전에는 수량이 차감되지 않습니다. 가구와 겹치거나 길을 막는 위치는 거절합니다.
- 방 오른쪽 위 **가구 편집** → 가구 선택 → **이동하기 / 회수하기**. 편집 모드에서는 캐릭터 뒤의 가구도 선택할 수 있습니다. **편집 끝내기**로 돌아옵니다. 최대 18개입니다. 이동·회수는 물건을 새로 만들지 않습니다.
- 화분·쿠션·분수·조명·세계수·수족관 주변에 친구가 다가가 관찰하고 쉽니다. 장식 활동은 시각 연출이며 클라이언트에서 코인을 만들지 않습니다.
- **수집 도감**에서 등급/지역별로 찾고 최초 발견일·누적 수량·햄스터 기록을 봅니다. 판매하거나 회수해도 발견 이력은 남습니다. 새 발견은 반짝이는 알림으로 안내합니다.
- 감기에 걸리면 재채기하고 천천히 걸으며 탐험을 쉬고 회복 속도가 낮아집니다. **상점 → 치료 → 감기약 구매(100코인)**로 인벤토리에 보관합니다. 아픈 친구를 선택하고 **인벤토리 → 감기약 → 주기** 또는 **생활·입양 → 친구 생활 → 감기약 사용**으로 즉시 치료합니다. 건강할 때는 구매·차감하지 않습니다.

### 입양·햄스터

- **생활·입양 → 입양**에서 루루·토토·별이·뭉치를 각각 10,000코인에 한 번 맞이합니다. 기존 네 친구를 포함해 최대 8명입니다. 새로운 친구도 이름·성장·돌봄·교감·드래그·탐험·수면을 사용할 수 있습니다. 사진 교체는 기존 모모·비비 두 친구에게 유지합니다.
- **생활·입양 → 햄스터 → 방에 꺼내 주기**. 방에는 세 마리까지이며 추가로 발견한 햄스터는 인벤토리에서 안전하게 보관합니다. **인벤토리에서 쉬게 하기**로 회수합니다. 판매·폐기 기능은 없습니다.
- 햄스터는 작은 SVG 캐릭터로 돌아다니고, 멈춰 보거나 고개를 갸웃하고, 그루밍·간식·낮잠·짧은 따라가기를 반복합니다. 말풍선은 없습니다. 일반 친구들이 가끔 다가가 구경하고 말을 건넵니다.
- 모바일은 상태 패널을 접어 방을 넓게 보고, 친구 카드를 누르면 상태를 펼칩니다. 캐릭터·가구 조작 중에만 스크롤을 막으며 목록과 일반 페이지는 계속 스크롤됩니다. 화면 확대 후에도 실제 요소의 화면 좌표로 드래그 위치를 환산합니다.

## 데이터 보존과 서버 규칙

- 기존 `Save.version=2` 형식을 확장하고 `world.expansion.version=1`을 추가했습니다. 친구별 `life`와 월드별 가구·입양·동물·이벤트·알림 확인 기록은 선택 필드에서 시작합니다. 필드가 없는 기존 데이터는 기본값만 덧붙입니다. 코인 재지급이나 새 월드 생성은 하지 않습니다.
- 기존 네 ID, 사진, 이름, 상태, XP·성격, 지갑, 인벤토리, 장부, 출석·미션·업적, 도감, 진행 중 탐험의 고정 결과, 추억을 유지합니다. 유효성 검사를 통과하지 못하는 파일은 원본을 자동 덮어쓰지 않습니다.
- 로컬 저장의 원본은 업데이트 전 `pocket-friends-v1-before-life` / IndexedDB `before-life`에 한 번 보관합니다. 백업을 둘 다 저장할 수 없으면 자동 저장을 막습니다. 클라우드 접속 시 기존 기기 로컬 게임은 덮어쓰지 않습니다.
- 실제 클라우드의 첫 확장 저장은 `game_commit_expansion`이 원본을 `game_upgrade_backups`에 보관하고, 기존 UUID 영수증·revision 검사·행 잠금 저장을 같은 트랜잭션에서 실행합니다. 백업은 일반 브라우저 계정에서 읽거나 쓸 수 없습니다. 새 SQL이 없으면 새 저장 자체가 실패하므로 백업 없이 전환하지 않습니다.
- 클라우드의 구매·소비·탐험 추첨·목욕 횟수와 종료·입양·개명·가구 수량·질병 치료·보상은 서버에서 검증합니다. 클라이언트가 보내는 시각이나 보상 수치를 사용하지 않습니다. 전송 중 끊겨도 같은 작업 번호로 다시 시도합니다.
- 자율 산책·하트·그루밍 등의 매 프레임 연출은 각 화면에서 실행합니다. 캐릭터의 직접 놓기, 가구 배치, 동물 배치 여부와 육성 데이터는 서버 저장이며 다른 기기에 반영됩니다.
- 이전 클라이언트가 확장 데이터를 잘라 저장하지 못하도록 확장 이후 구형 요청에는 새로고침 안내를 반환합니다. 서비스 역할 키·게임 비밀번호는 프런트엔드에 넣지 않습니다.

설정은 `src/expansion/config.ts`(생활·입양·수면·확률·가구 크기), `src/progression/config.ts`(음식·레벨·경제), `src/balance.ts`(교감)에서 바꿉니다. 테스트 결과와 운영 검증 범위는 [검증 보고서](EXPANSION_VERIFICATION.md)에 기록합니다.
