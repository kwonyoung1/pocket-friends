# 사천성 정원: 탐험과 경쟁

기존 main(083ae2b)에는 사천성/테스트 HTML이 없어서 React 게임의 **사천성** 메뉴로 새로 추가했습니다. 캐릭터·사진·육성·코인·인벤토리·가구·햄스터·영단어·기존 탐험은 그대로 사용합니다.

## 탐험 규칙

| 단계 | 가로 × 세로 | 패 | 제한 | 완료 보상 |
|---|---|---|---|---|
| 1 | 6 × 3 | 18 | 60초 | 60코인 |
| 2 | 6 × 6 | 36 | 120초 | 150코인 |
| 3 | 8 × 8 | 64 | 180초 | 300코인 |
| 4 | 10 × 10 | 100 | 240초 | 500코인 |
| 5 | 12 × 10 | 120 | 300초 | 800코인 |

시작 성공 시 서버 시각으로 60분 쿨타임을 설정합니다. 공유 월드 전체가 하나의 탐험을 이어 하며 PC/모바일에서 현재 보드·단계·힌트·시간을 복원합니다. 진행 중 중복 시작은 금지하며, 완료 선택 화면이 남아 있으면 쿨타임이 끝나도 먼저 정산해야 합니다.

단계 완료 화면에서 **보상 받고 멈추기 / 다음 단계 도전하기**를 선택합니다. 5단계 완료 시 자동 정산합니다. 보상을 더하지 않고 마지막 완료 단계 금액만 한 번 지급합니다. 다음 단계 시간 초과·포기도 같은 보상을 유지합니다. 1단계 실패는 0코인입니다. 종료 전 확인창을 표시하고 종료 세션은 재사용할 수 없습니다.

창의 ✕는 메뉴만 닫고 게임은 유지합니다. 시간은 계속 흐릅니다. 브라우저가 닫혔을 때 별도의 예약 서버를 실행하지는 않습니다. 서버가 보관한 절대 종료 시각을 다음 정상 명령에서 확인하여 자동 정산합니다. 사천성 화면을 다시 열면 만료 확인 명령을 자동 전송합니다. 서버가 지급을 완료하기 전에는 완료로 표시하지 않습니다.

## 연결·힌트·섞기

같은 그림을 직선 또는 최대 두 번 꺾어 연결합니다. 다른 패는 통과할 수 없으며 보드 외곽의 빈 테두리를 이용할 수 있습니다. 방향과 꺾은 횟수를 포함한 경로 탐색으로 판정합니다. 모든 단계와 두 모드에 같은 판정을 사용합니다.

서버가 쌍으로 만든 패를 전체 무작위 배치합니다. 높은 단계는 더 넓은 공간과 더 다양한 그림을 사용합니다. 인접한 고정 쌍만 배치하지 않습니다. 모든 패를 제거하면 클리어하고, 남은 패가 있는데 연결이 없으면 자동으로 섞습니다. 남아 있던 위치·그림별 개수를 유지하여 최대 24번 시도하며, 실패하면 기하학적으로 연결할 수 있는 두 자리에 동일 그림을 교환 배치합니다. 따라서 최소 한 쌍을 보장합니다.

자동 섞기는 수동 횟수를 차감하지 않습니다. 선택·힌트를 지우고 0.5초 동안 서버와 화면 양쪽에서 입력을 차단하며 안내와 애니메이션을 표시합니다. 수동 섞기에도 같은 보장 로직을 사용합니다. 힌트는 연결 가능한 한 쌍을 강조하고 제거하지 않습니다. 탐험은 단계별, 경쟁은 회차별 힌트 3회입니다. 원본 v3 코드가 없어 수동 섞기는 단계/회차별 **3회**로 설정했습니다. `src/sichuan/board.ts`의 `rules`에서 조정할 수 있습니다.

## 경쟁·공유 랭킹

8 × 8, 64개 패를 무제한 재시작할 수 있습니다. 탐험 쿨타임과 독립적이며 입장료·코인 보상·실패 제한시간이 없습니다. 마지막 유효한 연결 명령을 서버가 받은 시각에서 시간을 확정하므로 응답 대기·결과 화면 시간은 추가하지 않습니다. 서버에는 밀리초를 저장하고 화면은 `00:00.00`으로 표시합니다. 네트워크 지연은 서버가 명령을 수신할 때까지의 시간에 포함됩니다.

현재 Supabase 인증 사용자 ID를 선수 ID로 사용합니다. 닉네임(2~12자)은 표시용입니다. 클라이언트가 제시한 시간·선수 ID·코인은 사용하지 않습니다. 시작 보드와 모든 연결을 서버가 검증하며 완료된 세션만 공유 월드 JSON의 랭킹에 등록합니다. 기존 RLS와 인증된 Edge Function 경로를 사용하므로 별도 공개 쓰기 테이블은 없습니다. 선수별 가장 빠른 기록만 보관·표시하고, 동률은 먼저 완료한 순서로 정렬하여 TOP 5를 표시합니다. 힌트·자동 섞기 횟수도 결과에 표시하고 순위는 시간으로만 결정합니다. TOP 5에 진입하는 새 개인 최고 기록에 축하 효과를 표시합니다.

**현재 로그인은 기기별 익명 인증입니다.** 같은 브라우저에서 닉네임을 바꿔도 같은 선수지만, 별도로 익명 로그인한 PC와 휴대폰은 서로 다른 선수로 인식합니다. 공유 월드·탐험·랭킹 조회는 동기화됩니다. 한 사람이 여러 익명 계정을 만드는 것까지 차단하는 실명/계정 연결 기능은 이번에 추가하지 않았습니다. 개발용 로컬 연습 기록은 해당 브라우저에만 저장되며, 클라우드 처음 가져오기 시 공용 랭킹·사천성 보상 근거로 가져오지 않습니다. 기존 육성 데이터는 가져옵니다.

## 데이터 보호

기존 저장 키/버전과 Supabase 프로젝트를 유지하며 `world.sichuan`만 필요할 때 추가합니다. 기존 데이터에 이 필드가 없으면 정상적인 이전 버전으로 읽습니다. 비정상 사천성 데이터는 오류로 중단하고 기존 파일을 초기화하지 않습니다. 서버는 기존 트랜잭션/CAS/작업 영수증으로 보드 변경과 코인 지급을 함께 저장합니다. 회차 상태·턴 번호·세션 ID를 검증하여 빠른 중복 터치와 기기 간 경합을 차단합니다. 이미 정산된 회차의 보상은 다시 지급하지 않습니다.

클라이언트 프로토콜은 7입니다. 사천성을 시작한 월드에서는 이전 화면의 쓰기 요청을 거부하고 새로고침을 안내하여 새 데이터를 이전 화면이 덮어쓰지 못하게 합니다. 기존 백업과 SQL은 그대로 유지합니다. **이번 업데이트에서 새로 실행할 SQL은 없습니다.** 기존 클라우드 설치가 완료된 프로젝트가 전제입니다.

## 모바일

보드와 패에만 `touch-action:none`, 텍스트 선택·기본 길게 누르기 메뉴 방지를 적용합니다. 보드 밖 메뉴와 페이지의 스크롤은 유지합니다. 마우스/터치 공통 Pointer 입력과 진행 중 잠금으로 이중 제거를 막습니다. 12 × 10까지 가로폭 안에 반응형 배치하고, 가로·세로 화면에서 컨트롤과 겹치지 않게 별도 줄을 사용합니다. 큰 화면의 보드/하단 메뉴는 대화상자 내에서 스크롤할 수 있습니다. 실제 iOS Safari 하드웨어 검증은 수행하지 않았습니다.

## 배포: 버튼 누르는 순서

새 프로젝트·새 비밀번호·새 SQL을 만들 필요가 없습니다. 기존 설정을 유지하세요.

1. [PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/sichuan-modes?expand=1)를 열고 **Create pull request**를 누릅니다.
2. PR의 **Checks**가 모두 초록색이 되는지 확인합니다. 실패하면 병합하지 말고 오류 로그를 확인합니다.
3. 먼저 [서버 배포 화면](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml)을 엽니다. **Run workflow → Branch: feat/sichuan-modes → Run workflow**를 누릅니다. 이번에는 아직 병합 전이므로 **main이 아니라 이 기능 브랜치**를 선택합니다. 최신 실행의 `deploy-backend`가 초록색이 될 때까지 기다립니다.
4. [열린 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls)에서 이번 PR을 열고 **Merge pull request → Confirm merge**를 누릅니다.
5. 병합하면 웹 배포는 자동 시작됩니다. [웹 배포 화면](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)에서 최신 `main` 실행의 **build / deploy**가 모두 초록색인지 확인합니다. 자동 실행되었으면 Run workflow를 다시 누르지 않아도 됩니다.
6. [게임 열기](https://kwonyoung1.github.io/pocket-friends/)에서 새로고침한 뒤 **사천성**을 누릅니다. PC와 휴대폰 모두 새로고침하세요. 기존 월드 선택 화면에서는 **이 클라우드 월드 사용하기**를 누릅니다.

서버 배포 실패 시 기존 월드를 초기화하거나 다시 가져오지 마세요. 오류가 `edge_functions_secrets_write`라면 기존 배포용 토큰의 Edge Function Secrets 권한을 확인해야 합니다. 배포는 사용자 GitHub에서 위 과정을 마쳐야 반영되며 개발 환경 테스트 통과만으로 실제 서비스 배포를 완료한 것은 아닙니다.
