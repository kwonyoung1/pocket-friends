# 다중 거래 · 오답 노트 · 넓어진 거실

기준 main은 지난 업데이트가 병합된 `f8b5764`이며, 작업 브랜치는 `feat/bulk-trade-notebook-expanded-room`입니다. 기존 GitHub Pages 주소와 Supabase 프로젝트를 유지합니다. 운영 데이터에 직접 접속하거나 운영 배포를 실행하지 않았습니다.

## 구현한 기능

- **다중 구매:** 상점에서 구매하기 → 수량 선택창 → 직접 입력/+/−, 단가·총액·최대 수량·부족 코인 표시 → 구매 확정. 음식·약·장난감·장식 상품을 대상으로 하며 캐릭터 입양은 기존 단일 구매·인원 제한을 유지합니다. 구매1회 최대10,000개, 총 보유10,000,000개, 잔액 상한1조코인 범위에서 서버가 가격·정수 수량·잔액·레벨을 검증합니다.
- **일괄 판매:** 인벤토리 → 일괄 판매 → 체크박스로 여러 종류 선택 → 항목별 수량 입력/+/−/전부 판매 → 종류·총수량·예상 금액 → 확인창. 신규 판매 가능한 전설이 포함되면 별도 경고를 표시합니다. 판매 금지 전설·캐릭터·햄스터는 선택할 수 없습니다. 방에 배치한 가구 수량은 재고에 포함하지 않으므로 회수 후 판매합니다. 한 항목이라도 유효하지 않으면 전체를 취소합니다. 도감 기록은 유지합니다.
- **거래 보존:** 가격·재고는 서버에서 다시 계산합니다. 기존 행 잠금·버전 비교·고유 작업 ID로 더블 클릭, 여러 기기의 동시 입력, 응답 유실 후 재시도를 처리합니다. 한 거래에서 코인/여러 재고/거래 기록을 함께 저장합니다. 최근100건의 상세 거래와 기존 코인 기록을 보관합니다. 전부 판매는 구매1회 제한과 별개로 해당 재고 전체(최대 보유량1000만개)를 처리할 수 있습니다.
- **오답 노트:** 영어·품사·뜻·예문·횟수·최근 날짜를 목록으로 표시합니다. 일반 보상 탐험에서 직접 정답을 맞히면 힌트 사용 여부와 무관하게 해당 항목을 삭제하고 “오답노트에서 복습 완료!”를 표시합니다. 정답 보기·건너뛰기로는 삭제하지 않습니다. 삭제 후 다시 틀리면 재등록합니다.
- **수동 삭제:** 개별 삭제, 체크박스 선택 삭제, 전체 선택/해제, 선택 개수와 취소 가능한 확인창을 제공합니다. 여러 항목을 모두 삭제할 때는 추가 확인 체크가 필요합니다. 서버 저장 전 목록을 미리 지우지 않습니다. 삭제는 코인·점수·단어 데이터·출제 이력을 바꾸지 않습니다. 최근1000건의 삭제 시각·단어 ID·자동/수동 사유를 저장합니다.
- **별도 복습 게임 제거:** 시작 버튼·탭·신규 복습 요청을 제거했습니다. 이전 저장 파일의 `review` 기록은 호환성을 위한 비활성 보관 데이터로 유지하고 실행하거나 보상받지 않습니다. 오답 노트와 진행 중이던 정상 보상 탐험은 유지합니다.
- **문제 출제:** 난이도별10문제 중 최대2개를 오답 노트에서 무작위 선택하고 나머지는 일반 후보로 채웁니다. 오답이 부족하면 일반 후보를 늘립니다. 일반 후보는 미출제 우선, 직전 회차 우선 제외, 해당 후보 풀을 소진한 뒤 다시 출제합니다. 각 단계의 선택 결과도 섞어 시작 시30문제 전체를 확정·저장합니다. 중간 새로고침/다른 기기에서 다시 뽑지 않습니다. 비율은 `src/words/selection.ts`에서 조정합니다. 드물게 한 난이도의 거의 모든 단어가 오답 노트에 쌓여 일반 후보8개도 남지 않으면, 최대20% 규칙을 어기지 않고 오답 노트 정리를 안내합니다.
- **기존 규칙 유지:** 3×10문제, 다의어 허용 정답, 빈 답 무채점, 문제당 한 번 채점, 단계별 힌트3회, 정답 보기·넘기기, 최대300코인/오답당−10, 시작 후2시간 제한·6시간 복구, 서버 시각·서버 채점을 유지합니다.

## 단어 데이터: 실제 수량과 미완성 범위

| 난이도 | 기존 | 신규 고유 단어 | 현재 합계 | 이번 목표까지 남은 신규 수 |
|---|---:|---:|---:|---:|
| 중학교 |30|100|130|900|
| 고등학교 기본 |30|100|130|900|
| 고등학교 심화 |30|100|130|900|
| 합계 |90|300|390|2700|

**이번 목표인 난이도별 신규1000개를 모두 구축한 것은 아닙니다.** 철자·품사·한국어 허용 답·영어 예문을 직접 작성하고 검토한300개만 추가했습니다. 자동으로 수를 채우거나 철자 변형·동일 표제어를 새 단어로 세지 않았습니다. 기존90개의 ID·뜻·예문을 유지합니다. 추가 중 발견한 기존8개 중복은 새로운 고유 단어로 교체했으며, 최종390개의 표제어가 대소문자 정규화 후 모두 고유한지 검사합니다. `issue`의 문제/쟁점/발행하다/발행 등 다의어를 허용합니다.

자료는 프로젝트에서 직접 작성한 초기 학습 자료입니다. 외부 사전 예문/번역을 대량 복사하지 않았으며 공식 교육과정 목록·전문 사전 감수 자료라고 주장하지 않습니다. 난이도는 대략적인 학습 수준입니다. 남은2700개는 어휘·뜻·예문·수준 검수를 거쳐 추가할 별도 작업입니다. 화면에도 실제390개라고 표시합니다. 운영 화면 JS에는 전체 답안 은행을 포함하지 않고 채점/힌트를 서버에서 처리합니다.

## 실제 면적 1.5배인 방

이전 좌표계는1000×640, 기본 이동 바닥은 x50~950/y230~570이었습니다. 각 축에 `sqrt(1.5)`를 곱해 약1224.745×783.837로 확장합니다. 이동 바닥의 가로·세로도 각각 약1.225배가 됩니다. 기존 충돌 영역과 가구의 위치·영역을 같은 비율로 변환하므로 실제 이동 가능한 기본 바닥 면적은1.5배입니다. 화면만 확대하는 변경이 아닙니다.

캐릭터의 좌표상 크기(기본100×128)와 초당 이동 속도는 유지합니다. 기본 가구·배치 가구는 확장된 방 비율로 표시합니다. 목적지/경로 격자/가구 충돌/드래그 좌표 변환/햄스터 목적지를 새 범위로 변경합니다. PC와 모바일 모두 방 내부 카메라에서 스크롤할 수 있고 모바일은 최소560px의 방을 유지해 캐릭터가 지나치게 작아지지 않게 합니다. 캐릭터는 잡아서 이동하고, 빈 바닥에서는 방을 밀어 둘러볼 수 있습니다. 페이지 전체의 가로 스크롤은 만들지 않습니다. 가구 배치 중에는 방 아래의 방향 버튼으로 카메라를 이동할 수 있으며, 배치 확인·취소 버튼도 방 아래에 유지합니다.

기존 가구 위치는 상대 비율대로 한 번만 변환합니다. 벽/통로와 겹친 기존 좌표는 가까운 유효 위치로 조정하며 ID와 보유 수량은 유지합니다. 유효 위치가 없는 손상 배치는 원본을 삭제하는 대신 저장을 중단합니다. `world.roomVersion=1`로 반복 확대를 막습니다. 새로고침 후 좌표가 다시 커지지 않습니다.

## 저장·백업·호환성

기존 저장 버전2, 친구 ID, 사진, 이름·개명 제한, 레벨·경험치·친밀도, 코인, 재고, 도감, 확정 탐험 결과, 가구 배치 ID, 햄스터, 목욕·감기·수면, 쓰다듬기6시간·수동 휴식4시간, 로그인·RLS를 유지합니다.

로컬은 `pocket-friends-v1-before-room` 또는 IndexedDB의 `before-room`에 업데이트 전 원본을 보관하고, 모두 실패하면 자동 덮어쓰기를 중단합니다. 클라우드는 새 SQL의 비공개 `game_room_backups`에 첫 좌표 변환 커밋 직전 원본 JSON·revision을 한 번 보관합니다. 새 SQL 실행 자체로 월드를 수정하지 않습니다. 원본 백업과 데이터 변경은 같은 트랜잭션에서 처리하며 CAS 실패/오류 시 함께 롤백합니다.

클라이언트 프로토콜6입니다. 방 확장 규칙이 저장된 월드는 이전 화면의 쓰기 요청을 거절하고 새로고침을 안내합니다. 새 서버를 먼저 배포하고 화면을 나중에 배포합니다. 기존 데이터 다시 가져오기/월드 초기화는 필요하지 않습니다.

## 눌러서 이동하는 배포 순서

1. [현재 게임](https://kwonyoung1.github.io/pocket-friends/)에서 **추억 보관**을 눌러 현재 JSON을 내려받습니다. 사이트 데이터 삭제나 재가져오기는 하지 마세요.
2. [이번 추가 SQL 열기](https://github.com/kwonyoung1/pocket-friends/blob/feat/bulk-trade-notebook-expanded-room/supabase/migrations/202610160002_room_trade.sql) → 코드 오른쪽 **Copy raw file**(복사 아이콘) 또는 **Raw → Ctrl+A → Ctrl+C**로 전체 내용을 복사합니다.
3. [Supabase 열기](https://supabase.com/dashboard) → 기존 **pocket-friends** 프로젝트 → 왼쪽 **SQL Editor** → **New query** → 붙여넣기 → **Run**. `Success. No rows returned`가 나오면 완료입니다. 이번 새 SQL 한 개만 추가합니다. 기존 초기화 SQL은 다시 실행하지 않습니다. 지난 보물 업데이트의 SQL이 적용된 기존 프로젝트를 전제로 합니다.
4. [PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/bulk-trade-notebook-expanded-room?expand=1) → base **main**, compare **feat/bulk-trade-notebook-expanded-room** 확인 → **Create pull request** → 검사가 모두 초록색이 될 때까지 기다립니다. [PR 설명](WIDE_PR.md)을 사용할 수 있습니다.
5. [서버 배포](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml) → **Run workflow** → Branch에서 **feat/bulk-trade-notebook-expanded-room** 선택 → **Run workflow** → 맨 위 새 실행 → **deploy-backend** 초록색 확인. 기존 token·Project ref·비밀번호를 재사용하며 새 secret은 필요하지 않습니다.
6. [열린 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls) → 방금 만든 PR 내부 → **Merge pull request → Confirm merge**. 목록 화면에는 병합 버튼이 없습니다.
7. [화면 배포](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml) → 맨 위 **main**의 병합 실행 → **build·deploy** 모두 초록색 확인. 병합으로 자동 실행되므로 Run workflow를 다시 누르지 않아도 됩니다. 실행 자체가 없을 때만 Run workflow → main → Run workflow를 누릅니다.
8. [게임 열기](https://kwonyoung1.github.io/pocket-friends/) → PC **Ctrl+Shift+R**, 모바일 새로고침 → 기존 사진·친구·코인·아이템·진행 탐험·가구·햄스터를 확인합니다. 변환된 방 안에서 가구의 상대 위치가 유지되어야 합니다.

## 배포 후 확인 순서

- 상점에서 기본 사료 구매하기 → 수량10 입력 →150코인 계산 확인 → 구매 확정 → 인벤토리10개 증가/다른 기기에서 공유 확인.
- 인벤토리 → 일괄 판매 → 일반 보물과 판매 가능한 새 전설 선택 → 수량/금액/전설 경고 확인 → 먼저 취소하여 변화 없음 확인 → 다시 확인 후 한 번만 판매되는지 확인. 기존 판매 불가 전설은 선택 목록에 없어야 합니다.
- 영단어 메뉴에서390개 표시와 별도 복습 버튼 제거 확인 → 기존 오답 목록 확인 → 개별/선택 삭제를 먼저 취소 → 확인 후 다른 기기에 같은 목록인지 확인. 일반 탐험에서 오답 단어를 직접 맞히면 “오답노트에서 복습 완료!”와 삭제를 확인합니다.
- 현재 진행 중인 영단어 회차는 순서·점수·힌트·쿨타임이 유지되어야 합니다. 정상 회차는3스테이지30문제를 끝까지 진행하여 보상1회 지급을 확인합니다.
- 방의 빈 바닥을 밀거나 PC에서 스크롤해 새 영역을 둘러보고, 캐릭터 드래그·가구 배치·햄스터 이동을 확인합니다. 새로고침 후 가구가 다시 확대되거나 수량이 바뀌지 않아야 합니다.

단위·DB126개, 전체 브라우저82개, 클라우드26개와 빌드·서버 타입 검사가 통과했습니다. 검증 범위와 결과는 [검증 보고서](WIDE_VERIFICATION.md)를 확인하세요. 실제 운영 SQL·배포와 실제 iPhone/Android에서의 확인은 위 순서로 진행해야 합니다.
