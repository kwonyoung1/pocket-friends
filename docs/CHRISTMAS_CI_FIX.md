# 크리스마스 업데이트 CI 오류 수정

사용자 제공 CI: 210개 E2E 중 PC·모바일에서 같은 네 시나리오가 실패(총 8건).

## 원인과 수정

1. **상태 아이콘/대사**: 조용한 방은 아이콘과 말풍선을 동시에 표시하지 않지만, 기존 테스트는 둘을 동시에 찾고 `boundingBox()`로 위치를 비교했다. 이제 짧은 상태 이모션을 먼저 표시하고 일반 상태 대사는 잠시 숨긴다. 직접 행동 대사는 아이콘보다 우선한다. 테스트는 아이콘 → 말풍선 전환, 상태 순환, 회복 후 제거 및 패널의 전체 필요 상태를 검증한다.
2. **반영 지연**: 대기 방 렌더 간격 300ms 때문에 시뮬레이션에서 발생한 아이콘/레벨업이 같은 프레임에 보이지 않을 수 있었다. 대사·상태 이모션·교감 단계·레벨업의 표시 상태가 바뀌면 다음 RAF에서 바로 반영한다. 내용이 바뀌지 않은 조용한 대기에서는 낮은 갱신 빈도를 유지한다.
3. **레벨업 대사 손실**: 성장/돌보기 결과 큐를 자연 대사 우선순위 2.5로 처리해 30초 자연 대사 제한이 걸릴 수 있었고, 실패해도 `shift()`로 메시지를 지웠다. 확정된 행동 결과는 우선순위 4로 처리하며 표시가 수락된 뒤에만 큐에서 꺼낸다. 이전 행동 결과나 교감이 끝날 때까지 남은 결과는 보존한다. 경험치/코인 계산은 변경하지 않는다.
4. **놀이 버튼 갱신**: 1.5초 사용 쿨타임은 끝났지만 느린 방 렌더 때문에 버튼 문구가 ‘잠깐 쉬는 중’으로 남았다. 열린 메뉴가 가장 가까운 거래/사용/행동 쿨타임의 종료 시각에 한 번 갱신되도록 타이머를 둔다. 렌더할 때 이전 타이머를 해제하고 메뉴를 닫으면 정리한다. 별도 RAF/반복 타이머는 추가하지 않았다.

겨울 아트, 이동 빈도/속도/최대 2명 제한, 데이터 형식, 개인 사진, 가구 좌표, 보상 수치는 변경하지 않는다. 테스트 대기시간을 늘리거나 실패 시나리오를 건너뛰지 않았다.

## 배포

수정 커밋은 기존 `feat/christmas-quiet-room`에 추가한다. 기존 PR에 자동으로 반영되며 새 PR을 만들 필요 없다. 아직 PR이 없다면 [PR 생성 링크](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/christmas-quiet-room?expand=1)를 사용한다.

1. 기존 PR **Checks**에서 새 수정 커밋의 실행이 초록색이 되는지 확인한다. 이전 실패 실행의 Re-run은 새 커밋을 검사하지 않는다.
2. 공용 `game.ts` 수정이 포함되어 [Deploy cloud backend (manual)](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml) → **Run workflow → Branch: feat/christmas-quiet-room → Run workflow**. 가장 위의 새 실행에서 **deploy-backend / Success**를 확인한다.
3. PR에서 **Merge pull request → Confirm merge**.
4. [Test and deploy Pocket Friends](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)에서 해당 병합의 **main** 실행을 열고 **build·deploy 모두 초록색**을 확인한다. 자동 실행이 있으면 수동 중복 실행하지 않는다.
5. [게임](https://kwonyoung1.github.io/pocket-friends/) 새로고침. SQL 실행·월드 초기화·브라우저 저장 데이터 삭제는 필요 없다.

## 검증 결과

- 사용자 로그의 실패 8건 집중 실행: 8/8 통과. 같은 네 시나리오를 PC·모바일에서 각각 2회 반복: **16/16 통과**.
- 전체 단위 테스트: **537/537 통과**, 41개 파일. 새로운 회귀 2개는 자연 대사 직후 레벨업/돌보기 결과 큐와 교감 중 큐 보존을 확인하고 XP가 바뀌지 않는지도 검증한다.
- 모바일 클라우드 회귀 **3/3 통과**: 두 모바일 세션의 겨울 테마 저장·전환·재접속과 원본 보존, 보물 3매치 중 방 DOM 변경 0 및 동기화 유지.
- TypeScript/Vite build, 단어 데이터 및 이펙트 번들 분리 검사 통과. 기존 청크 크기 경고는 남아 있다.
- 전체 210개 E2E를 다시 실행하지 않고 해당 실패 범위 및 공통 저장·배경 정지 회귀만 확인했다. 실물 휴대폰/운영 데이터에 대한 쓰기는 수행하지 않았다.

## 추가: 동물 보행 테스트의 고정 관찰 구간 제거

후속 CI에서 197개 통과 후 `tests/animals.spec.ts`의 데스크톱 보행 검증만 실패했다. 기존 검증은 30초를 한 번 건너뛴 뒤 8초 동안 동물이 걷는다고 가정했다. 새 규칙은 최대 60초 휴식과 동시 2명 제한이므로, 그때 모든 동물이 쉬거나 두 사람이 슬롯을 쓰는 것이 정상일 수 있다.

- 해당 테스트에만 재현 가능한 난수 시드 42를 설정한다.
- 고정 시점 대신 동물의 실제 `data-moving` 상태를 관찰한다. 대기 구간은 가상 시계로 건너뛰고, 이동 중인 동물을 화면에 가져온 뒤 실제 RAF 프레임을 샘플링한다.
- 관찰은 최대 240단계 및 활성 보행 샘플 80회로 제한하며 전역 테스트 timeout은 늘리지 않는다.
- 기존 6회 이상 이동 샘플·5종 이상 보행 프레임 검증을 유지하고 **동일 동물이 실제로 20 월드 단위 이상 이동**했는지도 확인한다. 화면에 보이는 동물과 유효한 프레임 0–7만 집계한다. 사용자가 잡으면 프레임이 멈추는 검증도 유지한다.
- 게임 코드·이동 빈도·동시 이동 제한·원화·저장 데이터는 수정하지 않는다. 실패를 건너뛰거나 게임을 빨리 움직이게 만들지 않았다.

이번 추가 수정은 테스트/문서만 변경하므로 **이를 위한 서버 함수 재배포는 필요 없다**. 기존 PR의 새 커밋 Checks를 확인하고, 병합 후 자동 main 웹사이트 배포를 확인한다. 앞선 공용 게임 코드 변경을 아직 서버에 배포하지 않은 경우에는 위의 기존 배포 절차를 따른다.

추가 수정 검증: 보행 시나리오 PC·모바일 각각 4회, 총 8회 통과. 최종 동물 테스트 파일 전체 PC·모바일 6/6 통과(보행/잡기, 기존 데이터 보존, 화면 밖·백그라운드·reduced-motion 정지). TypeScript/Vite 및 번들 분리 검사 통과. 전체 210개 E2E는 반복하지 않았다.
