# 상태 자연 변화 밸런스 업데이트

기준: 최신 main `ef4c5ac`(PR #13 병합). 기능 브랜치: `feat/gentle-status-balance`.

## 1. 실제 변경 수치

| 상태 | 이전 시간당 | 변경 후 시간당 |
| --- | ---: | ---: |
| 포만감 | −27 | **−9** (1/3) |
| 체력 | −9.6 | **+8** (자연 감소 제거) |
| 청결도 | −18 | **−9** (1/2) |
| 기본 행복도 | −13.2 | **−6.6** (1/2) |
| 포만감 10 이하 행복도 추가 감소 | −7.2 | **−3.6** (1/2) |
| 청결도 10 이하 행복도 추가 감소 | −4.8 | **−2.4** (1/2) |
| 위 두 상태가 모두 10 이하일 때 총 행복도 감소 | −25.2 | **−12.6** |

포만감·청결도가 감소하다가 10을 통과하는 시간도 구분하여 행복도를 계산합니다. 자주 갱신할 때와 한 번에 오프라인 시간을 계산할 때 결과가 같도록 했습니다. 기존 30/10 이모션 기준, 이동 속도 조건, 행복 이모션 조건은 변경하지 않았습니다.

이전의 '자연 회복 2배' 요청은 **시간당 +8**로 대체됐습니다. +8에 추가 배율을 곱하지 않습니다.

## 2. 체력 회복 계산과 유지한 기능

자연 회복량 = **8 × 실제 경과 밀리초 ÷ 3,600,000**.

- 체력 40 → 15분 후 42, 30분 후 44, 1시간 후 48, 3시간 후 64.
- 체력 90 → 2시간 후 100. 모든 상태는 0~100입니다.
- 소수점은 계산·저장 중 유지하며 상태 패널에서만 정수로 표시합니다.
- 새 자연 변화는 접속 종료 후에도 실제 전체 경과시간을 반영합니다. 새 규칙에는 종전의 8시간 자연 변화 제한을 적용하지 않습니다.
- 자연 +8은 수면·목욕·탐험 중에도 적용합니다. 탐험 시작 시 체력 소모는 기존대로 별도 차감합니다.
- 음식 효과와 취향 배율, 수동 쉬게 하기 **+20 / 캐릭터별 4시간**, 쓰다듬기 효과 및 쿨타임은 그대로입니다.
- 목욕은 **30분 진행 / 캐릭터별 하루 4번 / KST 자정 횟수 갱신**, 완료 시 청결 100·행복 +4로 유지합니다. 목욕 완료 이후 시간에만 새 청결 감소율을 적용합니다. 별도의 추가 30분 대기 시간을 만들지 않았습니다.
- 야간 수면 추가 회복 **+12/시간**, 감기일 때 **+6/시간**을 유지합니다. 일반 체력 감소를 상쇄하던 **+9.6/시간 보정**은 새 규칙에서 제거합니다. 따라서 정상 수면 중 합계는 자연 +8 + 수면 +12 = **+20/시간**, 감기는 **+14/시간**입니다.
- 기존 수면 시간표, 목욕·탐험 시간의 수면 추가 회복 제외, 수면 보너스의 기존 최대 8시간 정산 범위는 유지합니다.
- 기존 캐릭터·이름·사진·성장·친밀도·코인·재고·도감·가구·탐험·사천성·단어·오답노트 데이터는 유지합니다.

## 3. 시간 계산을 한 경로로 통합

`settleLife`에서 상태 자연 변화·수면·목욕 완료를 함께 정산하고, 저장의 마지막 시각과 캐릭터별 마지막 정산 시각을 갱신합니다. 프레임별 이동 함수에서 상태를 다시 깎거나, 복귀 이벤트에서 같은 시간을 별도로 더하지 않습니다.

운영 클라우드 상태는 서버가 계산합니다. 명령을 보낼 때마다 미정산 시간만 처리하고, PC·모바일 동시 요청은 기존 DB의 revision/CAS와 작업 번호 영수증으로 보호합니다. 다른 기기가 먼저 정산하면 뒤 요청은 최신 저장을 다시 읽어 남은 시간만 처리합니다.

입장할 때와 브라우저로 돌아올 때 정산 요청을 보내며, 접속 중에는 기존 30초 간격 정산을 유지합니다. 확인용 읽기는 기존대로 5초 주기입니다. 화면 수치는 서버 응답에 따라 갱신되지만 계산은 30초 정액이나 1시간 정액이 아닌 실제 경과시간에 비례합니다.

정기 정산을 시작하는 클라이언트 타이머도 `Date.now` 대신 단조 시계 `performance.now`를 사용합니다. 기기 날짜를 과거로 바꿔도 정기 정산이 멈추지 않습니다. 상태값·경과시간을 클라이언트 명령에 끼워 넣어도 서버는 자체 시간을 사용합니다. 개발용 로컬 모드는 기존처럼 기기 시각을 사용하며 운영 공유 월드의 서버 검증을 대신하지 않습니다.

## 4. 기존 저장 전환 — 추가 SQL 없음

**기존 Supabase 프로젝트와 기존 테이블·RPC를 그대로 사용합니다. 추가 SQL, 새 프로젝트, 새 비밀번호나 토큰이 필요하지 않습니다.**

- 기존 공유 월드는 새 서버에서 **처음 성공한 정산 시점**에 전환합니다.
- 업데이트 전 저장에서 그 전환 시점까지의 미정산 시간은 **기존 규칙으로 한 번만 처리**합니다. 기존 오프라인 최대 8시간 정책도 이 전환 정산에는 유지합니다.
- 전환 시각과 밸런스 버전을 저장하고, 그 뒤의 경과시간부터 새 −9/+8/−9/−6.6 규칙을 적용합니다.
- 예: 체력 80의 이전 저장이 낮에 1시간 묵어 있었다면 첫 전환 때 기존 규칙으로 70.4가 되고, 전환 후 1시간은 새 규칙으로 78.4가 됩니다. 이전 시간 전체에 +8을 소급해 올리지 않습니다.
- 새 게임은 생성 시점부터 새 규칙을 사용합니다.
- 기존 로컬 저장은 변경 전 원본을 자동 백업한 후 전환합니다. 저장 공간 부족으로 백업할 수 없으면 자동 덮어쓰기를 중단합니다.
- 최초 클라우드 가져오기는 브라우저에서 미리 시간 계산한 결과가 아니라 원본 데이터를 서버에 보내고, 최종 정산 시각을 서버 시각으로 설정합니다.
- 클라이언트 버전 10을 사용합니다. 전환된 월드에는 이전 화면의 쓰기를 차단하고 새로고침을 안내합니다.

첫 적용 때 숫자가 움직일 수 있는 것은 위의 기존 미정산 시간을 처리하기 때문이며, 캐릭터를 기본값으로 초기화하는 동작은 없습니다.

## 5. GitHub에 적용하는 순서

### A. Pull Request 만들고 검사 확인

1. [이번 브랜치 PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/gentle-status-balance?expand=1)를 엽니다.
2. 위쪽 **base: main**, **compare: feat/gentle-status-balance**를 확인합니다.
3. 초록색 **Create pull request**를 누르고, 작성 화면에서도 **Create pull request**를 누릅니다.
4. 이미 만들었다면 [Pull requests 목록](https://github.com/kwonyoung1/pocket-friends/pulls)에서 해당 PR을 엽니다. 같은 PR을 중복 생성하지 않습니다.
5. 아래 검사 표시가 초록색이 될 때까지 기다립니다. 노란색 `In progress`는 진행 중입니다. 빨간 ×이면 해당 `build` 검사에서 실패한 단계를 확인합니다.

### B. 새 서버를 기능 브랜치로 배포

1. [Deploy cloud backend (manual) 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml).
2. 오른쪽 **Run workflow**를 누릅니다.
3. 펼쳐진 창에서 **Branch: feat/gentle-status-balance**를 선택합니다. 아직 병합 전이므로 이 단계에서는 main이 아닙니다.
4. 창 안의 초록색 **Run workflow**를 한 번 누릅니다.
5. 맨 위 새 실행 제목을 열어 **deploy-backend**가 초록색 ✓, **Success**인지 확인합니다.

이 워크플로는 +8 회복 등 실제 상태 계산을 하는 서버를 배포합니다. 서버를 배포한 뒤 이전 화면에 새로고침 안내가 잠시 나올 수 있으므로 아래 웹 배포까지 이어서 완료합니다.

### C. PR을 main에 합치기

1. [Pull requests 목록](https://github.com/kwonyoung1/pocket-friends/pulls)에서 이번 PR을 엽니다.
2. **Conversation** 탭 아래로 내려 검사 통과를 확인합니다.
3. **Merge pull request → Confirm merge**를 누릅니다.
4. 보라색 **Merged**를 확인합니다.

### D. 게임 웹 화면 배포 확인

1. [Test and deploy Pocket Friends 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml).
2. 최신 **Merge pull request …**, 브랜치 **main** 실행을 엽니다.
3. **build와 deploy가 모두 초록색 ✓**인지 확인합니다. 병합으로 자동 실행되므로 이미 진행 중이라면 Run workflow를 다시 누르지 않습니다.
4. 자동 실행이 없는 경우에만 **Run workflow → Branch: main → Run workflow**를 한 번 실행합니다.

이 워크플로는 검사를 실행하고 게임 웹 화면을 배포합니다. 서버 배포의 Success만으로 웹 화면까지 배포된 것은 아닙니다.

### E. PC·모바일 확인

1. [포켓프렌즈 게임 열기](https://kwonyoung1.github.io/pocket-friends/).
2. PC는 **Ctrl+Shift+R**, 휴대폰은 브라우저 **새로고침**을 합니다.
3. 기존 비밀번호로 입장하고 **이 클라우드 월드 사용하기**를 누릅니다. 기존 월드가 있으므로 새 공유 월드를 생성할 필요가 없습니다.
4. 기존 이름·사진·코인·아이템·가구가 유지되는지 확인합니다.
5. 야간 수면이나 음식·휴식 없이 낮 시간의 같은 캐릭터 체력을 비교합니다. 15분 동안 +2, 30분 +4가 기준이며, 수면 중에는 별도 수면 보너스가 더해집니다.
6. 같은 월드를 PC·휴대폰으로 함께 열어도 +8이 +16으로 늘지 않는지 확인합니다. 상한 100과 화면 반올림 때문에 항상 정수 표시가 즉시 바뀌지는 않습니다.
