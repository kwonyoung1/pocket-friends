새 순수 로직·컨트롤러 검사는 다음을 확인합니다.

1. 4,999 / 5,000 / 5,000.001 / 5,001ms 콤보 경계. 정확히 5초까지 유지, 초과하면 중단.
2. 유효 교환에만 직접 콤보 +1과 시간 +5초, 무효/연쇄/중복 입력에는 추가 없음.
3. 모든 직접 배율·기존 자동 연쇄 배율·최종 ×8 상한·정수 점수·중복 제거 방지.
4. 계산·연출·자동 섞기·일시정지 시간 제외, 분수 시간 보존, 역방향 시간 방어, 잔여 0에서 부활/새 입력 방지.
5. 재시작·모드 전환·게임 종료 정리, 도전 최고/최근 기록과 새로고침 체크포인트 중복 방지.
6. 난이도 1~7의 색상·최소 두 유효 교환, 점수에 따른 정상 보드 보존과 단계별 상승, 특수 보석 유지.
7. 긴 연출 압축 전후 최종 보드·총 점수 동일, 표시 점수 역행 없음.
8. 기존 v1 스테이지 기록 유지, 여러 탭 최고값 병합, 이전 v1 탭의 저장 덮어쓰기에도 별도 도전 기록 유지, 저장 이벤트 재쓰기 루프 방지.
9. 4초마다 80회 성공하는 제어 입력을 포함해 **누적 판단 시간 5분을 지나도 강제 종료되지 않음**.
10. 최적화한 유효 교환 판정이 기존 전체 매치 판정과 여러 보드에서 일치.

브라우저 검사는 모드 선택·30초 시작·+5 이벤트·일시정지·시간 종료·직접 콤보 지속/해제·설정·기존 기록·뷰포트 밖 넘침 방지·모션 줄이기·백그라운드 자동 일시정지와 기존 드래그/터치/키보드를 확인합니다. 클라우드는 PC/모바일 두 브라우저에서 퍼즐 중 방의 렌더링이 멈춰도 동기화가 유지되고, 다른 기기의 구매를 종료 후 다시 읽으며 추가 보상이 없는지 확인합니다.

클라우드 검사는 격리된 테스트 인증·네트워크와 기존 서버 핸들러 경로를 사용합니다. 실제 사용자의 운영 Supabase 월드에는 테스트 데이터를 쓰지 않았습니다. 모바일은 iPhone 13 크기/터치 에뮬레이션이며 실제 iPhone Safari 실기기 검증은 아닙니다.

## 난이도 시뮬레이션

```bash
MATCH3_SAMPLES=20 node scripts/match3-v2-balance.mjs
```

5가지 반응 시간/오입력 가정 × 20개 고정 시드, 총 100판입니다. 실제 엔진과 시간 계산기를 사용하며 매 안정 보드에서 유효 교환이 최소 2개인지 검사합니다. 봇은 가능한 정답 목록을 알기 때문에 **사람의 탐색 시간·실제 승률을 측정한 실험이 아닙니다**. 아래 값은 입력 가능한 누적 판단 시간 기준입니다. 모델의 가정은 스크립트에 공개했습니다.

초기 높은 점수 문턱에서는 일반 모델 중앙값이 약 245초, 숙련 모델은 약 531초로 목표보다 길었습니다. 새 보충 보석만 후보 수에 맞추는 제한적 최적화와 낮춘 점수 문턱(1,500→23,000), 최소 3수 뒤 한 단계 상승을 적용해 조정했습니다. 이미 생성된 매치나 특수 보석은 지우지 않습니다.

| 모델 | 중앙 생존(판단 시간) | 최소~최대 | 5분 초과 / 20 |
| --- | ---: | ---: | ---: |
| 초보 가정 | 75.0초 | 35.0~105.0초 | 0 |
| 일반 가정 | 139.9초 | 93.0~228.4초 | 0 |
| 숙련 가정 | 228.6초 | 153.7~312.8초 | 1 |
| 매우 빠른 가정 | 896.1초 | 423.9~904.8초 | 20 |
| 매번 1초 만에 정답을 고르는 봇 | 900초 관측 상한 | 900초 | 20 |

900초 이후 관측을 멈추는 것은 **시뮬레이션의 측정 한도**이며 게임의 강제 종료 규칙이 아닙니다. 매우 빠른 모델 중 관측 한도에 도달한 판은 생존 중이므로 실제 종료 시간의 중앙값으로 해석하면 안 됩니다. +5초 고정 규칙상 평균 5초보다 빨리 성공하는 플레이어는 계속 생존할 수 있습니다. 실제 사람의 난이도 분포는 추가 플레이 테스트가 필요합니다.

동시에 다른 브라우저 검사를 돌리지 않은 재측정에서 엔진 계산 22,686회의 P95는 4.06ms, 최댓값은 23.45ms였습니다. 이는 순수 계산 시간이며 화면 프레임 간격이나 입력부터 표시까지의 전체 지연과는 다릅니다.

## 실제 연속 실행 측정

```bash
MATCH3_V2_SOAK=1 CI=1 npm run test:e2e -- tests/match3-v2-performance.spec.ts --workers=2
```

시간을 가속하지 않고 PC·모바일 각각 300초 이상 강한 효과의 도전 모드를 실행합니다. 실제 경과 시간, 교환 수, 콤보, 난이도, rAF 콜백 간격, 50ms 이상 긴 작업, GC 후 JS 힙, DOM 노드와 브라우저 오류를 수집합니다. 봇이 입력 가능한 즉시 정답을 고르므로 생존 기록의 판단 시간은 실제 5분보다 짧습니다. 5분 이후 강제 종료 부재는 별도 순수 시간/컨트롤러 검사로도 확인합니다.

측정 환경은 **개발 빌드의 독립 퍼즐 하네스·서버의 headless Chromium·에뮬레이션 뷰포트**입니다. rAF 빈도는 실제 물리 화면 FPS나 운영 Supabase 네트워크에서의 FPS를 보증하지 않습니다. 클라우드 격리와 복원은 별도 통합 검사 결과입니다. 유한한 측정으로 장기간 메모리 누수가 전혀 없다고 단정하지 않습니다.

| 화면 / 뷰포트 | 실제 시간 | 교환 / 직접 콤보 | 평균 rAF/초 | 간격 P95 | 50ms 이상 작업 / 최장 | DOM 전→후 | GC 후 힙 증가 |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| desktop / 1440×1100 | 300.05초 | 452 / 452 | 56.12 | 33.3ms | 12 / 136ms | 472→476 | 2.33MiB |
| mobile / 390×664 | 300.11초 | 456 / 456 | 58.18 | 16.8ms | 6 / 68ms | 472→482 | 2.43MiB |

두 화면 모두 난이도 7에서 종료 없이 진행했고 남은 시간은 30.0초, 브라우저 오류는 0개였습니다. 빠른 정답 봇의 누적 판단 시간은 PC 26.5초·모바일 24.9초이므로 위 실제 300초를 생존 기록 300초로 표시하지 않습니다. 강한 효과 상태에서 PC에는 최대 136ms, 모바일에는 최대 68ms의 긴 작업이 관측되어 모든 프레임이 완벽했다고 보고하지 않습니다. GC 후 힙 증가는 각 10MiB 한도 안이고 DOM 증가도 제한 안이었습니다.

## 보호 범위와 배포

기존 사천성·영단어·App·CloudGate·클라우드 클라이언트/서버/프로토콜·Supabase 함수/SQL·3매치 GameShell·GitHub Actions는 기준 main과 동일하게 유지합니다. 육성 데이터 마이그레이션·신규 테이블·서버 배포·외부 보상·추가 npm 의존성은 없습니다. 로컬 3매치 기록에만 필드를 추가하고 도전 기록 보관용 키를 추가합니다. 퍼즐은 별도 지연 로딩 청크(약 49KB JS, gzip 약 18KB)이며 측정 하네스는 운영 번들에 포함되지 않습니다. 기존 메인 번들의 500KB 초과 경고는 남지만 빌드는 통과합니다.

기본 CI는 시간이 긴 opt-in 실측 4개(v1 10분×2, v2 5분×2)를 의도적으로 생략합니다. v2 5분 실측은 위 명령으로 별도 실행합니다. [사용법](TREASURE_MATCH_V2.md) · [클릭별 배포 순서](TREASURE_MATCH_V2_DEPLOY.md)
