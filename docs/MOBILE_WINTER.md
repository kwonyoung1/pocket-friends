# 모바일 우선 · 겨울 테마 · 영이/찬미 산책 모션

## 범위와 실제 적용

브랜치: `feat/mobile-winter-walk`. 시작 시 최신 main은 `91c4153`이었습니다. 이전 동물/원화 작업이 미병합 상태라 새 브랜치에서 기존 작업 `b03a661`까지 이어받아 현재 동물·사람 외형을 보존했습니다. 이번 PR에는 그 미병합 작업도 포함됩니다.

이번 작업은 390px 세로 화면을 기준으로 실제 App, RoomArt, HumanSprite 렌더링에 적용했습니다. 별도 목업/실험 화면으로 대체하지 않았습니다. PC 전용 디자인·레이아웃 개선·성능 테스트·스크린샷을 추가하지 않았습니다. 기존 CI의 기능 회귀 범위는 유지하고 새 모바일 UI 검사는 desktop 프로젝트에서 제외했습니다. 향후 모바일 우선 원칙은 루트 [AGENTS.md](../AGENTS.md)에 기록했습니다.

## 겨울 테마

기존 기본·할로윈을 보존하고 선택 목록에 겨울을 추가했습니다. 사용자가 선택하기 전 기본값을 바꾸지 않습니다. 테마 값은 기존 `world.roomTheme` 구조로 저장/동기화됩니다. 새 저장 포맷이나 SQL 마이그레이션은 없습니다.

새 `src/assets/room/winter-watercolor.webp`는 실제 생성한 수채화 겨울 방입니다. 기존 방 구도·가구 위치를 기준으로 창밖의 눈 덮인 나무·지붕·하늘, 소파의 니트 담요·겨울 쿠션, 눈사람 장식·따뜻한 창가 조명·겨울 식물을 제작했습니다. 사용자가 배치한 가구·보물은 독립 요소와 기존 좌표·수량을 그대로 사용합니다.

`WinterDecor.tsx`는 눈송이를 **창문의 네 유리 영역을 합친 SVG clipPath 안에서만** 표시합니다. 기본 최대 8개, 친구가 8명 이상이거나 낮은 하드웨어 사양이 감지되면 4개, 감소 모션에서는 0개입니다. CSS transform/opacity를 사용하고 새 Pixi 렌더러나 날씨 API를 추가하지 않았습니다.

게임의 한국 시간 기준으로 아침(06~10시), 낮(10~17시), 저녁(17~21시), 밤(21~06시)의 창 색/따뜻한 조명을 조절합니다. 클라우드에서는 기존 서버 동기화 시계를 사용합니다. 장식의 시간 갱신은 분 단위이며 가시성/백그라운드 상태에 따라 중단합니다.

## 영이·찬미 원화와 움직임

기존 PNG, 얼굴·헤어·의상, 사용자 사진을 임의로 교체하지 않았습니다. 동물 원화·보행 코드·에셋도 이번 작업에서 변경하지 않았습니다.

처음 만든 매우 작은 보폭의 초안은 사용자의 추가 지시에 따라 제외했습니다. **보폭과 팔 스윙을 좀 더 살린 가벼운 산책**으로 두 사람의 이동 원화를 다시 생성했고, 각 8칸, 총 16개 실제 보행 그림을 추가했습니다. 무릎을 높이 들거나 뛰어다니는 기존 자세 대신 낮은 발 들기와 규칙적인 발 교대, 적당한 팔 스윙을 사용합니다. 얼굴을 CSS로 늘리거나 몸을 찌그러뜨리지 않습니다.

이전의 과장된 인상은 큰 보폭·무릎 들기 두 자세를 고정된 0.88초 간격으로 교대하던 방식과, 상위 생활/교감의 점프·기울기 효과가 겹칠 수 있던 구조에서 비롯됐습니다. 이번에는 실제 이동 거리로 프레임을 진행하고 사람에게만 과한 상위 효과를 억제합니다.

- 상태: idle, walk-start, walking, walk-stop, turning, resting, sleeping.
- 시작/종료 전환은 각각 200ms, 방향 전환은 180ms입니다. 정지·보행 그림의 위치와 크기를 맞추고 전환 시 아래로 튀지 않는지 검사했습니다.
- 실제 이동 거리 40 월드 단위당 8프레임. 제자리·드래그·감소 모션에서는 발이 진행하지 않습니다.
- 코드로 추가하는 몸통 상하 이동/기울기는 0입니다. 새 원화 자체의 작은 자세 변화가 보행을 표현합니다. 원화의 모든 픽셀을 각도/높이로 정밀 측정했다고 주장하지 않습니다.
- 대기 동작은 사람에게만 5~12초 간격의 작은 둘러보기·최대 1도 갸웃과 기존 눈 깜빡임·미세한 균일 호흡을 적용합니다. 반복 점프는 사용하지 않습니다.
- 동물과 같은 **공용 rAF 스케줄러**를 재사용하지만 동물 리깅/보행 상태를 사람에게 적용하지 않습니다. 프레임 변경마다 React setState를 하지 않습니다.
- 기존 정지/표정/수면 그림은 기존 경로를 유지합니다. 새 이동 이미지를 읽지 못하면 기존 모습이 남습니다. 부위별 자유 관절·독립 눈동자 리깅은 추가하지 않았습니다.

|파일|내용|
|---|---|
|`art-source/mobile-winter/winter-room.png`|새 겨울 배경 생성 원본|
|`art-source/mobile-winter/boy-walk.png`, `girl-walk.png`|최종 채택한 산책 원화 시트|

|같은 폴더의 `walk-atlas.webp`|2048×256 런타임 스트립, 각 8칸·256px 프레임|

출처는 image_gen을 사용한 새 AI 원화이며, 기존 자체 이미지로 외형과 구도를 참고했습니다. 원본에 없는 자세를 추출했다거나 인간 작가가 손으로 그렸다고 표시하지 않습니다. 외부 유료/무료 스톡과 신규 런타임 라이브러리는 포함하지 않았습니다. [출처·이용 조건](../art-source/mobile-winter/LICENSE.md)에 구체적으로 기록했습니다.

원본 시트 칸은 384×512입니다. 512px 검수용 칸으로 정렬하고 모바일 런타임만 256px로 축소했습니다. 보행 두 스트립 합계는 약 **198KiB**이며, 512px 런타임으로 만든 첫 버전 약 530KiB보다 줄었습니다. 비압축 RGBA 크기 계산상 두 스트립은 약 16→4MiB입니다. 실제 GPU 메모리 측정값은 아닙니다. 원본 PNG와 문서/영상은 게임 접속 시 자동으로 내려받지 않습니다. 겨울 배경도 선택 시 표시합니다.

## 모바일 사용성과 버튼 오류

360×800, 375×812, 390×844, 412×915에서 확인했습니다. 세로 화면의 여백을 줄이고 주요 메뉴/테마 버튼에 최소 44px 터치 영역, 입력·선택 항목 16px 글자, safe-area와 viewport-fit=cover/dvh를 반영했습니다. 고정된 상단 메뉴가 방을 덮지 않도록 모바일에서는 일반 문서 흐름으로 표시합니다. 돌보기 접기/펼치기는 유지합니다.

넓은 방 안을 움직여 보는 기존 카메라는 유지합니다. 모바일 페이지 전체의 가로 넘침을 막되 저장된 월드 좌표나 방 크기를 줄여 초기화하지 않습니다.

이전 클라우드 실패의 원인은 터치 환경에 남은 호버 위치 이동이었습니다. 실제 관측에서 보물 3매치 버튼의 y 좌표가 매 프레임 2px씩 번갈아 움직였습니다. coarse-pointer/hover:none 환경에서는 **translate와 transform 모두 위치를 바꾸지 않도록** 수정했습니다. 강제 클릭이나 타임아웃 확대로 숨기지 않았습니다. 원래 보물 3매치의 게임 규칙·보상·서버 로직은 변경하지 않았습니다.

## 검증과 한계

- 관련 단위 테스트 **67개 통과**: 사람 보행 상태, 거리 기반 프레임·드래그/보정 제외, 겨울 시간대, 테마 저장·기존 배치 호환성.
- 서버 테마 회귀 **1개 통과**: 서버 시각, 무료 변경, 이름/좌표/재화/인벤토리/장비/가구 보존. 해당 서버 파일의 다른 39개는 이번 범위에서 실행하지 않았습니다.
- 모바일 브라우저 관련 **22개 통과**, 핵심 2개는 최종 에셋/레이아웃으로 추가 재검증. 4가지 세로 크기·창밖 눈 제한·테마 복구·사진 크롭/복원·멀티터치/드래그·이름/수면/돌보기를 포함합니다.
- 모바일 클라우드 관련 **5개 통과**: 기존 할로윈/배치, 이전에 실패한 3매치 진입 3건, 겨울 두 기기 동기화/복원. 메뉴 위치 수정 후 stage 진입도 추가 통과했습니다. 운영 DB가 아닌 기존 테스트용 서버 핸들러에서 검증했습니다.
- 원화 16개 투명도·테두리 여백·크기·해시와 보행 인접 실루엣 차이 검사 통과.
- TypeScript/Vite 빌드, 영단어 데이터 제외·이펙트 실험실 격리·초기 거실 PixiJS/GSAP 제외 검사 통과.
- 실제 앱을 모바일 뷰포트에서 60초 실행해 두 사람의 0~7번 프레임을 관측했고 페이지 오류는 없었습니다. 이는 최종 텍스처 축소 전 기능 스모크 기록입니다. 최종 화면 영상은 축소된 런타임을 사용해 다시 촬영했습니다.
- 최종 텍스처의 별도 30초 GC 비교에서는 이벤트 리스너 312→303, DOM 노드 992→998, JS 힙 약 12.06→12.41MB였습니다. 초기 메모리 28MB 등 GC 전 표본만으로 누수를 판단하지 않았습니다. 활성 리스너가 중복 누적되는 징후는 관측되지 않았지만 장시간/모든 기기의 누수 부재를 보증하는 검사는 아닙니다.
- **실물 Android Chrome·iPhone Safari, 저사양 기기의 GPU/FPS/발열/배터리는 검증하지 못했습니다.** 터치 에뮬레이션을 사용했으며 PC 전용 검증은 하지 않았습니다.

## 병합·배포 — 이번에는 서버도 한 번 배포합니다

이번에는 서버가 winter 테마 값을 받아야 하므로 **게임 서버 함수 배포가 필요합니다.** 이전 동물 원화만 변경했던 업데이트와 다릅니다. Supabase 프로젝트나 테이블을 다시 만들지 마세요. SQL 실행·데이터 초기화는 필요 없습니다.

1. GitHub에 로그인하고 [이번 PR 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/mobile-winter-walk?expand=1)를 엽니다. **base: main**, **compare: feat/mobile-winter-walk**를 확인하고 **Create pull request**를 누릅니다. 이미 해당 PR이 있으면 그 PR을 엽니다.
2. PR **Checks**가 초록색이 될 때까지 기다립니다. 아직 노란색이면 기다리고, 실패하면 로그를 확인합니다.
3. 먼저 [Deploy cloud backend (manual)](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml)을 엽니다. **Run workflow → Branch: feat/mobile-winter-walk → Run workflow**를 한 번 실행합니다. 이 브랜치의 새 허용 규칙을 서버에 배포하는 단계입니다. **deploy-backend가 초록색**인지 확인합니다. 기존 프로젝트와 저장 데이터는 그대로 사용합니다.
4. PR로 돌아와 **Merge pull request → Confirm merge**를 누릅니다.
5. [Test and deploy Pocket Friends](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)를 엽니다. 병합 후 자동 실행되는 **main** 작업에서 **build·deploy 둘 다 초록색**인지 확인합니다. 자동 실행됐다면 Run workflow를 중복으로 누르지 않습니다. 자동 실행이 없을 때만 **Run workflow → main → Run workflow**를 한 번 실행합니다.
6. [게임 열기](https://kwonyoung1.github.io/pocket-friends/)에서 모바일 탭을 닫았다가 다시 열거나 새로고침하고, 방의 **방 테마 선택 → 겨울 테마**를 선택합니다. 동기화할 다른 휴대폰도 새로고침해 새 버전을 받습니다. 기존 사진·코인·캐릭터가 있는지 확인하되 사이트 데이터나 저장 공간을 삭제하지 마세요.

서버를 먼저 배포하면 이전 기본·할로윈도 계속 지원하면서 새 프런트엔드의 겨울 선택을 받을 준비가 됩니다. GitHub Actions는 서버에서 실행되므로 시작 후 PC를 꺼도 진행됩니다. 이 문서는 배포 방법이며, 아직 운영 배포를 수행했다고 표시하지 않습니다.
