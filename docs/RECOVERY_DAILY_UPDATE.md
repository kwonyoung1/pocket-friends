# 체력 음식·한국 시계·일일 랭킹·단어 확장

작업 기준: main `f601408` (PR #12까지 병합됨). 작업 브랜치: `feat/recovery-daily-ranking`.

## 이번 변경

- 기존 상점에 체력 음식 3종을 추가했습니다. 기존 수량 선택·다중 구매·인벤토리 사용을 그대로 사용합니다. 사용 1회에 1개를 소비하며 모든 상태값은 0~100입니다.

| 음식 | 가격 | 포만 | 행복 | 체력 |
| --- | ---: | ---: | ---: | ---: |
| 따뜻한 호박죽 | 120 | 35 | 5 | 15 |
| 꿀바나나 스무디 | 180 | 20 | 12 | 25 |
| 특제 보양 삼계탕 | 300 | 60 | 10 | 40 |

- 좋아하는 음식은 포만·행복·체력 모두 1.5배, 싫어하는 음식은 0.8배, 일반 음식은 1배입니다. 각 증가량은 반올림합니다. 기본 사료는 배율에서 제외합니다.
- 특별 친구 `special-boy`, `special-girl`은 같은 설정 객체를 참조합니다. 둘 다 무지개 마카롱을 좋아하고 치즈버거를 싫어합니다. 이름을 바꾸어도 유지하며, 이전 저장 데이터의 두 친구 취향만 교정합니다. 다른 친구 취향은 유지합니다.
- 직접 그린 파스텔 SVG 음식 일러스트를 추가했습니다.
- 한국 시간 시계를 방 상단 중앙에 추가했습니다. 맵을 밀어도 같은 자리에 있고 클릭·드래그를 가로채지 않습니다. 별도 memo 컴포넌트 내부에서만 1초 타이머를 실행합니다. 클라우드에서는 기존 서버 기준 단조 시계를 사용합니다.
- 경쟁 TOP 5는 서버가 확정한 클리어 시각의 KST 날짜로 나눕니다. 오늘 날짜·순위·닉네임·클리어 시간·자정까지 남은 시간을 표시합니다. 자정에는 화면을 다시 열 필요 없이 오늘 목록이 바뀝니다. 자정에 걸친 판은 완료 날짜에 들어갑니다.
- 기존 전체 최고 기록 `bests`를 유지하고 `dailyBests`를 추가합니다. 이전 저장에 남은 전체 최고 기록은 해당 기록 날짜로 옮겨 담아 보존하며, 없었던 과거 기록을 만들어 내지는 않습니다. 같은 사용자·같은 날짜에는 최고 기록 하나만 보관합니다. 전날 항목을 삭제하지 않습니다.
- 클라이언트 버전 9 및 선택적 월드 표식을 추가해 이전 화면의 쓰기가 새 규칙을 덮어쓰지 못하게 합니다. 새 화면으로 새로고침하면 기존 월드를 이어서 사용할 수 있습니다.

## 자연 체력 회복은 별도 확인 필요

최신 main에서 확인한 실제 수치는 다음과 같습니다.

| 구분 | 현재 수치 | 이번 처리 |
| --- | --- | --- |
| 낮 자연 회복 | 별도 양수 회복 로직 없음 | 새 회복량 선택 대기, 임의 추가하지 않음 |
| 일반 체력 감소 | 분당 0.16, 시간당 9.6 감소 | 유지 |
| 수동 쉬게 하기 | 체력 +20, 캐릭터별 4시간 쿨타임 | 유지 |
| 야간 수면 | 일반 감소 보정 9.6/시간 + 수면 회복 12/시간, 감기는 수면분 절반 | 유지 |
| 오프라인 경과 처리 | 기존 최대 8시간 정산 | 유지 |

따라서 “기존 자연 회복의 정확히 2배”를 구현했다고 보고하지 않습니다. 회복 기준이 0이므로 새로운 기준이 필요합니다. 채팅에 시간당 +24 / +12 / 현재 유지 선택을 요청해 두었습니다. 답변 전에는 기존 육성 정책을 보존합니다.

## 영단어 목표와 실제 수량

기존 단어 ID 390개를 유지하고 직접 작성한 300개를 추가했습니다. 예문·한국어 뜻·품사·정답·힌트가 있으며, 전체 난이도를 통틀어 표제어 중복이 없습니다.

| 난이도 | 기존 | 추가 | 현재 | 목표 | 부족 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 중학교 | 130 | 100 | 230 | 1,800 | 1,570 |
| 고등학교 기본 | 130 | 100 | 230 | 1,800 | 1,570 |
| 고등학교 심화 | 130 | 100 | 230 | 1,400 | 1,170 |
| 합계 | 390 | 300 | 690 | 5,000 | 4,310 |

**5,000개 목표는 미완료입니다.** 카운트만 채우는 중복·기계적 예문·출처 불명 사전 복사는 넣지 않았습니다. 공개 자료 후보에서 재사용 권한·한국어 대응·예문을 함께 확보하지 못하여 이번에는 직접 작성한 데이터를 반영했습니다. 난이도는 학습용 분류이며 공식 교육과정 인증은 아닙니다. 구조 검사와 대표 뜻 검사는 자동화했지만 외부 전문가의 690개 전수 감수를 받았다는 의미는 아닙니다.

원본: `data/words/recovery-expansion.tsv`. 생성: `node scripts/build-word-expansion.mjs`. 일치 검사: `node scripts/build-word-expansion.mjs --check`. 생성 파일: `src/words/recoveryRows.ts`.

기존 영단어 출제 이력·진행 중 회차·오답노트·수동/일괄 삭제·정답 시 자동 삭제·3단계 30문제·2시간 쿨타임·최대 300코인·힌트 3회는 유지합니다. 새로운 복습모드는 없습니다. 서버 전용 전체 정답 데이터는 배포용 브라우저 번들에 넣지 않습니다.

## 데이터와 Supabase

**새 Supabase 프로젝트, 새 비밀번호, 새 토큰, 추가 SQL이 필요하지 않습니다.** 기존 JSON 월드와 현재 RPC·권한 정책을 그대로 사용합니다. 기존 캐릭터·이름·사진·코인·아이템·가구·탐험·미니게임·오답노트를 초기화하는 코드를 추가하지 않았습니다. 이미 실행 중인 서비스의 실제 데이터에 테스트를 실행하거나 데이터를 재작성하지 않았습니다. 테스트는 격리된 저장 데이터와 PGlite 데이터베이스에서 수행합니다.

## 초보자용 적용 순서

이 안내의 두 Actions는 역할이 다릅니다. **Deploy cloud backend (manual)**은 음식 효과·취향·랭킹을 판정하는 서버를 바꾸고, **Test and deploy Pocket Friends**는 검사 후 실제 게임 웹 화면을 바꿉니다. 이번 변경에는 둘 다 필요합니다.

### 1. 변경사항을 합칠 요청 만들기

1. [PR 만들기 화면 열기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/recovery-daily-ranking?expand=1)를 누릅니다.
2. 위쪽 `base: main`, `compare: feat/recovery-daily-ranking`인지 확인합니다.
3. 초록색 **Create pull request**를 누릅니다. 다음 작성 화면에서도 **Create pull request**를 누릅니다.
4. 이미 PR을 만들었다면 [Pull requests 목록](https://github.com/kwonyoung1/pocket-friends/pulls)에서 해당 요청을 엽니다. 같은 PR을 또 만들 필요는 없습니다.
5. PR 아래 검사가 초록색이 될 때까지 기다립니다. `In progress`는 검사 중입니다. 빨간 ×면 `build`를 눌러 실패한 단계의 오류를 확인합니다.

### 2. 최신 기능 브랜치의 서버 배포하기

1. [서버 배포 화면 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml)를 누릅니다.
2. 오른쪽 **Run workflow**를 누릅니다.
3. 펼쳐진 창의 **Branch**에서 **feat/recovery-daily-ranking**을 선택합니다. 이 단계는 병합 전이므로 `main`을 선택하면 이번 서버 코드가 아닙니다.
4. 창 안의 초록색 **Run workflow**를 한 번 누릅니다.
5. 목록에 새로 생긴 맨 위 실행 제목을 누릅니다. `deploy-backend`에 초록색 ✓, 상태 **Success**가 나오면 서버 배포 완료입니다.
6. 이 브랜치를 이미 성공적으로 배포했고 이후 코드 변경이 없다면 다시 실행하지 않습니다.

이 단계에서 이전 화면에 새로고침 안내가 잠시 나올 수 있습니다. 다음 웹 배포까지 마친 뒤 새로고침하면 됩니다.

### 3. main에 합치기

1. [Pull requests 목록](https://github.com/kwonyoung1/pocket-friends/pulls)으로 돌아가 이번 PR을 엽니다.
2. **Conversation** 탭 맨 아래로 내립니다.
3. 검사 통과를 확인한 다음 **Merge pull request → Confirm merge**를 누릅니다.
4. 보라색 **Merged**가 표시되면 완료입니다. `Merge pull request`가 없고 `Open 0`이면 PR을 아직 안 만들었거나 이미 병합했을 수 있으므로 해당 PR의 상태를 먼저 확인합니다.

### 4. 실제 게임 화면 자동 배포 확인

1. [게임 웹 배포 화면 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml)를 누릅니다.
2. 맨 위 **Merge pull request …**, 브랜치 **main**인 새 실행을 엽니다.
3. `build`와 `deploy` 모두 초록색 ✓가 될 때까지 기다립니다. 병합하면 자동으로 실행되므로 이미 진행 중이면 **Run workflow를 또 누르지 않습니다.**
4. 자동 실행이 정말 없다면 오른쪽 **Run workflow → Branch: main → Run workflow**를 한 번만 실행합니다.
5. 서버 배포의 초록색만으로 웹 화면까지 바뀐 것은 아닙니다. 이 화면의 `deploy` 성공까지 확인합니다.

### 5. PC와 모바일에서 확인

1. [포켓프렌즈 열기](https://kwonyoung1.github.io/pocket-friends/)를 누릅니다.
2. PC는 **Ctrl+Shift+R**, 모바일은 브라우저 **새로고침**을 실행합니다.
3. 필요하면 기존 비밀번호로 들어가 **이 클라우드 월드 사용하기**를 누릅니다. 기존 데이터가 있는 상태에서 새 공유 월드를 만드는 절차는 진행하지 않습니다.
4. 기존 이름·사진·코인·가구가 유지되는지 먼저 확인합니다.
5. 방 위쪽 한국 시간 시계, 상점의 회복 음식 3종, 두 특별 친구의 음식 취향을 확인합니다.
6. 사천성에서 **오늘의 TOP 5**, 날짜와 다음 초기화까지 남은 시간이 보이는지 확인합니다. 전날 기록이 오늘 목록에서 빠지는 것은 정상이며 보존된 기록이 삭제된 것은 아닙니다.
7. 영단어 화면은 실제 수량 **690개**로 표시됩니다. 5,000개 완료로 표시하지 않습니다.

배포가 실패하면 재실행부터 반복하지 말고 실패한 빨간 단계를 열어 오류를 확인합니다. 이번 작업은 추가 SQL 입력이나 기존 저장소 초기화를 요구하지 않습니다.

현재 경쟁 참가자는 기존과 동일하게 인증 UID를 기준으로 구분합니다. 익명 로그인으로 접속한 PC와 휴대폰은 월드는 공유하지만 서로 다른 참가자 UID를 가질 수 있습니다. 닉네임만 같다고 하나의 계정으로 합치지는 않습니다.

검사 결과: 단위·서버 175개 통과, 화면 112개 시나리오 검증(전체 107개 통과 후 수정 대상 및 새 검사 10개 재검사 통과), 클라우드 36개 시나리오 검증(34개 통과 후 새 검사 2개 재검사 통과), 빌드·Deno 검사 통과. 단일 실행과 재검사 구분은 [검증 보고서](RECOVERY_DAILY_VERIFICATION.md)를 참고하세요.
