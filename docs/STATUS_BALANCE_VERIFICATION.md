## 초기 검사에서 변경한 기대값

처음 단위 검사에서 기존 규칙을 전제로 한 3개 기대값이 실패했습니다. 새 규칙에서도 같은 시간을 다시 적용하지 않는지 확인하는 의미는 유지하면서 다음과 같이 수정했습니다.

- 구데이터의 8시간 제한 검사는 구규칙 함수에 남겼습니다. 새 자연 회복은 실제 전체 시간으로 검사합니다.
- 목욕 후 1ms가 더 지나면 행복도 자연 감소가 아주 작게 발생하므로, '완전히 같은 숫자' 대신 정확한 1ms 감소를 검사합니다.
- 목욕 완료 뒤 2시간의 청결도 기대값은 새 반감 속도에 따라 64에서 82로 수정했습니다.

이후 단위 194개와 전체 화면 118개가 단일 실행에서 모두 통과했습니다. 실패한 검사를 삭제하거나 비활성화하지 않았습니다.

## 검증 범위

- Chromium 데스크톱과 iPhone 크기·터치 에뮬레이션을 사용했습니다. 실제 iOS Safari 기기에서의 검사는 수행하지 않았습니다.
- PGlite와 격리된 클라우드 서버 핸들러로 검증했습니다. 사용자가 Actions를 실행하기 전에는 운영 서버와 게임 화면에 배포됐다고 보고하지 않습니다.
- 빌드의 기존 큰 JS 청크 경고는 남아 있으며 빌드는 성공했습니다.
- 새 자연 변화는 전체 경과시간을 계산하지만, 기존 수면 추가 보너스의 최대 8시간 정산 범위는 유지합니다. 구규칙의 8시간 자연 변화 제한은 전환 전 구간에만 적용합니다.
