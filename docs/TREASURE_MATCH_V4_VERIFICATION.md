## 핵심 검증 범위

- 2,999 / 3,000 / 3,000.001 / 3,001ms 경계, 3초 초과 초기화, 매치당 직접 콤보/시간 한 번, 자동 연쇄와 무효 입력 제외, ×8 상한.
- 각 Lv.1~7의 시간 소모 배율, Lv.7 실제 5초=15초 차감, +5초는 배율 미적용, 다음 구간부터 새 배율 적용, 조작 불가능/백그라운드/일시정지 시간 제외.
- 최고 콤보·최장 실제 조작 가능 유지 시간·2콤보 이상 이어간 횟수·콤보 종료 후 최대값 유지.
- 요청한 200,000점·32콤보·65초=3,650코인과 모든 콤보 구간, 유지 보너스 최고 구간 하나만 적용.
- 실제 컨트롤러가 서버 발급 시드로 만든 기록을 같은 엔진으로 재생했을 때 최종 보드·점수·콤보·유지 시간·보상 일치.
- 서버 시작 번호 재시도 동일 세션, 짧은 간격 새 시작 제한, 교환/시각 조작·시간 종료 뒤 입력·다른 계정 세션·무인증·중도 종료/빈 기록 거절.
- 분할 재생 결과의 일치, 서버가 준 체크포인트만 사용, 입력 기록 변경 불가, 클라이언트가 덧붙인 최종 점수는 정산에 사용하지 않음.
- 최소 연출 시간·입력 순서·실제 시작/종료 서버 나이 검증. 가능한 게임의 재현을 확인하며 인간/봇 판별을 보장하지는 않음.
- PGlite에서 **실제 신규 SQL**을 실행해 동시/반복 정산 한 번만 지급, 지급 중 세션 업데이트 오류 시 코인까지 롤백, 권한 없는 직접 테이블/RPC 접근 거절, SQL 재실행 시 데이터 유지.
- 보상 지급 중 다른 월드 조작이 오래된 revision으로 도착하면 기존 game_commit에서 충돌 처리되어 새 코인을 덮어쓰지 않음. 코인 이외 월드 필드·사진/친구 데이터·holds 보존.
- PC/모바일 브라우저에서 서버 도전 시작→게임 중 새 보상 통신 없음→정상 종료→서버에서 지급 후 응답 유실→새로고침→동일 기록으로 확인→중복 지급 없음→거실 코인 갱신.
- 기존 스테이지 기록/설정·이전 버전 탭 대응·터치/키보드/드래그·유효 교환 최소 2개·긴 연쇄 후 입력 복귀.

PGlite는 PostgreSQL 호환의 격리된 로컬 DB입니다. 운영 Supabase 프로젝트와 실제 사용자의 월드에는 테스트 데이터를 쓰거나 신규 SQL을 적용하지 않았습니다. 보상 브라우저 테스트는 기존 인증/월드 서버 핸들러와 새 보상 서버 핸들러를 테스트 네트워크에 연결합니다. 원자성·RLS/RPC 권한은 별도 실제 SQL 테스트로 확인했습니다. 실제 iPhone Safari 검증을 했다고 표시하지 않습니다.

## 성능·난이도 재현 명령

```bash
MATCH3_SAMPLES=20 node scripts/match3-v4-balance.mjs
MATCH3_V4_SOAK=1 CI=1 npm run test:e2e -- tests/match3-v4-performance.spec.ts --workers=2
```

반응 시간/오입력 가정 5종 × 고정 시드 20개, 총 100판의 모델입니다. v4의 실제 난이도별 배율과 3초 콤보를 계산합니다. 실제 사람의 성공률/생존 시간 측정이 아닙니다. 관측 한도 900초는 시뮬레이션 한도이며 게임의 강제 종료 규칙이 아닙니다.

5분 실측은 실제 시계를 가속하지 않고 각 뷰포트에서 300초 이상 자동 플레이합니다. rAF 빈도·간격·긴 작업·GC 후 JS 힙·DOM·오류를 수집합니다. 가장 빠른 정답 봇이므로 실제 300초와 입력 가능 누적 생존 시간은 다릅니다. 독립 퍼즐 개발 하네스의 headless Chromium 결과이며 물리 화면 FPS·실제 iPhone Safari·운영 Supabase 네트워크 FPS를 보장하지 않습니다. 기존 방 렌더링 격리/복귀와 실제 보상 정산 경로는 별도 클라우드 통합 검사입니다.

## 보존·제약·배포

기존 `src/sichuan`, `src/words`, `src/cloud`와 `src/App.tsx`, 기존 `supabase/functions/game` 및 기존 마이그레이션 파일은 원본 main과 동일합니다. 기존 사천성 점수·명령·탐험/경쟁·랭킹·동기화는 수정하지 않습니다. 새 SQL은 별도 세션 테이블과 보상 함수만 추가하고 기존 월드를 초기화하지 않습니다. 지급 시 최신 월드 코인과 revision/updated_at만 갱신합니다.

스테이지/연습/중도 종료는 보상 없음, 정상 종료 성공 3~2,000회·12시간 이내만 정산, 요청 크기 450KB, 계정당 새 시작 10초 간격, 로컬 기록 소급 지급 없음이라는 운영 제한을 UI·사용법에 공개했습니다. 검증 실패/미배포 상태에서는 코인을 지급했다고 표시하지 않습니다. 이미 지급된 영수증은 12시간이 지나도 재확인할 수 있습니다.

앱 패키지는 추가하지 않았고 검증용 Deno 실행 도구만 별도 임시 캐시에 설치했습니다. 기존 메인 번들의 큰 청크 경고는 남지만 빌드는 성공합니다. 이번에는 신규 SQL + 신규 treasure 서버 + 웹사이트 배포가 필요하며 [클릭별 배포 안내](TREASURE_MATCH_V4_DEPLOY.md)를 따릅니다.
