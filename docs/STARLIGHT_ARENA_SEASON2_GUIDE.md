## 1. 시즌 2에서 달라지는 것

아레나 전용 모험가 8종을 추가합니다. 기존 일반 친구 10종과 환수 8종을 포함하여 등록 전투 데이터는 26종이며, 실제 편성에는 보유한 동료만 나옵니다. 모험가는 일반 육성방·탐험·가구 목록에 추가하지 않습니다.

첫 액티브는 모든 동료 Lv.20, 두 번째 액티브는 Lv.35입니다. Lv.10 패시브·Lv.40 마스터리·Lv.50 기존 필살기는 보존합니다. 아레나 성장과 일반 육성 성장은 분리합니다.

실제 이전 main은 일반 스테이지 50개이므로 이를 15개로 삭제하지 않습니다. 50개 ID·지역·적 배치는 유지하고 시즌 2 레벨·전투 XP 곡선을 다시 설정합니다. 크리스마스 이벤트는 별도입니다.

## 3. 캐릭터 획득 — 클릭 순서

1. [운영 게임](https://kwonyoung1.github.io/pocket-friends/)을 열고 기존 비밀번호·기존 공유 월드로 접속합니다. 새 월드를 만들거나 저장 데이터를 삭제하지 않습니다.
2. **별빛 아레나** → **정식 도전** → 해금한 스테이지 → **지역 이름으로 출발**을 누릅니다.
3. 서버가 승리를 검증하고 지급한 상자를 확인합니다.
4. **환수 도감 · 보물상자** → 상자 이름의 **확률 보기**를 눌러 환수·모험가 확률을 구분해서 확인합니다.
5. 해당 상자의 **개봉**을 누릅니다. 연출 중 **연출 건너뛰기**로 바로 결과를 볼 수 있습니다.
6. 결과의 **확인** → **별빛 모험가**를 누릅니다. 획득한 인물은 정상 색상, 미획득은 실루엣으로 표시됩니다.
7. 모험가 중복은 해당 인물 전용 조각으로 보존합니다. **모험가 조각 5 → XP 100**은 아레나 XP만 올립니다. 일반 육성에는 영향을 주지 않습니다. 모험가는 환수 성급 합성을 사용하지 않습니다.

## 4. 상자 기본 확률 — 합계는 각각 100%

환수 기존 등급별 기본 확률과 코인 지급액을 유지합니다. 모험가 기회는 일반 보상 확률에서 배분했으므로 일반 보상이 나올 빈도는 낮아집니다. 환수 획득 확률을 절반으로 나누는 방식이 아닙니다.

| 상자 | 일반 | 환수 희귀/영웅/전설/신화 | 모험가 희귀/영웅/전설/신화 |
| --- | ---: | --- | --- |
| 숲 | 70% | 20 / 0 / 0 / 0% | 8 / 2 / 0 / 0% |
| 호수 | 61% | 22 / 2 / 0 / 0% | 11 / 4 / 0 / 0% |
| 수정 | 50% | 25 / 5 / 0 / 0% | 14 / 6 / 0 / 0% |
| 고대 | 43% | 24 / 7.5 / 0.5 / 0% | 16 / 8 / 1 / 0% |
| 별빛 | 36% | 24 / 8.5 / 1.5 / 0% | 18 / 10 / 2 / 0% |
| 전설 | 30% | 24 / 8 / 2.7 / 0.3% | 20 / 11 / 3.7 / 0.3% |
| 크리스마스 | 20% | 22 / 11 / 6 / 1% | 22 / 11 / 6 / 1% |

동일 종류·등급 안에서는 인물별 균등 추첨합니다. 예를 들어 크리스마스 모험가 희귀 22%는 엘리·카이 각각 11%, 영웅 11%는 아리아·레온·세린 각각 약 3.6667%, 전설 6%는 시온·로제 각각 3%, 신화 1%는 루시안입니다.

기존 환수 천장 40회/300회는 유지되며 **환수**를 보장합니다. 모험가로 대체하지 않습니다. 해당 보장 회차에는 환수 해당 등급 100%로 화면에 표시되고 다른 결과는 0%가 됩니다. 모험가 별도 천장은 추가하지 않습니다. 모험가를 얻어도 기존 환수 천장이 상위 환수를 얻은 것으로 잘못 초기화되지 않습니다.

일반 보상 지급액과 일일 공용 코인 5,000 한도, 보유 상자 9,999 한도, 중복 조각 상한은 유지합니다. 전설/크리스마스 일반 코인 지급액은 각각 40/160입니다. 기존 코인 한도에 따른 강화석 대체·부분 지급 규칙도 유지합니다.

## 5. 도감·편성·레벨·주문서

1. **환수 도감 · 보물상자**에서 **일반 캐릭터**, **환수 도감**, **별빛 모험가**로 구분해 봅니다. 환수에만 기존 **환수 합성**을 사용합니다.
2. **파티 편성으로 돌아가기** → 보유 인물 카드를 누릅니다. 최대 5명, 중복 금지, 영이 또는 찬미 1명 필수입니다.
3. 기본 COST 10, 구매한 지휘력 +3, 실제 출전 아레나 Lv.40 리더 +1, 기존 천상의 지휘 인장 +1의 최대 15를 유지합니다. 구매·인장은 초기화하지 않습니다. 레벨 기반 리더 보너스는 아레나 Lv.40에 다시 적용됩니다.
4. **별빛 상점 → 경험치 주문서** → 대상 캐릭터 → 주문서·수량 → **주문서 구매**로 보관하거나 보유분을 **주문서 사용 → 확인하고 진행**합니다.
5. 주문서는 일반 캐릭터·환수·모험가 모두 **아레나 전용 XP**에 적용됩니다. 일반 육성 XP에는 적용하지 않습니다. 기존 주문서 재고·가격·XP 지급량은 유지합니다.
6. 성장 공식은 아레나 공통 `다음 레벨 XP = 20 + 8×현재 레벨`, 최고 Lv.50입니다. 훈련·스킬 강화는 이전 구매를 유지하되 잠긴 스킬은 해금될 때 효과를 사용합니다.
7. **스킬 · 해금 정보**에서 Lv.20/35를 확인합니다. 전투에서는 스킬을 누르면 대상 미리보기가 나오고 **선택한 스킬 사용**을 눌러 확정합니다.

## 6. 영이·찬미·기존 동료

영이 Lv.20 **별빛 지휘**는 아군 공격/행동을 지원하며 Lv.35 **별의 심판**은 3명과 주 대상 추가 타격입니다. 찬미 Lv.20 **포근한 치유**, Lv.35 **달빛의 기적**은 전원 회복·보호막·2턴 재생입니다. 기존 Lv.50 필살기와 구매한 스킬 강화 ID는 유지합니다.

일반 동료도 첫 액티브를 Lv.20으로 옮기고 Lv.35의 역할별 공격·회복·방어를 강화합니다. 환수 8종은 기존 외형·성급 배율·마스터리·속성 공명을 보존하면서 Lv.35를 다중 대상/연속 공격·해제·행동 지원·재생·반격 등으로 강화합니다. 신규 인간도 다른 환수의 공명 효과를 받지만 환수 공명의 발생원으로 잘못 등록하지 않습니다.

## 7. 범위·연속 공격·DOT

UI는 단일/2명/3명/전체, 회복·보호막, 타격 횟수와 지속 턴을 표시합니다. 적이 부족하면 살아 있는 고유 대상 수만 공격합니다. 루시안·영이의 추가 타격은 선택한 주 대상에만 적용합니다.

각 연속 타격은 보호막·HP·치명타 판정을 따로 처리하고, 실제 타격별 피해량을 별도 표시합니다. 연출의 후속 타격이 서버 피해를 다시 지급하지 않습니다.

화상·독·출혈은 해당 유닛 차례 시작에 피해가 발생합니다. 같은 종류는 한 개만 유지하고 새 효과는 강도/지속을 제한해 갱신합니다. 지속 최대 3턴, 종류별 차례당 최대 HP 12%(보스 3.5%)의 피해 상한, 빙결/기절 재제어 면역을 유지합니다. 남은 턴은 전투 HUD에 표시됩니다. 전투가 끝난 상태 이상은 다음 전투에 이어지지 않습니다.

**전투 속도**로 2배속, **전투 연출 설정**으로 이펙트 품질·짧은 컷인을 조절합니다. 낮은 성능/감소된 모션 환경에서는 이펙트를 줄입니다.

## 8. 초기화 범위와 복구 스냅샷

**시즌 2 배포 후 첫 인증된 아레나 접속 시 서버 전환 명령이 실행됩니다.** 이 게임은 하나의 공유 월드 안에 아레나 계정 기록을 보관하므로 기존 모든 아레나 계정에 한 번 적용합니다. 읽기 전용 건강 검사·로그인 전 운영 스모크 검사는 초기화를 실행하지 않습니다.

| 초기화 | 보존 |
| --- | --- |
| 일반 친구의 아레나 전용 Lv./XP를 1/0으로 생성 | 일반 육성·탐험 Lv./XP·친밀도·이름·ID·사진 |
| 환수·기존 모험가 Lv./XP를 1/0 | 환수·모험가 소유·성급·중복·조각·합성·마스터리 |
| 일반 스테이지 클리어·해금·최초 수령 상태 | 코인·보물·인벤토리·장비·강화·가구 |
| 시즌 2 진행 시작 | 상점 훈련·스킬 강화·COST 구매·주문서 재고·인장 |
| — | 기존 에너지 잔액·회복 시각·보유 상자·천장·이벤트 기록 |
| — | 계정·auth.users·회원 권한·사천성·3매치 기록 |

실제 테이블은 기존 `game_worlds`의 `id=home`, `data.world.arena` JSON이며 일반 성장은 `data.friends[*].growth`입니다. `game_members`, `auth.users`는 수정/삭제하지 않습니다. DB 테이블·컬럼 마이그레이션은 필요 없습니다.

전환 순서는 실제 서버가 로드한 기록의 계정·성장·클리어·최초 수령 건수 계산 → 초기화 대상의 `season1Archive` 복구 스냅샷 생성 → 아레나 대상만 초기화 → 크기·구조 검사 → 기존 PostgreSQL RPC의 CAS/영수증 트랜잭션 커밋입니다. 스냅샷과 초기화는 둘 다 저장되거나 둘 다 저장되지 않습니다. 서버 `season=2`가 있으면 재초기화하지 않습니다. 백업이 한도를 넘거나 검증이 실패하면 초기화를 커밋하지 않습니다.

복구 스냅샷은 서버에 남기며 대량의 과거 기록을 매번 다운로드하지 않도록 공개 동기화에서는 제외합니다. 클라이언트에는 `seasonReport` 집계만 보입니다. 기존 시즌 1의 유효 전투는 동결한 rules 1~4로 마칠 수 있고, 옛 클리어는 별도 정산 기록에 반영하므로 시즌 2 스테이지를 건너뛰지 않습니다. 옛 전투 정산도 원본 백업을 덮어쓰지 않습니다.

## 9. Supabase에서 전환 검증 — 읽기 전용

1. [Supabase 프로젝트 목록](https://supabase.com/dashboard/projects) → 기존 **pocket-friends** 프로젝트를 선택합니다. 새 프로젝트를 만들지 않습니다.
2. 왼쪽 **SQL Editor** → 새 쿼리를 엽니다.
3. 다음 **SELECT만** 실행합니다. 실제 운영 기록이므로 외부에 전체 데이터나 인증 값을 공유하지 않습니다.

```sql
select id, revision,
  data #>> '{world,arena,season}' as arena_season,
  data #> '{world,arena,seasonReport}' as transition_audit,
  (data #> '{world,arena,season1Archive}' is not null) as recovery_snapshot_exists
from public.game_worlds
where id = 'home';
```

4. 최초 아레나 접속 후 `arena_season=2`, `recovery_snapshot_exists=true`, 집계의 `accounts/friends/beasts/clears/firstRewards`를 확인합니다. 전환 전에는 미설정이 정상입니다. 집계는 실제 운영 전환 전 수치이며 테스트에서 사용한 수치와 다릅니다.
5. 필요하면 아래로 보존된 레벨·성급과 새 레벨을 읽습니다.

```sql
select a.key as arena_account, b.key as beast_id,
  b.value ->> 'level' as current_level,
  b.value ->> 'stars' as preserved_stars,
  w.data #> array['world','arena','season1Archive','accounts',a.key,'beastGrowth',b.key] as old_growth
from public.game_worlds w,
  lateral jsonb_each(coalesce(w.data #> '{world,arena,accounts}', '{}'::jsonb)) a,
  lateral jsonb_each(coalesce(a.value -> 'beasts', '{}'::jsonb)) b
where w.id = 'home';
```

레벨은 플레이·주문서 사용 후 이미 1보다 높을 수 있습니다. 다시 초기화해서 검증하지 않습니다. **테이블 삭제·전체 월드 교체·auth.users 삭제·공용 레벨 UPDATE를 실행하지 않습니다.** 복구가 필요하면 스냅샷을 보존하고 초기화 대상 필드만 전문가가 검토해 복구해야 합니다. 현재 전체 월드를 옛 백업으로 덮으면 새 코인·아이템을 잃을 수 있습니다.

## 10. 난이도·성장 곡선

일반 스테이지 1~15의 적 기준 레벨은 `1,1,2,5,7,10,14,17,20,23,26,29,32,35,35`입니다. 이후 기존 50개까지 이어집니다. 처음 세 스테이지는 무강화 Lv.1 기본 친구 파티로 검증합니다.

반복 XP는 `min(180,30+4×스테이지 인덱스)`, 최초 XP는 `min(240,60+6×인덱스)`이며 무료 전투 XP는 시즌 2에서 출전 인물별 하루 600까지입니다. 기존 코인 한도는 늘리지 않습니다. 주문서 XP와 조각 XP는 기존 보유 자산을 소비하는 별도 성장입니다. 초반은 무료 전투로 성장하고, 기존 탐험에서 모은 코인으로 주문서를 구입할 수도 있습니다.

## 11. PR 검사·명시적 보호 리뷰·병합

1. [이번 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls?q=is%3Apr+head%3Acodex%2Farena-season2) → 해당 PR을 클릭합니다.
2. **Approve workflows to run**이 실제로 보일 때 클릭하여 검사 실행을 허용합니다.
3. **Checks**에서 `unit`, `browser`, `cloud`, 필수 `build` 성공을 확인합니다. PR에서 운영 전용 `deploy/backend`가 Skipped인 것은 아직 배포가 아니라는 뜻입니다.
4. 이번 변경은 데이터 전환·보상·서버 코드라 기존 보호 정책상 명시적 리뷰·병합이 필요합니다. **Files changed → Submit review → Approve → Submit review**로 검토합니다. 본인이 PR 작성자이면 다른 권한 있는 리뷰어가 필요합니다.
5. 필수 검사와 리뷰가 완료되어 버튼이 활성화되면 **Merge pull request → Confirm merge**를 누릅니다. 보라색 **Merged**를 확인합니다. 기존 봇이 보호 변경을 자동으로 우회 병합하도록 바꾸지 않습니다.

## 12. 서버와 Pages 배포

1. [최신 main 실행 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Amain)을 엽니다.
2. **이번 PR 병합**으로 시작된 실행을 선택합니다. 이전 실행 재실행은 이전 코드일 수 있습니다.
3. `Waiting / release-approval`이 보이면 **Review deployments → release-approval 선택 → Approve and deploy**를 누릅니다.
4. **game Edge Function 배포가 필수**입니다. 배포 계획이 변경된 함수를 결정하며, 무관한 함수를 강제로 재배포하지 않습니다.
5. `backend / functions`, `backend-gate`, `deploy`의 성공을 확인합니다. `deploy` 안의 **Verify live HTML, exact commit and executable assets**, **Read-only live mobile boot check**가 성공해야 합니다.
6. [Pages 설정](https://github.com/kwonyoung1/pocket-friends/settings/pages)에서 사이트 주소를 확인합니다. 설정이 정상이라면 다시 바꾸지 않습니다.
7. [게임](https://kwonyoung1.github.io/pocket-friends/)을 새로고침 → 기존 월드 → **별빛 아레나**를 엽니다. 최초 전환 완료, 아레나 Lv.1, 일반 육성 원래 레벨, 보존된 재화·강화를 확인합니다. 운영 검증을 위해 임의 상자 지급이나 무료 재화 명령을 만들지 않습니다.

## 14. 디자인·전략 참고와 성능

[브라운더스트2](https://www.browndust2.com/)의 직업별 구분, [에픽세븐](https://epic7.onstove.com/)의 역할·상태 이상, [옥토패스](https://octopathtraveler2.square-enix-games.com/)의 도트/배경 조합과 약점, [스타레일](https://hsr.hoyoverse.com/)의 행동 순서와 기본/스킬 선택을 설계 원칙으로 참고합니다. 실제 전투 코드는 기존 포켓프렌즈 엔진을 재사용하며 상업 그래픽·UI·기술 이름을 복제하지 않습니다. 외부 사이트를 실시간 열람한 것으로 주장하지 않습니다.

새 원화·도트는 WebP/PNG로 최적화해 Pages 정적 자산으로 제공합니다. 전투는 실제 파티 스프라이트만 로딩하며 새 인물의 수만큼 Supabase 조회를 반복하지 않습니다. 복구 스냅샷을 일반 동기화에서 제외합니다. 모바일 세로 360×800/375×812/390×844/412×915와 터치 버튼·저성능 이펙트·2배속을 검증하며, 브라우저 에뮬레이션을 실기기 검증이라고 보고하지 않습니다.
