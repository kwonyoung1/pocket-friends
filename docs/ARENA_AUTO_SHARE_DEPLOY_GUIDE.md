# 아레나 자동 공유 — 클릭 안내서

같은 게임 접속 비밀번호로 로그인한 모든 기기가 환수·상자·에너지·클리어·진행 중인 전투를 공유합니다. 기기를 새로 등록하거나 연결 코드를 입력하지 않습니다. 서로 다른 사람도 같은 접속 비밀번호를 사용하면 같은 아레나를 사용합니다. 로그아웃한 기기는 다시 비밀번호로 로그인해야 하며, Supabase 인증·월드 회원 검증은 유지합니다.

## 1. 이번 PR과 검사 확인

1. [이번 브랜치 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls?q=is%3Apr+head%3Acodex%2Farena-shared-world)을 엽니다. `codex/arena-shared-world` → `main`인 PR을 누릅니다. 이미 병합한 #41이 아닌 이번 PR을 확인합니다.
2. **Checks**를 누릅니다. `unit`, `browser`, `cloud`, 필수 `build`가 성공해야 합니다. **Approve workflows to run**이 표시되는 경우에만 누릅니다.
3. 기존 자동 병합이 완료되면 **Merged**가 표시됩니다. **Approvals required**가 있으면 **Files changed → Submit review(또는 Review changes) → Approve → Submit review**로 최신 변경을 검토합니다. 작성자 본인 승인이 제한되면 권한 있는 다른 리뷰어가 필요합니다.
4. 검사·리뷰를 모두 통과했는데 수동 병합이 필요할 때만 **Merge pull request → Confirm merge**를 누릅니다. 기존 보호 정책·자동화 설정을 바꾸지 않습니다.

이번 변경은 서버의 아레나 공유 범위를 변경합니다. 저장소 [AGENTS.md](../AGENTS.md)의 “Security/auth, DB, secrets, economy, workflow changes ... required explicit review/production approval” 지침과 기존 자동화 정책의 검토·배포 승인을 유지합니다.

## 2. 서버와 웹 배포 확인

1. [main 배포 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Amain)을 누릅니다. 이번 병합 커밋의 최신 실행을 엽니다.
2. **Waiting / release-approval**이 표시되면 **Review deployments → release-approval 체크 → Approve and deploy**를 누릅니다. 지정된 리뷰어만 승인할 수 있습니다. 이미 진행 중이면 추가 버튼을 누르지 않습니다.
3. `plan`의 서버 배포 대상에서 `game`을 확인합니다. **backend / functions**, **backend-gate**, **deploy**와 배포된 SHA 검증이 성공해야 합니다. 서버 명령이 바뀌므로 웹만 배포해서는 완료가 아닙니다. `treasure`와 DB 테이블 구조는 바뀌지 않습니다.
4. `deploy`에서 **Verify live HTML, exact commit and executable assets**, **Read-only live mobile boot check** 성공을 확인합니다. 전체 실행이 초록색이어도 `deploy Skipped`이면 실제 웹 배포 여부를 따로 확인합니다.
5. [공개 버전 정보](https://kwonyoung1.github.io/pocket-friends/version.json)의 SHA가 이번 배포 커밋과 일치하는지 확인합니다. 기존 실행을 재실행하는 것으로 새 코드를 적용하지 않습니다.

## 3. 다른 기기에서 자동으로 이어하기

1. 기존 기기로 [포켓프렌즈](https://kwonyoung1.github.io/pocket-friends/)에 접속합니다. 평소 비밀번호로 로그인하고 **별빛 아레나**를 누릅니다. 기존 월드는 **이 클라우드 월드 사용하기**를 선택합니다. 새 월드를 만들거나 초기화하지 않습니다.
2. **환수 도감 · 보물상자**에서 **모든 기기 자동 공유** 안내를 확인합니다. 최초 전환 시 기존 진행 중인 전투의 계정을 우선 선택하며, 그 외에는 저장된 계정 ID 순서로 하나를 선택합니다. 보상·환수·에너지를 합산하지 않습니다.
3. 다른 기기에서 같은 게임 주소를 열고 같은 접속 비밀번호로 로그인합니다. **이 클라우드 월드 사용하기 → 별빛 아레나**를 누릅니다. 별도 코드를 입력하지 않습니다.
4. 환수·상자·에너지와 **전투 이어하기**가 동일하게 표시되는지 확인합니다. 온라인의 보이는 화면에서 다른 기기 변경은 기존 약 5초 주기 동기화로 반영됩니다. 숨긴 화면·오프라인에서는 복귀 후 다시 읽습니다. 무제한 실시간 동기화를 추가하지 않습니다.
5. 같은 전투를 두 기기에서 동시에 다르게 진행하면 서버가 이미 저장된 행동과 다른 기록을 거부할 수 있습니다. 최신 서버 기록으로 이어 하세요. 코인·상자 보상을 다시 지급하거나 에너지를 충전하지 않습니다.

## 4. 예전에 기기마다 따로 진행한 기록이 있는 경우

1. **환수 도감 · 보물상자 → 보존된 이전 아레나 기록**을 누릅니다. 기존 계정이 여러 개일 때만 표시됩니다.
2. **공유할 기존 아레나 기록**에서 환수·클리어·상자 수를 보고 기록을 고릅니다.
3. **이 기록을 모든 기기에서 사용**을 누릅니다. 모든 기기가 이 기록으로 바뀝니다. 선택하지 않은 기록과 진행 중인 전투도 그대로 보존합니다.
4. 같은 메뉴에서 다시 다른 기존 기록을 선택할 수 있습니다. 새 계정을 만들거나 에너지·보상·천장 횟수를 합산·초기화하지 않습니다.

## 5. 오류가 생기면

- **최신 화면으로 새로고침**: 옛 화면이 기기별 저장 방식으로 덮어쓰지 않도록 막은 것입니다. 새로고침하고 재입장합니다. 쿠키·저장 공간·계정을 지우지 않습니다.
- **다른 기기에서 공유 기록 변경**: 최신 기록을 확인하고 원래 의도한 기록에서 다시 조작합니다. 오래된 상자·육성 요청은 다른 기록에 적용하지 않습니다.
- 연결이 끊긴 미확인 작업: 기존 **같은 작업 다시 시도** 또는 로그인 화면의 **앞선 작업 결과 다시 확인**을 사용합니다. 원래 작업 번호를 유지합니다. 일반 구매·강화의 확인 절차도 유지합니다.
- 서버 배포 인증 실패: [cloud-backend 설정 목록](https://github.com/kwonyoung1/pocket-friends/settings/environments)에서 해당 환경과 실행 로그를 확인합니다. 이 업데이트 때문에 토큰을 새로 만들 필요는 없습니다. 실제 만료가 확인된 경우에만 [Supabase 토큰 페이지](https://supabase.com/dashboard/account/tokens)를 사용합니다. 토큰을 채팅에 보내지 않습니다.
- 운영 장애: [기존 승인형 롤백](https://github.com/kwonyoung1/pocket-friends/actions/workflows/rollback-pages.yml)을 사용하되 서버와 웹의 공유 방식 호환성도 확인해야 합니다. DB·기존 기록을 초기화하지 않습니다.

이미 정상인 GitHub Secrets·브랜치 보호·Supabase 프로젝트는 다시 설정하지 않습니다. [기존 자동화 설정 문서](../AUTO_DEPLOY_SETUP.md)는 실제 권한·설정 오류가 있을 때만 참고합니다. 로컬 통과, 원격 CI, 병합, 서버 배포, 웹 배포는 각각 별도로 확인합니다.
