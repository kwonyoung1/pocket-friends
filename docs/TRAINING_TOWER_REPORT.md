작성: 2026-11-27 KST. 기준 main `3a7faa6b6484c842aecef2fd1258f2456e51344d`, 작업 브랜치 `codex/starlight-training-tower`.

## 구현

- 별빛 아레나 안에 수련탑 진입·층 입력/±1/±10·최고/최근층·숙련 목록을 추가했다. 최고 클리어+1까지 해금하며 낮은 층 재도전, 입장 에너지0, 일일 시도 제한 없음, 기존 직접 스킬/별빛 조작을 유지한다. 테스트/측정 스크립트의 자동 선택은 운영 자동 전투 기능이 아니다.
- 1–10층1–2명, 11–20층2–3명, 21–30층3–4명, 31–50층4–5명, 51층 이후4–6명. 서버 시드로 조합·특성을 정하고 10층마다 보스 및 기존 고유 패턴을 재사용한다. 14지역의 그림·몬스터를 순환하지만 지역 순환이 능력치 난이도를 초기화하지 않는다.
- HP/ATK/DEF 성장 계수는 `100+8×(층−1)`%로 선형 증가한다. 총 HP·ATK 예산을 인원에 나눠 같은 층의 적 수 차이가 큰 난이도 편차를 만들지 않게 했다. 정상 참조 HP122/ATK18, 보스 HP470/ATK36에 해당 구간 평균 인원 예산을 적용한다. 고유 방어·회복·상태이상·약점·보스 전략은 유지한다. 새 전투가 서버의 성장 계수를 스냅샷으로 저장한다.
- 황금3%/수정5%/그림자2%는 상호 배타적인 전투별 추첨이다. 황금은 전용 이름/황금 tint와 XP보너스, 수정은 DEF×1.4와 기존 약점, 그림자는 ATK×1.15와 XP보너스다. 기존 원화/스프라이트/배경을 재사용했고 새 엔진·상업용 외부 그래픽을 추가하지 않았다.
- 한 전투당 일반/강공ATK+10%/철벽DEF+15%/신속속도+10%/생명력HP+15%/약점노출약점피해+10% 중 하나. 진행·시드·참가자 프로필은 티켓에 고정한다.
- 결과는 참가자별 XP/전후 숙련 레벨/성장률/최고층/누적 승리를 표시한다. 같은 층 재도전은 결과에서 바로 시작하며 다음 층·수련탑 복귀도 제공한다.

## 숙련 공식과 보상

숙련 레벨=`floor(누적 XP/1000)`. XP와 레벨, 층, 누적 승리는 10진 문자열/BigInt로 보존하며 게임 규칙상 최대 레벨·최대 층·능력치 보너스 상한을 두지 않는다. 기존 JSON 저장 크기 제한은 유지한다. 극단적으로 큰 전투 수치는 공통 10진 지수로 유한 표현하므로 상대적으로 아주 작은 값에는 기존 최소 정수1의 수치 해상도 한계가 있다. 무한 정밀도 전투를 주장하지 않는다.

`최종 능력치 = 기존 성급·장비·영구 강화 적용 능력치 + floor(해당 캐릭터의 현재 레벨 기본 능력치 × 숙련 레벨 × 비율)`

비율은 ATK0.0002, DEF0.00015, HP0.00025다. 숙련 보너스를 성급·훈련 배율로 다시 곱하지 않는다. Lv.100/500/1000/5000의 ATK는 +2/10/20/100%, DEF+1.5/7.5/15/75%, HP+2.5/12.5/25/125%다. 전투 능력치 비교는 영이·찬미·아스트라·루시안의 다섯 숙련 단계에서 검사했다. 아래는 Lv.50 영이, 성급5 입력(인간은 미적용), 영구훈련 각20의 예시다.

|친구|숙련 Lv.|HP|ATK|DEF|
|---|---:|---:|---:|---:|
|영이|0|838|127|36|
|영이|100|855|129|36|
|영이|500|925|138|38|
|영이|1000|1012|149|40|
|영이|5000|1710|238|60|

층 효율은 최고층과의 차이0–5:110%, 6–15:100%, 16–30:90%, 31–50:75%, 51이상:50%다. 첫 승리+10%p는 해당 층 한 번, 연승 승리당+2%p(10회/20%p 상한), 황금+15%p/그림자+10%p를 합하고 최종 효율150% 상한을 적용한다. 패배·포기·기한 만료는 연승 보너스만 초기화한다. 누적 숙련과 클리어를 지우지 않는다. 첫 클리어 이력은 순차 해금과 `firstThrough`로 압축한다.

최종 참가자별 XP=`max(1, floor(100 × 훈련규모 × min(150, 층효율+보너스)/100))`. 훈련규모는 입장 때 실제 전투 계산의 적 HP/해금 공격 스킬 위력으로 예측해 0.01–8로 고정한다. 행동을 오래 끌어 XP를 늘릴 수 없다. 최대1200XP/승리이며 고층이라는 이유만으로 지수 증가하지 않는다. 너무 강한 파티로 낮은 층을 한 번에 지우는 파밍의 보상을 줄인다. 일반 코인·경험치·강화석·상자 등 기존 경제 보상은 수련탑에서 추가 지급하지 않는다.

1층, 실제 Lv.1 영이·찬미·모모·비비·루루의 5인 파티, 1,000개 시드, 효율110%, 첫/연승/희귀 XP추가 제외 조건에서 평균98.335XP/승리, **10.17승/숙련1레벨**이다. 이는 초기 성장 표본이며 모든 레벨·파티·층에서 정확히 10승을 보장하지 않는다. 기준 훈련규모1에서는 100XP/승리이며 고층과 강화 파티의 실제 횟수는 달라진다.

## 저장·무결성·호환

- 기존 공유 월드의 계정 JSON 하위 `account.tower`에만 추가한다. 새 DB 테이블/스키마/마이그레이션/새 Supabase 프로젝트가 없고 기존 친구/가구/재화/아레나 클리어를 초기화하지 않는다. 같은 비밀번호의 기존 공유 아레나 소유자 규칙을 재사용한다. 보존 계정도 섞지 않는다.
- 서버가 소유/레벨/성급/장비/훈련/스킬/COST를 결정한다. 클라이언트의 seed·XP·레벨·승리 값은 명령 검증에서 거절한다. 서버 전투 재생으로 승리와 체크포인트 연장을 검증한 뒤 기존 revision CAS로 지급한다.
- 동일 시작 재전송은 활성 티켓을 반환하고 완료 재전송은 지급된 결과만 반환한다. 두 기기 동시 완료/응답 유실 후 새 요청 ID/다른 소유자/조작된 층·행동/새 월드 import의 위조 숙련 제거를 검사했다. 기존 인증/RLS/접속 비밀번호·서버 승인 경계는 유지한다.
- 기존 규칙1–9 티켓은 해당 엔진을 사용한다. main의 규칙9 계산을 `legacy-v9`에 동결했다. 새 화면의 일반 전투와 수련탑은 규칙10을 쓴다. 옛 클라이언트의 일반 시작은 기존9로 호환하며 새 `proficiency:1` 명시가 있는 시작만10이다. 공통 클라우드 wire header는9를 유지하므로 다른 미니게임 통신 형식을 변경하지 않는다. 새10 전투를 이어할 때는 오래 열린 기기의 화면을 새로고침해야 한다.

## CI 최적화와 시간

검증 강도 FULL과 실행 범위를 분리했다. FULL은 전체 단위/자동화/정책/Deno/빌드와 필수 browser/cloud 성공 확인을 유지한다. 기능 내부의 확인된 아레나 변경은 관련 2개 브라우저 파일·10개 클라우드 파일만 선택한다. 수련탑 내부 UI는 지원되는 안전한 구문에서 STANDARD(수련탑 검사), 기존 적 성장 수치 리터럴은 FAST가 가능하다. 해석 불가한 UI 구문·보상/저장/의존성 변경은 FULL로 올린다.

match3/사천성 내부만 변경하면 해당 기능 범위를 선택한다. 공통 저장·인증·게임 디스패처, 워크플로/정책/툴링, 모르는 파일·동적 의존성·전역 CSS·기능 혼합·삭제·심볼릭 링크·분석 실패는 전체로 돌아간다. 8가지 사용자 요구 사례를 정책 테스트에 포함했다. 기존 trusted main/base, 정확한 head/SHA·validated-head·build·리뷰·서버 승인·Pages 검증·운영 읽기 전용 스모크는 삭제하지 않았다. AGENTS.md는 수정하지 않았다.

정책을 바꾸는 **이번 PR 자체는 기존 trusted main/base의 전체 CI를 유지**한다. 원격 전체 검사를 후보 정책으로 축소하지 않는다. 이번 배포가 끝난 뒤 순수 기능 PR에 범위 최적화가 적용된다. 전체 수집은 브라우저246/클라우드148 슬롯이며, 관련 실행은16/88 슬롯이다. 수집 개수는 실행 시간 절감률이 아니다. 같은 최종 커밋의 전후 전체 CI/배포 시간 실측값이 없어 절감률을 제시하지 않는다. 위 1.0분/9.9분은 로컬 관련 검사 측정값이며 GitHub 실행 시간이 아니다.
