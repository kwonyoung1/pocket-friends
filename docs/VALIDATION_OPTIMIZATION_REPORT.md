# 통합 검증·자동 배포 최적화 결과

2026-11-26. 요청 FULL / 자동 최소 FULL / 적용 FULL. 이번 변경은 자동화 자체의 변경이므로 FAST로 도입하지 않습니다.

## 구현

- Codex와 CI가 `scripts/validation/policy.mjs`를 공유합니다. 로컬은 실제 작업 트리, CI는 실제 git head/base diff를 읽습니다.
- AUTO 기본값, FAST/STANDARD/FULL 요청, 더 높은 최소 위험도로 자동 상향, 판정 실패 시 FULL을 구현했습니다.
- FAST는 허용된 숫자 토큰/계수·정적 에셋만 확인된 경우입니다. 연산/식별자/스킬 추가, 보상/성장/서버/자동화, 불확실한 변경은 더 높은 등급으로 분리합니다.
- STANDARD는 실제 영향 기능 단위·브라우저 및 필요한 클라우드만 선택합니다. 순수 전투 애니메이션은 불필요한 클라우드/Deno를 생략합니다.
- FULL은 기존 전체 단위·자동화·Deno·브라우저·클라우드를 유지합니다.
- `AGENTS.md`에 작업별 실행 정책과 동일 코드/환경의 성공 검사 중복 방지, 실패/관련 변경만 재검증하는 규칙을 저장했습니다.

## CI 안전성

새 `changes` job은 후보 브랜치의 분류 코드를 실행하지 않습니다. 신뢰하는 main/base의 정책/CLI를 추출하고, 검증 계획은 후보 저장소 밖의 runner temp에 씁니다. 계획의 head/base·등급·필수 검사·선택 목록을 확인하며 이상하면 FULL로 복구합니다.

마지막 내부 main의 유효한 `release-proof` 이후 미배포 변경을 누적 분석합니다. 미검증/미배포 서버 변경 뒤에 이미지 커밋만 추가해 FAST로 낮추지 못합니다. 운영 배포 증명 조회가 실패하거나 정책이 처음 도입될 때에도 FULL입니다.

기존 필수 `build` 이름, trusted Codex 출처, strict branch protection, 리뷰, 검증 PR head/main base, `validated-head-...-base-...` 이름, exact-head merge, main 배포와 운영 승인, Supabase SHA 상태, Pages SHA/HTML/JS 및 읽기 전용 모바일 실행 검사를 유지했습니다. 정책상 생략한 job만 사유 있는 Skipped로 인정하며 필요한 검사 실패·취소·누락·예상 밖 Skipped는 통과하지 않습니다. 현재 선택적 범위/정책 해시와 실제 소스 tree/lock/빌드 구성/환경도 증명에 남깁니다.

사용자 요청은 `validation.request.json`에 base SHA와 함께 저장합니다. 미래 자동 PR은 이를 지정 메타데이터 항목으로 표시합니다. 본문·라벨·커밋 문구로 최소 위험도를 낮추지 않습니다. 이번 첫 도입은 파일에 FULL을 기록하고 bootstrap도 FULL을 강제합니다.

## 설치·캐시·중복

- FAST는 browser/cloud job이 없어 그 npm/브라우저 설치도 하지 않습니다. 의존성 설치가 필요한 검증 job은 기존 3개에서 1개로 줄어듭니다(별도 경량 분석 job은 npm 설치 없음).
- job마다 머신이 다르므로 필요한 `npm ci`를 잘못 공유하지 않습니다. npm 다운로드 캐시는 유지합니다.
- Playwright 버전·OS·아키텍처 키를 사용해 관계없는 package-lock 변경의 브라우저 캐시 미스를 줄입니다. OS 의존성 설치와 실행 probe, 손상 시 한 번의 복구 후 재검증을 유지합니다.
- 프로덕션 빌드는 한 번이며 내부 tsc를 별도로 중복 실행하지 않습니다. 이번 작업에서 빌드 후 테스트 fixture를 수정한 뒤에는 그 변경의 타입만 증분 검사했습니다.
- 경과 시간만 필요한 테스트는 불필요한 장시간 프레임 재생을 줄였습니다. 연속 발화·입력·애니메이션·보상 구간은 유지했습니다.
- 기존 보상 테스트가 분할 응답 `pending`을 너무 일찍 `paid`로 단정하던 부분은 제한된 재시도로 정산 완료를 확인합니다. 서버 보상 계산/RPC/재화 처리는 변경하지 않았습니다.
- 시계 설치 직후 같은 순간에 정지하려던 fixture의 경쟁 조건과, 짧은 `pressing` 프레임을 놓치던 드래그 테스트를 안정된 실제 hold/최종 drop 검증으로 보완했습니다. 중복 보상·원본 사진·지갑·저장·동기화 assertion은 유지합니다.

PR 검사 결과로 main 전체 검사를 대체하는 자동 재사용은 활성화하지 않았습니다. PR/main 빌드 환경과 동일 소스/lock/environment의 실제 재사용 증명을 아직 확보하지 못했으므로, main도 판정된 등급을 검사하고 새로 빌드합니다. 아티팩트 이름만 같다는 이유로 다른 환경/커밋의 검사를 재사용하지 않습니다.

## 검증

- 자동화/정책 71개: A~G, 실제 임시 git 저장소의 변경 분석, 사용자 요청 상향/오류, 미배포 서버 누적 분석, 후보 정책 미실행, 실제 workflow gate, 실패/취소/누락/위조 계획, SHA/보호 규칙, 브라우저 캐시 복구를 검증했습니다.
- 전체 Vitest 681개를 실행했습니다. 첫 실행의 분할 보상 1개 실패를 테스트의 bounded pending 처리로 수정하고 해당 파일 8개를 다시 통과시켰습니다. 다른 58개 파일의 코드는 바꾸지 않았습니다.
- TypeScript/Vite 프로덕션 빌드와 고정 Deno lock 검사를 통과했습니다. 변경 후 증분 타입 검사도 통과했습니다.
- 전체 브라우저 224개: 첫 실행 200 통과/19 기존 생략/5 실패. 실패 5개는 원인 확인 후 모두 재검증 통과했고, 시간 처리 최적화가 바뀐 모바일/데스크톱 항목도 추가로 확인했습니다.
- 전체 클라우드 106개: 첫 실행 68 통과/24 기존 생략/14 실패. 단일 머신에서 여러 소프트웨어 GPU 검사를 동시에 실행한 부하와 fixture 타이밍 문제가 포함되어, 다른 브라우저 검사를 종료한 뒤 실패 항목만 단일 worker로 재검증했습니다. 실패 14개는 재검증에서 모두 통과했습니다(3.7분). 정책상 생략된 job을 통과로 표기한 것이 아니며, 기존 테스트별 skip 24개는 유지했습니다.
- YAML 파싱 및 workflow shell 구문 검사도 수행했습니다. 실제 운영 DB나 사용자 계정에 테스트 요청을 보내지 않았습니다.

위 로컬 시간을 GitHub runner 속도나 CI 절감률로 환산하지 않습니다. FAST에서는 전체 브라우저/클라우드 job을 생략하므로 같은 규모의 작업에서 기존 13분대 cloud job을 피할 수 있다는 구조적 예상은 가능하지만, 총 배포 시간·절감률은 main에 정책을 적용한 뒤 실제 FAST 실행으로 확인해야 합니다. 공개/비공개 저장소의 과금·사용량을 조회했다고 보고하지 않습니다.

## 변경 파일과 운영 상태

주요 파일: `scripts/validation/*`, `.github/workflows/deploy.yml`, `scripts/automation/github.mjs`, `scripts/automation/tests.mjs`, workflow 안전성 테스트, `package.json`, `AGENTS.md`, 관련 test fixture, 요청 메타데이터와 이 문서/클릭 안내서입니다. 게임 런타임/DB 스키마/기존 캐릭터 능력치/아이템/코인/사용자 진행은 변경하지 않았습니다. 자동 생성된 테스트 스크린샷은 기능 변경으로 커밋하지 않습니다.

GitHub PR/병합·실제 CI·main 발행 상태는 별도로 확인해야 합니다. GitHub API/운영 URL 조회가 차단되면 푸시 성공을 운영 배포 성공으로 보고하지 않습니다. 이번 자동화 변경은 기존 정책상 보호 리뷰·운영 승인 대상이며 이를 제거하지 않습니다. 서버 배포는 이 작업 자체로 새로 요구하지 않지만 이전 main의 미배포 변경은 기존 release plan이 판단합니다.
