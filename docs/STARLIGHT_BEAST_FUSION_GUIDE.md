# 별빛 아레나 환수 합성·속성 공명 — 클릭 안내

게임: https://kwonyoung1.github.io/pocket-friends/

이번 변경은 기존 자동 공유 아레나를 확장합니다. 같은 접속 비밀번호의 모든 기기가 환수·에너지·합성 결과를 공유합니다. DB 테이블 변경·데이터 초기화·새 토큰 발급은 필요하지 않습니다. 아래 기능은 이번 서버와 웹 배포가 모두 끝난 뒤 사용할 수 있습니다.

## 1. 이번 코드와 배포 확인

1. [이번 작업 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls?q=is%3Apr+head%3Acodex%2Farena-beast-fusion)을 엽니다. `codex/arena-beast-fusion` → `main`인 PR을 누릅니다. 이전 #41·#42와 구분합니다.
2. PR이 없다면 [자동 PR 워크플로](https://github.com/kwonyoung1/pocket-friends/actions/workflows/auto-pr.yml)의 해당 브랜치 실행을 확인합니다. 실패했고 열린 PR도 없는 경우에만 [변경 비교](https://github.com/kwonyoung1/pocket-friends/compare/main...codex/arena-beast-fusion?expand=1) → **Create pull request**를 사용합니다. Base는 `main`, Compare는 `codex/arena-beast-fusion`입니다.
3. PR의 **Checks**를 누릅니다. `unit`, `browser`, `cloud`, 필수 `build`가 성공해야 합니다. **Approve workflows to run**이 표시될 때만 누릅니다. 실패한 검사를 무시하거나 보호 규칙을 해제하지 않습니다.
4. 자동 병합되면 보라색 **Merged**가 표시됩니다. **Approvals required**가 있으면 **Files changed → Submit review(또는 Review changes) → Approve → Submit review**로 최신 변경을 검토합니다. 작성자 본인 승인이 제한되면 권한 있는 다른 리뷰어가 필요합니다. 모든 조건을 충족했는데 수동 병합이 필요할 때만 **Merge pull request → Confirm merge**를 사용합니다.
5. [최신 main 배포 목록](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml?query=branch%3Amain)을 열어 이번 병합 커밋의 실행을 누릅니다.
6. **Waiting / release-approval**이면 **Review deployments → release-approval 체크 → Approve and deploy**를 누릅니다. 지정된 리뷰어가 승인해야 합니다. 버튼이 없고 실행 중이면 기다립니다.
7. `plan`에서 변경된 서버 함수 `game`을 확인합니다. **backend / functions**, **backend-gate**, **deploy**와 배포 SHA 확인이 성공해야 합니다. `treasure`는 변경하지 않으며 기존 서버 배포 계획이 의존성이 바뀐 함수만 선택합니다.
8. **Verify live HTML, exact commit and executable assets**, **Read-only live mobile boot check**가 성공했는지 확인합니다. 전체 실행이 초록색이어도 `deploy Skipped`는 실제 웹 배포 성공과 다릅니다.
9. [공개 버전 정보](https://kwonyoung1.github.io/pocket-friends/version.json)의 SHA가 해당 배포 커밋과 같은지 확인한 뒤 [게임](https://kwonyoung1.github.io/pocket-friends/)을 새로고침합니다.

이번 변경에는 서버 합성·전투·보상 검증 코드가 포함됩니다. [AGENTS.md](../AGENTS.md)의 “Security/auth, DB, secrets, economy, workflow changes ... required explicit review/production approval” 지침과 기존 `scripts/automation/policy.mjs`에 따른 리뷰·운영 승인을 유지합니다. 정상인 Secrets·토큰·자동화 설정을 다시 만들지 않습니다.

## 2. 환수 합성하기

1. [운영 게임](https://kwonyoung1.github.io/pocket-friends/)에서 평소 접속 비밀번호로 로그인합니다. 기존 월드는 **이 클라우드 월드 사용하기**를 선택합니다. 새 월드나 계정을 만들 필요가 없습니다.
2. **별빛 아레나 → 환수 도감 · 보물상자 → 환수 합성**을 누릅니다.
3. **합성 대상**에서 보유한 환수를 고릅니다. 두 그림은 같은 종류의 주환수와 동일 성급 재료를 뜻합니다. 기존 레벨·XP·별자리·COST를 유지합니다.
4. 현재 성급, 조각 수, 필요한 재료, 합성 전후 HP·ATK·DEF를 확인합니다.
5. **★2로 합성**(현재 성급에 따라 ★3·★4·★5)을 누릅니다. 재료가 부족하거나 최고 성급이면 버튼이 비활성화됩니다. 별도의 확률 실패나 코인·에너지 소모는 없습니다.
6. 두 환수의 빛이 모이는 연출 뒤 결과를 확인합니다. **연출 건너뛰기 → 합성 결과 확인**으로 빨리 마칠 수 있습니다. 3성부터 공격의 충격 고리·파티클을 강화하고, 4성부터 특별 오라, 5성은 전용 황금빛 합성 배경·광선·오라와 필살기 컷인을 사용합니다. 모션 감소 설정을 지원합니다.
7. **최근 합성 결과 다시 보기**는 저장된 결과만 보여 줍니다. 재료를 다시 쓰거나 성급을 다시 올리지 않습니다.

### 기존 조각과 합성의 관계

현재 저장 구조는 같은 환수를 여러 개체로 쌓지 않고, 주환수 1마리와 전용 조각으로 보유합니다. 중복 1마리의 조각 가치는 그대로 희귀 8·영웅 16·전설 32·신화 64개입니다. 동일 종류의 조각만 사용할 수 있습니다.

| 합성 | 추가로 필요한 1성 중복 환수 분량 | 희귀 조각 | 영웅 조각 | 전설 조각 | 신화 조각 |
|---|---:|---:|---:|---:|---:|
| 1성 + 1성 → 2성 | 1마리 | 8 | 16 | 32 | 64 |
| 2성 + 2성 → 3성 | 2마리 | 16 | 32 | 64 | 128 |
| 3성 + 3성 → 4성 | 4마리 | 32 | 64 | 128 | 256 |
| 4성 + 4성 → 5성 | 8마리 | 64 | 128 | 256 | 512 |

주환수까지 포함하면 5성에 총 1성 16마리 분량이 필요합니다. 예전 조각도 같은 가치로 사용할 수 있고 잔여 조각은 남습니다. `duplicates`는 과거 획득 이력이므로 이를 별도 재료로 다시 지급하지 않습니다. 이미 XP·별자리 육성에 사용한 조각도 재지급하지 않습니다. 조각을 기존 육성에 쓰면 그만큼 합성 재료도 줄어듭니다.

### 성급별 실제 배율

| 성급 | HP·ATK | DEF | 속도·치명타·회피 |
|---|---:|---:|---|
| ★1 | 1.0배 | 1.0배 | 성급으로 증가하지 않음 |
| ★2 | 1.35배 | 1.2배 | 동일 |
| ★3 | 1.85배 | 1.45배 | 동일 |
| ★4 | 2.6배 | 1.75배 | 동일 |
| ★5 | 3.7배 | 2.1배 | 동일 |

DEF는 높은 성급이 적 공격을 사실상 전부 무효화하지 않도록 별도 성장 곡선을 사용합니다. 정수 반올림이 적용됩니다. ★4 이상 환수의 회복·보호 효율은 추가 10% 강화하며, 피해 감소·상태 이상 확률·행동 횟수를 무제한 올리지 않습니다. 별자리 마스터리와 성급은 서로 다른 성장입니다.

## 3. 속성 공명 확인하기

1. **파티 편성으로 돌아가기**를 누릅니다. 환수를 파티에 추가합니다.
2. **활성화된 환수 공명**에서 편성된 환수의 실제 속성을 확인합니다. 기존 속성 이름을 사용합니다. 예를 들어 피닉은 화염, 네뷸라는 어둠, 셀레나는 물입니다. 성운·달빛은 개성 이름이며 새 속성을 임의로 추가하지 않았습니다.
3. 최대 5명·COST 10·영이 또는 찬미 필수 규칙은 그대로입니다. 예를 들어 영이+루미+네뷸라+피닉은 4명/COST 9로 빛·어둠·화염 공명을 구성합니다. 요청 예시 중 5명/COST 12인 조합은 기존 COST 규칙 때문에 허용하지 않습니다.
4. 전투에서 공격자의 공명 아이콘을 확인합니다. 살아 있는 **다른 환수**가 공급하는 속성이 적용됩니다. 환수 본인의 공명은 자신에게 적용하지 않지만 다른 환수의 속성은 받을 수 있습니다. 공격자의 원래 속성은 유지됩니다.
5. 기본 공격 또는 공격 스킬을 적중시키면 모든 서로 다른 공명이 각각 연출되고 **최근 공명**에 속성별 추가 피해가 표시됩니다. 적이 이미 쓰러졌거나 보호막에 막혔다면 HP 추가 피해는 0일 수 있습니다.

### 공명 제한

- 같은 속성은 한 번만 발동합니다. 가장 높은 공급 성급을 사용하며 같은 속성의 추가 환수는 한 번의 작은 보너스만 줍니다.
- 속성 순서는 화염·물·자연·대지·빛·어둠으로 고정하고, 존재하는 속성에 기본 20·15·10·5% 순서의 기여를 줍니다. 성급당 +1%p(최대 +4%p), 같은 속성 추가 공급은 +1%p 한 번입니다. 합산 비율은 50%로 정규화합니다.
- 실제 보호막 흡수와 HP 추가 피해를 합해 한 스킬 전체에서 공격자 상태창 ATK의 50%를 넘지 않습니다. 광역 공격은 이 예산을 대상 수로 나눕니다. 추가 피해에는 별도 방어·상성이 반영됩니다.
- 다단 공격마다 공명하지 않고 한 스킬에 한 번만 처리합니다. 공명이 공명을 다시 부르지 않습니다. 회복·보호·버프·반격·지속 피해·적 공격으로 추가 공명을 만들지 않습니다.
- 공명 약점 감소는 적당 한 스킬 합계 최대 0.25로 작게 제한합니다. 화상·빙결 등 고유 상태 이상은 원래 스킬 효과를 사용하며 공명으로 무한 중첩하지 않습니다.
- 모든 속성별 연출을 순차적으로 짧게 표시합니다. 2배속·모션 감소·저성능 기기 파티클 축소를 지원합니다.

## 4. 스킬 범위와 대상 확인하기

1. 편성 카드의 **스킬 · 해금 정보**에서 스킬명·속성·단일/2명/3명/전체·공격 배율·상태 이상·해금 레벨·별빛 비용을 확인합니다. 도감의 **스킬·획득 상자**에서도 확인할 수 있습니다.
2. 전투에서 스킬 버튼을 누릅니다. 이 단계에서는 아직 공격하지 않습니다.
3. 강조된 적·아군과 **몇 명 선택** 표시를 확인합니다. 대상은 필드 또는 상태 버튼을 눌러 바꿀 수 있습니다. 스킬 아래의 ‘…명 선택’ 문구를 누르면 상세 효과를 펼칠 수 있습니다.
4. **선택한 스킬 사용**을 눌러 실행합니다. 기본 공격도 같은 절차입니다. 단일·2인·3인 범위는 중복 없는 살아 있는 대상만 선택하며, 한 명만 남았다고 같은 적에게 여러 명분의 타격을 추가하지 않습니다.
5. 2인 예시는 네뷸라의 **공명의 별가루**, 이클립스의 **월식 분신**입니다. 3인 예시는 피닉의 **홍련 깃털**, 루미의 **은빛 혜성우**입니다. 각 스킬의 기존 해금 레벨·별빛 비용을 충족해야 합니다.

## 6. 연결 끊김·기존 전투·오류 대응

- 합성 중 연결이 끊기면 **같은 작업 다시 시도** 또는 **같은 합성 작업 다시 확인**을 누릅니다. 새로고침한 경우 평소처럼 월드에 들어가 **환수 합성**에서 현재 성급·조각·최근 결과를 확인합니다. 원래 작업 번호와 기대 성급으로 중복 소비를 막습니다.
- 다른 기기에서 먼저 합성했다면 **최신 성급** 오류가 날 수 있습니다. 최신 기록을 읽고 새 성급과 필요 재료를 확인하세요. 오류를 해결하려고 조각·환수 데이터를 지우지 않습니다.
- 진행 중인 전투는 입장 당시 능력치·성급을 유지합니다. 업데이트 이전 규칙 1·2 전투도 원래 전투 계산으로 서버 검증과 보상을 완료할 수 있습니다. 새 전투부터 규칙 3 상향·공명·합성이 반영됩니다.
- **최신 화면으로 새로고침** 메시지는 옛 전투 화면으로 새 데이터를 덮어쓰지 않도록 막은 것입니다. 새로고침하고 재입장합니다. 쿠키·계정·저장 공간을 지우지 않습니다.
- 합성 메뉴가 없다면 이전 웹 버전일 수 있습니다. 1번의 배포 SHA를 확인합니다. 웹만 새롭고 서버가 옛 버전이면 합성을 진행하지 말고 `game` 배포 로그를 확인합니다.
- 자동 배포 실패 시 [Actions](https://github.com/kwonyoung1/pocket-friends/actions)를 열고 이번 커밋의 실패 단계를 확인합니다. 인증 실패만으로 토큰을 무조건 재발급하지 않습니다. 기존 정상 설정은 유지합니다. [기존 설정 안내](../AUTO_DEPLOY_SETUP.md)는 실제 권한·설정 오류가 확인된 경우에만 참고합니다.
- 운영 장애는 [기존 승인형 롤백](https://github.com/kwonyoung1/pocket-friends/actions/workflows/rollback-pages.yml)을 사용합니다. 새 성급이 저장된 월드는 이전 서버·화면이 지원하지 않을 수 있으므로 웹만 되돌렸다고 복구 완료로 판단하지 않습니다. 데이터를 초기화하지 말고 규칙 3을 읽을 수 있는 서버·화면 조합으로 복구합니다.
