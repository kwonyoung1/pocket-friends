# 보물·음식 취향·영단어 탐험 업데이트

기존 main `952dcd9`에서 `feat/treasures-food-word-expedition` 브랜치를 만들었습니다. 기존 캐릭터 ID·사진·이름·레벨·경험치·친밀도·코인·인벤토리·가구·햄스터·탐험 결과·인증을 유지하는 추가 변경입니다. 운영 데이터에 직접 접속하거나 SQL을 실행하지 않았습니다. 아래 배포가 필요합니다.

## 구현한 기능

- 희귀 보물 진주·토파즈·은·자수정, 전설 보물 다이아몬드·금·루비·사파이어·에메랄드. 각각 프로젝트에서 그린 SVG를 사용합니다. 유료 이미지 API는 사용하지 않습니다. 인벤토리, 도감, 발견일·획득 횟수와 전설 발견 연출에 연결했습니다. 소리는 기존 스피커 버튼을 켰을 때만 재생합니다.
- 기존 일반/고급/희귀 수집용 보물의 **실제 판매액**을 5→10, 15→30, 50→100코인으로 변경합니다. 기존 전설의 판매 불가 설정은 유지합니다. 새 보물은 진주150·은200·토파즈250·자수정300·금1500·사파이어1800·루비2000·에메랄드2200·다이아몬드3000코인에 판매합니다. 희귀/전설 수집용 보물은 확인창을 거쳐 1개만 판매하고 도감은 유지합니다.
- 음식 4종 추가: 딸기우유60(+포만10/행복15), 치즈버거120(+55/8), 초밥 도시락180(+70/12), 무지개 마카롱250(+20/30). 기존 음식5종도 유지합니다. 선호1.5배/비선호0.8배/보통1배를 **양수 포만·행복 효과에만 반올림**하여 적용하고 100으로 제한합니다. 기존 선호 음식 +5 보너스는 제거해 중첩하지 않습니다. 기본 사료는 항상1배입니다. 음식 수량은1개만 소비합니다.
- 음식 취향은 고유 ID로 저장하며 개명과 무관합니다. 영이 역할 `special-boy`는 버거/우유, 찬미 역할 `special-girl`은 마카롱/버거를 선호/비선호합니다. 요청 예시의 몽글 역할은 실제 기존 첫 친구 `momo`(기본 이름 모모)에 적용했습니다. 비비·코코·두두·입양 친구 등 모든 친구에게 서로 다른 선호/비선호를 부여하며 미지정 ID도 결정적인 기본 취향을 저장합니다. 기존 이름을 바꾸지 않습니다. 상세 정보에서 취향을 확인합니다. 사진 얼굴은 왜곡하지 않고 하트·움직임·대사로 표현합니다.
- 영단어 탐험: 3단계×10문제, 한 회차 중복 없음, 난이도별 미출제 우선·직전 회차 우선 제외, 한국어 허용 정답/일부 활용형 정규화, Enter·빈 입력 검사, 문제별 한 번 채점, 스테이지별 힌트3회, 정답 보기·건너뛰기, 오답 노트와 무보상 복습. 메뉴를 닫았다 열면 이어갑니다. 새로고침 및 PC·모바일에서도 이어집니다.
- 영단어 보상은 서버가 채점 기록으로 `max(0,300-오답×10)`을 계산해 한 번 지급합니다. 시작 시점부터2시간 제한, 진행 중 회차 이어하기 우선, 포기해도 제한 유지, 시작6시간 후 미완료 회차는 무보상 종료합니다. 복습은 보상·보상 쿨타임에 영향이 없습니다.
- 수동 쉬게 하기: 친구별 체력+20, 짧은 휴식 움직임·대사, 보상 성공 시점부터 정확히240분 제한. 상세 패널에 남은 시간을 표시하며 서버 시각으로 동기화합니다. 기존 자동 휴식·야간 수면과 쓰다듬기6시간 제한은 별개로 유지합니다.

## 실제 단어 수와 한계

**중학교30 + 고등학교 기본30 + 심화30 = 총90개**를 등록했습니다. 목표5000개 중4910개는 아직 없습니다. 요청서에서 허용한 정확성 우선의 초기 부분 집합으로 시스템을 먼저 완성했습니다. UI에도90개라고 표시합니다.

뜻·허용 답안·예문은 직접 작성해 검토한 초기 자료입니다. 공식 교육과정 선정 목록이나 사전 기관의 감수를 받은 데이터라고 주장하지 않습니다. 외부 사전 크롤링·유료 API·라이선스가 불명확한 대량 자료는 사용하지 않았습니다. 실제 교육용 대량 목록 구축에는 별도의 어휘·난이도 검수가 필요합니다. `src/words/bank.ts`에 같은 구조로 확장할 수 있습니다. 영어 표제어를 소문자로 정규화하고 중복·난이도 수·필수 필드를 테스트합니다.

채점/전체 답안 은행은 Edge Function에 포함하고 운영 프런트엔드 번들에서는 제외합니다. 힌트에는 예문·품사·첫 두 한글 음절 초성만, 채점 후에는 그 문제의 뜻을 전달합니다. 이미 공개된 단어/뜻과 자동 입력까지 완벽히 차단하는 시험 보안은 보장하지 않습니다. 금액·시간·채점 상태·재시도는 서버가 검증합니다. 개발 서버 로컬 모드는 서버 시간 보호를 제공하지 않습니다.

## 탐험 확률

| 지역 | 일반 | 고급 | 희귀 | 전설 수집 보물 전체 |
|---|---:|---:|---:|---:|
| 신비의 숲 |70%|24%|6%|0%|
| 반짝이는 해변 |55%|32%|13%|0%|
| 고대 동굴 |40%|37%|22.75%|0.25%|
| 비밀의 정원 |25%|40%|34.5%|0.5%|

각 행의 합계는100%입니다. **기본 수집용 보물1개**의 등급 확률이며 개별 보물의 확률이 아닙니다. 전설 등급이 나오면 동굴/정원에 등록한 기존3종+새5종 총8종 중 균등 추첨합니다. 따라서 기본1회에서 개별 전설은 동굴0.03125%, 정원0.0625%입니다. 숲/해변에는 전설 수집용 보물을 등록하지 않습니다.

호기심형은8% 확률로 같은 수집 보물 풀을 한 번 더 독립 추첨합니다. 전설 수집 보물을1개 이상 얻는 실질 확률은 `p + 0.08*p*(1-p)`: 동굴0.26995%, 정원0.5398%입니다.

기존 배치 가구32종은 별도로 보존하며25% 확률로1개를 추첨합니다. 가구 등급 분포는 위 지역의 표와 같고 해당 지역/등급 가구 중 균등 선택합니다. 탐험당 전설 가구 확률은 동굴0.0625%, 정원0.125%입니다. 가구 결과를 수집 보물 확률에 합산하지 않습니다. 감기10%·햄스터0.5%도 각각 독립 추첨입니다. 출발 때 정한 기존 탐험 결과는 다시 추첨하지 않으므로 업데이트 전 숲에서 확정한 전설도 귀환 때 그대로 받습니다.

## 데이터 보존

저장 버전2와 기존 저장 키를 유지합니다. 새 취향·마지막 수동 휴식 보상·영단어 진행만 추가하며 업그레이드 자체로 코인이나 아이템을 지급/차감하지 않습니다. 기존 진행 탐험은 결과를 그대로 유지합니다.

로컬은 업데이트 전 원본을 localStorage의 `pocket-friends-v1-before-adventure` 또는 IndexedDB의 `before-adventure`에 한 번 보관합니다. 두 저장소 모두 백업할 수 없으면 자동 덮어쓰기를 중단하고 수동 백업을 안내합니다. 클라우드 게임은 기존 로컬 원본을 덮어쓰지 않습니다.

새 SQL은 별도 비공개 `game_adventure_backups` 테이블과 커밋 함수를 추가합니다. SQL 실행만으로 월드가 바뀌지 않습니다. 첫 성공적인 새 버전 커밋과 같은 트랜잭션에서 직전 월드 JSON·revision을 한 번 보관합니다. 실패한 트랜잭션은 백업/보상 모두 취소됩니다. 익명·일반 인증 사용자는 이 백업을 읽거나 수정할 수 없습니다. 기존 행 잠금/버전 비교/작업 ID 재시도 방지로 동시 입력을 처리합니다.

클라이언트 프로토콜5입니다. 새 규칙이 한 번 저장되면 이전 버전 화면의 쓰기를 거절하고 새로고침을 안내합니다. **서버 먼저, 화면 나중**에 배포하세요. 기존 월드를 다시 가져오거나 새로 만들 필요가 없습니다.

## 눌러서 이동하는 배포 순서

이번에는 **추가 SQL1개가 필요**합니다. 이전 업데이트 문서의 “SQL 불필요”는 이전 업데이트에만 해당합니다.

1. 먼저 [현재 게임 열기](https://kwonyoung1.github.io/pocket-friends/) → 로그인 → **추억 보관**을 눌러 현재 JSON을 PC에 보관합니다. 사이트 데이터 삭제/월드 초기화/기존 데이터 재가져오기는 하지 마세요.
2. [새 SQL 파일 열기](https://github.com/kwonyoung1/pocket-friends/blob/feat/treasures-food-word-expedition/supabase/migrations/202610160001_adventure.sql) → 코드 오른쪽 **Copy raw file**(겹친 사각형 아이콘)으로 **내용 전체**를 복사합니다. 버튼이 없으면 **Raw**를 열고 Ctrl+A → Ctrl+C입니다.
3. [기존 Supabase 프로젝트 열기](https://supabase.com/dashboard) → 기존 **pocket-friends** 프로젝트 → 왼쪽 **SQL Editor**(사각형 안 `>_` 아이콘) → **New query** → 복사한 SQL 붙여넣기 → **Run**. `Success. No rows returned`가 나오면 완료입니다. 새 프로젝트를 만들거나 이전 초기화 SQL을 다시 실행하지 않습니다. 이 추가 SQL은 다시 실행해도 데이터를 초기화하지 않습니다.
4. [Pull Request 만들기](https://github.com/kwonyoung1/pocket-friends/compare/main...feat/treasures-food-word-expedition?expand=1) → base가 **main**, compare가 **feat/treasures-food-word-expedition**인지 확인 → **Create pull request**. 검사가 모두 초록색이 될 때까지 기다립니다. 본문은 [PR 설명](ADVENTURE_PR.md)을 사용할 수 있습니다.
5. [서버 배포 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy-cloud.yml) → **Run workflow** → Branch에서 **feat/treasures-food-word-expedition** 선택 → **Run workflow**. 가장 위 새 실행을 눌러 **deploy-backend**가 초록색인지 확인합니다. 이번에는 **main이 아니라 새 기능 브랜치**를 고릅니다. 기존 token·Project ref·비밀번호 설정을 재사용하며 새 secret은 필요하지 않습니다. token 만료/권한 오류가 나올 때만 교체합니다.
6. [열린 PR 목록](https://github.com/kwonyoung1/pocket-friends/pulls) → 방금 만든 PR → 아래 **Merge pull request → Confirm merge**. 목록 화면에는 Merge 버튼이 없습니다. 실패한 검사가 있으면 합치지 않고 오류 로그를 확인합니다.
7. [화면 배포 열기](https://github.com/kwonyoung1/pocket-friends/actions/workflows/deploy.yml) → 맨 위 **main**의 병합 실행 → **build**와 **deploy** 모두 초록색 확인. 병합으로 자동 실행되므로 **Run workflow를 또 누를 필요가 없습니다.** 실행이 전혀 없을 때만 Run workflow → main → Run workflow를 누릅니다.
8. [업데이트 게임 열기](https://kwonyoung1.github.io/pocket-friends/) → PC는 Ctrl+Shift+R, 모바일은 탭을 닫고 다시 열거나 새로고침. 데이터가 보이지 않으면 초기화하지 말고 서버 배포/로그인/오류 문구를 확인합니다.

서버 배포는 Supabase의 채점·보상 규칙을 갱신하고, 화면 배포는 GitHub Pages의 UI를 갱신합니다. 두 작업의 초록색은 각각 별개입니다. 브랜치 푸시·테스트 통과만으로 운영 배포가 완료된 것은 아닙니다.

## 배포 후 확인

1. 기존 사진·이름·친구 수·코인·보유품·가구·햄스터·진행 탐험을 백업과 비교합니다. 일반적인 시간 경과에 따른 상태 변화는 계속됩니다.
2. 상점 → 음식에서 새4종과 가격 확인 → 구매 → 인벤토리에서 선호 음식을 사용 → 하트·대사·상세 정보 취향 확인. 다른 기기에서 새로 동기화합니다.
3. 탐험 메뉴의 실제 확률표와 도감의 보물 목록을 확인합니다. 희귀/전설 보유품 판매를 누르면 확인창이 나와야 합니다. 취소하면 재고/코인이 유지됩니다. 전설은 확률이 낮으므로 바로 나오지 않는 것이 정상입니다.
4. 영단어 탐험 시작 → 빈 답은 채점 안 됨 → 힌트 반복은1회만 차감 → 틀린 답/정답 보기/건너뛰기를 각각 확인 → 메뉴 닫고 모바일에서 이어하기 →30문제 완료 → 오답수×10을 뺀 코인1회 확인 → 새로고침해도 중복 지급 안 됨 → 오답 노트와 복습 확인.
5. 친구 상세에서 쉬게 하기 → 체력+20(최대100)·짧은 휴식·4시간 표시 → 연속 입력/다른 기기/새로고침 후 추가 보상 없음 확인. 기존 자동 휴식과 야간 수면은 계속됩니다.

자동 검증은 단위/DB114개·PC/모바일 브라우저76개·클라우드24개가 통과했습니다. [검증 보고서](ADVENTURE_VERIFICATION.md)에 범위와 재검사 결과를 기록했습니다. 실제 운영 Supabase, 실제 휴대폰의 OS별 동작 및 소리 청취는 배포 후 확인해야 합니다.
